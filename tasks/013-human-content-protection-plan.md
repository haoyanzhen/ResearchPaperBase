# Task013 人工内容保护子条目规划

文档版本：v1.0
更新日期：2026-10-24

## 1. 授权、依据与交付边界

每日整理仅授权本单规划，不授权编码、契约修改或业务测试执行。FR-017唯一主规划责任归本单，TRACK-012a/012d继续开放。依据[FR-017](../docs/design/01_functional_requirements.md#fr-017-内容修改保护基座)、[05应用提交](../docs/design/05_application_use_cases.md)、[A07确认契约](010-task-confirmation-event-contracts.md)、[07持久化](../docs/design/07_data_persistence.md)及[08权限](../docs/design/08_security_permissions.md)。设计语义沿用现行规范，不添加新确认政策。

P0包含Agent草稿/人工确认/人工修改可见状态、当前内容与最后修改人/时间/来源、允许编辑入口、重新生成覆盖确认及失败取消保护。排除版本列表/差异/回退（FR-036），综述专属追溯/审查历史（FR-035），Workspace未提交草稿（task009），知识版本采用（FR-018）、业务发布与通用P1恢复。具体内容在其业务状态下是否可写仍由所属FR与领域决定；本单不赋予已完成Review重新编辑权限。

## 2. 切片、所有者与交接

每片须另获实现授权；HP编号是局部规划标识。HP-04为HP-01–03随交付执行的共用约束，不形成反向依赖。

| 切片 | 输入→可观察输出 / 包含 | 所有者、文件职责 | 硬前置及交接 / 排除 |
| --- | --- | --- | --- |
| HP-01 / P0 | 当前内容、修订和合法动作→明确三态及最后修改人/时间/来源，保留当前稿 | Construction/Research/Review所属应用模块唯一写正文及修订；各前端显示状态；07记录由对应存储适配器承接 | 身份、Project授权、对象读取/修订端口；不依赖Graph运行；不建设完整历史版本系统 |
| HP-02 / P0 | 合法人工编辑→保存准确当前稿，标人工修改并记录元数据 | 原业务模块分别接入检索词/筛选结果/有效性/AI分析；Research标题/标签/总结；Review大纲/章节/审查建议处理状态/终稿 | HP-01及各对象现行可写状态；每类独立小片，不能一次宣称全部完成；交HP-03/04 |
| HP-03 / P0 | 重新生成目标及修订→对人工确认或修改内容展示覆盖影响、按已定确认契约提交 | 所属应用消费task010预览/确认，前端显示影响与保留范围；Agent只交结果提案 | HP-01、A04错误及A07适用确认类型；不另建token协议，不对不需确认的普通保存增加确认 |
| HP-04 / P0共用验收 | 生成中编辑、撤权、失败/取消、旧确认及重复提交→拒绝不合格提案并保留原稿 | 各应用最终提交条件与真实存储事务，测试所有者随各业务片 | HP-01–03交付必测；规则来源05/A07；排除Construction知识发布资格的完整实现验收 |

实际拟落点为backend对应应用/领域/存储模块及frontend对应编辑器；工程目前只有骨架，端口、源码文件、物理字段和测试路径须在获授权片的S1确定，不伪造已存在实现。输入输出跨模块仅使用类型化引用/提案；Workspace与Agent不得直接写正式正文。

## 3. 需求验收规格

下表为预期规格，全部运行用例尚未建立；真实存储隔离及服务内commit清理由AGENTS约束，外部模型默认mock。

| 场景 / 主切片 | 输入、动作及交错 | 预期、禁止副作用及观察 |
| --- | --- | --- |
| HP-T01 / HP-01 | Agent草稿被合法人工确认，再读取和重开页面 | 内容状态变人工确认；UI可区分三态；最后修改人/时间/来源可追溯，不伪造人工修改 |
| HP-T02 / HP-02 | 对第2节每一种允许内容保存编辑；重复读取；使用无权主体或只读对象保存反例 | 准确保存并标人工修改；拒绝分支正文、修订、元数据不变；逐内容分别记录API/存储/UI证据 |
| HP-T03 / HP-03 | 人工确认→重新生成，分别未确认、拒绝覆盖、合法确认后提交 | 必须展示确认；前两者不覆盖；合法提交仅作用于确认范围，保留其他人工内容 |
| HP-T04 / HP-03 | 人工修改→重新生成；以Agent草稿或旧确认提案冲突 | 人工修改高于人工确认、高于Agent草稿；未获适用确认不得覆盖；检查正文、状态与修订 |
| HP-T05 / HP-04 | 生成失败或取消；提交前失败与服务内commit失败分别注入 | 原正文与人工保护元数据保持；不产生成功覆盖或部分提交；真实事务回滚并清理隔离库 |
| HP-T06 / HP-04 | 屏障置于提案读取后/最终提交前，期间人工编辑或确认依赖修订变化；交换提交先后顺序 | 陈旧提案/确认被拒绝，不覆盖新人工稿；以两事务及持久结果证明，不以mock调用顺序代替 |
| HP-T07 / HP-04 | 派发后撤权/对象变只读，再提交；确认请求/提交结果丢失后重复 | 最终授权/状态与幂等按既有契约裁决；无越权、重复修订或事件；保留合法已提交结果，不误报新写入 |
| HP-T08 / HP-01–03 | 无版本列表/差异/回退页面；Workspace恢复旧草稿；既有Session/Review绑定旧KV | 人工保护、覆盖确认仍可用；恢复不提交，绑定不变；不调用FR-035/036增强来冒充本单完成 |

完成条件：获授权的每个小片将FR子项→上述场景→实际文件/测试→当前执行日志逐项对齐，覆盖成功/拒绝/故障和适用竞争，修复缺陷并独立审查后提交人工审核。HP-T02内容清单必须逐项展开，不能靠单一文本编辑器测试宣称跨业务完成。

## 4. 明确开放缺口与检查点

HP-01缺字段/端口/错误绑定和三态转换实际测试；HP-02缺逐内容的领域合法状态、路由/文件/测试实例矩阵；HP-03缺实际确认UI与应用接入；HP-04缺隔离数据库、确定交错屏障及幂等持久证据。Owner均为本单对应片，FR-035/036及唯一发布者仍交原规划归属，不吞并其验收。

建单不表示逐子条目任务已全部完成，更不表示测试覆盖。无新业务决定；若现行规范不足以决定某内容状态，按实施入口列证据/选项/建议并仅暂停该分支。规划文档核验见[每日整理](../docs/workorders/nightly_maintenance_2026-10-24.md)；设计执行、代码、运行测试、人工接受均未开始，不进入交付执行队列。
