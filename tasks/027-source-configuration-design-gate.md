## 6. D-SOURCE-01：非论文来源的业务含义（初始提案；地址决定见第9节）

证据：01 FR003要求来源范围及可验证资料线索（第299–324行），FR021要求从配置来源检索可下载资料（第943行）；04-01 §2.1要求新增Provider必须有实现能力注册。机器SourceWrite枚举web/document_site/public_file，但输入只有base_url、access_mode、secret、速率及启停等通用字段，03-01 P06c只有Base URL。现行设计未确定该地址是单一资源、站点入口还是搜索API，也未定义文档站遍历边界。

| 选项 | 具体行为及影响 |
| --- | --- |
| A：显式资源与具名适配器（建议） | web只读取用户指定的单页，public_file只处理指定文件；document_site仅支持具名、有明确查询/目录协议的站点适配器，不通用递归抓站。没有适配器的类型不开放、不标为可用，文档站能力范围确认后再实现。保留四个基础论文源支持。需要明确接受本阶段非论文来源边界。 |
| B：通用站点检索/抓取 | 把站点入口作为资料发现范围；需先确定允许域名/路径、是否跟随子链接、深度/数量、跨站重定向和凭据传递范围，再实现相应配置与验收。范围与网络副作用更大，不能从一个Base URL推定。 |

建议A：给用户可预期的访问范围，避免测试连通成功冒充检索能力。此为待决定建议，未写入现行规范。只有明确成功响应200不够；后续测试须验证对应协议/资源线索、不可访问及不支持格式等分类。

仅受影响部分为下一配置切片中非论文Provider的能力注册、UI含义及测试标准；四论文源及通用CRUD不存在因此产生的全局技术阻塞。但用户明确要求遇到未明确设计即停，本轮完成独立接受记录和决策核查后保存交接，不绕行另启管理员或Construction业务，也不先采用候选语义实现。
