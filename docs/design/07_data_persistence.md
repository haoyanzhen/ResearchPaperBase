## 1. 设计目标

本文定义可实施的逻辑记录、约束、短事务和故障处理，承接 02 的业务规则及 [05-01 内部契约](05-01_internal_module_contracts.md)。它不重新定义权限、状态或 P0/P1/P2；首版知识存储选择及映射见末尾A09，其他历史方案保留原范围。

旧 `07_data_schema.sql` 已按用户授权删除，不再作为建库或迁移参考入口。下述记录名是迁移实现的逻辑映射，不要求一记录一张表；物理拆分必须满足相同条件更新和隔离约束。真正可执行的表结构以后仅由版本化迁移维护，不再平行手写第二份 SQL 草案。本轮是设计细化，未建库、未运行并发或恢复测试。

资料策略的选择、来源分类、执行依据及派生依赖逻辑扩展见[08-01 §4](08-01_agent_data_access_policy.md#4-文件分类与入库流程)。Q1–Q4已确认；逻辑事实与裁决见§3.1/§6.4，物理字段、约束和迁移仍需实现，执行依据记录每次当前政策/分类修订，不保留启动权限上限作为授权；不把本文现有记录表视为已覆盖新增分类/政策事实。凭据更新不能改写历史业务配置快照，详见08 §12.3。

LLM模型发现结果与逐模型测试事实分开保存；测试事实关联配置身份、model_id、配置修订、凭据修订、时间和安全结果。个人及系统模型的可选投影检查当前修订，旧/迟到成功不授予新配置可用性；保存事实和计算投影不能改历史任务快照。逻辑身份不包含密钥明文，不要求新增LLM启停字段。物理字段与迁移尚未实现。

首版具体存储/迁移工具与测试隔离选择见[00-01](00-01_engineering_baseline.md)。本文维护逻辑约束；可执行字段仍由未来版本化迁移维护。

## 2. 存储分工

| 存储 | 用途 | 说明 |
| --- | --- | --- |
| PostgreSQL 或等价关系库 | 账号、配置元数据、Project、Run/Session、论文身份、版本、状态、审计 | 业务事实的权威来源 |
| 文件存储 | PDF、解析文本、导出文件、临时产物 | 通过对象 key 引用，不暴露真实路径 |
| 向量库 | Project 内按候选运行或已发布 Knowledge Version 隔离的文档向量 | 与关系库通过同步状态关联，不以可变 Project 单一集合覆盖旧版本 |
| 图谱存储 | 论文、作者、关键词、概念、方法节点边 | 可由关系库/图数据库/文件图谱实现 |
| Secret Store | API key、SMTP 密码、系统密钥 | 关系库只保存密钥引用或密文标识 |
| 队列/调度状态 | 异步任务与重试 | MVP 可由关系表承载，后续可替换队列 |

## 3. 逻辑记录与字段映射

通用约定：身份为服务端生成 UUID；业务修订为不透明 revision；时间统一 UTC。可变业务对象有 revision/created_at/updated_at；不可变事实有身份、created_at 和内容校验依据，不强制伪造 updated_at。内部 epoch 是执行隔离序号，不对客户端充当 revision。API DTO 不能直接作为 ORM 保存对象。

## 4. 身份与隔离

- `papers` 表保存全局论文身份和可复用元数据。
- `project_papers` 保存 Project 私有关联、评分、有效性、推送状态和 AI 分析。
- 文件资产必须绑定 Project 或导出任务，清理时按拥有者和引用关系判断。
- 普通用户查询必须通过 Project 权限过滤。
- 管理员账号治理不等于 Project 内容读取权，不能通过数据库诊断或后台任务绕过隔离。
- Project 子记录使用 (project_id,id) 复合关联或等价约束验证祖先归属；仅逐个核验 UUID 存在不合格。版本、Run、候选、文件、证据组合也必须一致。
- 授权过滤必须进入数据读取与文件/索引/图谱端口，不能先全局 top-k 再按 Project/版本过滤。缓存键含 Project、版本/清单、资产修订及相关检索配置，命中不复用旧授权。

### 4.1 唯一性与索引

除第 3 节业务约束外，迁移必须提供以下可核验约束：命令 (actor,operation,scope,key) 唯一；同命令结果提交身份唯一；版本来源 Run 唯一；单会话回复占用、单章/终稿写入资格唯一；同版成员键唯一；所有子对象复合归属可验证。列表索引按 04 的 Project/owner、时间和稳定 id 顺序，消息按既定轮次顺序；不让数据库默认行序充当协议。

当前资产身份与历史成员记录分开。不能在历史内容修订表用 (project_id,paper_id) 唯一约束禁止重导入，也不能为重导入删除旧修订。检索词默认值仅创建时应用，更新不补默认。数据约束失败按 04 映射安全错误，不把原 SQL 暴露给用户。

## 5. Knowledge Version 数据规则

`knowledge_versions` 应保存 Project、版本号、来源 Construction Run、发布时间、状态、关系库论文快照范围、向量索引引用、图谱引用和发布诊断摘要。

研究与综述的父对象持续工作。以 (Project, 轮次或生成/审查操作, KnowledgeVersion) 保存版本依赖；受理与读取当前默认版本按发布事务排序，依赖和可重放结果同事务持久化。执行恢复从原记录取得 pin，新的追问或写作在原 Session/Run 下建立新依赖。已有稿件按来源修订解析历史证据，升级不删除旧依赖。旧记录升级时，有历史证据则按其可验证来源回填，无法确定时标为未知，不按最新指针补造历史。

版本固化论文与资料集合、正文来源、分析、引用定位、向量和图谱引用。候选写入与已发布读取隔离；允许复用未变化资产，但不得改变旧版本内容。旧版本仍被研究或导出依赖时，不得因常规清理破坏必要证据；权限撤销或必须删除时保留原因并安全拒绝访问。

ConstructionRun 成功结果保存 `published` 或 `no_change`（非生命周期状态）：published 关联本 Run 新发布版本；no_change 保存核验既有版本、范围、时间及核验依据，不创建新 KnowledgeVersion 或切换默认指针。no_change 的候选以“已废弃／核验无变化”收尾，不得误标已发布；published 的候选保持已发布；具体字段由数据模型细化。两类成功的决定都要与取消排他并校验当前权限、写资格、基线和完整性。failed 放弃恢复保存独立的放弃/清理事实，保留失败状态和诊断，不转换 cancelled。

### 5.1 资产原子单元与修订闭包

本节是 [已确认快照方案](02-02_construction_versioning_appendix.md#25-不可变逻辑快照与资产复用边界)的数据实现边界，非 SQL/迁移定稿。数据原子化指可独立标识、验证、引用和回收的修订单元，不要求把所有内容拆成最细字段。

| 单元 | 修订与复用规则 |
| --- | --- |
| ProjectPaper / ProjectMaterial 成员及元数据 | 稳定身份与发布修订分离；版本清单固定成员、排除/来源状态和元数据，不读取可变当前行还原历史 |
| 文件与正文 | 不可变对象引用、内容校验值、来源及解析配置；更换内容必须生成新修订；项目私有归属独立于物理去重 |
| 分块与引用定位 | 绑定正文修订、切片配置及稳定片段 ID；偏移/页码绑定具体文件或文本修订；重切片不能复用旧片段 ID 表示新内容 |
| 分析 | 绑定输入修订、生成配置及人工修订/确认依据；修改产生新修订，不改变旧分析或继承失效确认 |
| 向量与图谱 | 记录所依赖分块/分析修订、模型/构建配置和视图标识；同正文但嵌入模型不同不可当作相同向量；节点/边的证据归属必须可验证 |
| 版本清单 | 固定完整成员关系、上述修订/视图及完整性校验；必须可确定性解析全部依赖，不能靠当前表或 latest 补全 |

资产身份、内容修订标识、业务编辑 revision 和 KnowledgeVersion ID 互不替代。内容哈希用于完整性/复用判定，不替代身份、授权及处理配置。首版可保存完整成员清单并共享不可变内容；不要求增量清单链。即使后续采用增量清单，也须保护祖先依赖，不能因清理祖先使仍保留版本无法解析。

上述修订单元用于候选处理及移除后显式重新导入，不授权更新已入库论文或资料内容。入库确认受理时保存固定候选/确认修订并锁定内容，失败保留草稿和诊断；当前已发布成员禁止 metadata/text/analysis 修订入口。移除保留全局身份、旧版本成员及引用闭包；重新纳入形成新内容修订，不继承旧人工确认。人工排除决定须持久化以阻止自动检索复活，显式重新纳入单独记录。

### 5.2 发布原子性与故障边界

1. Construction 在隔离候选范围准备全部资产，外部对象完成持久写入和可读验证；验证绑定候选修订、清单及依赖校验值。已就绪对象不可再原地修改，发布前不得对正式读取开放。
2. 在关系库短事务或等价原子边界内，重验权限、构建资格、候选/确认修订及基线；关联同一清单与就绪证明，提交版本发布记录、默认指针、Run 成功结果、依赖登记及持久事件。以唯一发布身份和条件更新裁决重复请求、取消和过时基线。
3. 跨文件、向量、图谱不承诺分布式 ACID；对用户保证的是“完整版本一次可见”。适配器须保证发布前验证的对象不可被覆盖/回收；不能只依据曾经 synced 的标志发布。最终一致存储须完成可读屏障后才可发布。
4. 发布前失败保留旧默认，仅按运行归属清理无依赖候选；提交结果不明先查询同一发布决定，不能重新发版。发布后外部服务故障报告该版本依赖不可用，不回退默认、不拼接其他版本；恢复相同对象须校验内容一致。通知失败不撤销发布。

关联移除命令持久保存确认集合、成员修订、已授权终止的具体冲突运行及幂等结果；未展示冲突不能沿用授权终止。全排除成功保存 published 和完整空清单/空索引/空图谱的就绪依据，并原子切换默认指针，保留旧闭包。空版本不等于缺失版本，Research/Review 可绑定它，成员为零不是创建约束；无证据提示不改变绑定。

数据库事务不能覆盖整个 LLM 或检索执行期；长时间一致性由不可变依赖和读取保护实现。

#### 5.2.1 发布提交协议

准备阶段为每个候选取得依赖保护，写入 attempt 私有对象，再登记不可变目标与摘要；完成每种存储的可读屏障并生成与候选修订绑定的就绪记录。发布事务不得现场调用 LLM、下载或重建索引。

提交阶段在 Project 裁决边界内锁定槽/Run/候选及依赖记录，按一致顺序取得锁，重验当前权限、Project治理 epoch、attempt资格、有效输入、确认依据、候选修订与默认基线；就绪记录引用的对象须仍受保护且不可变。随后一次提交：唯一完成记录、KnowledgeVersion与完整清单成员、持久依赖、默认指针、候选published、Run succeeded/published、执行失权/释放槽及发布outbox。任何条件失败整体不生效。

no_change 使用同一完成唯一键和裁决边界，必须已有可用基线并完成本轮无变化核验；一次记录 verified_version/范围/时间、Run succeeded/no_change、候选废弃原因、失权/释放槽和完成事实，不创建版本/发布事件、不切默认。首次无版、零新增或检索失败不能据此成功。

Project归档/删除、版本发布与清理标记复用同一 Project 裁决记录；账号禁用/删除另通过账号治理记录与提交时当前身份重验串行裁决。跨资源事务按账号治理→Project→槽/Run→候选/内容→依赖对象的固定顺序，同类多个对象按稳定 id 排序，避免相反加锁顺序；服务不得各自 commit 破坏整体性。具体数据库可用行锁或等价串行化条件写，必须由故障测试证明同等性质。

### 5.3 在途读取与回收的并发边界

持久依赖保护默认版本、保留的研究/综述/引用及导出所需证据；在途保护覆盖任务排队、执行、分页读取和重试期间所需范围。普通短请求至少在读取期间持有保护；分页请求每页重新取得保护，失效游标不能授权读取已回收内容。具备持久依赖的对象不依赖短租约维持历史保留。

取得读取保护与标记可回收必须在同一互斥或条件提交边界裁决：先取得保护则清理不可删除；先进入回收则拒绝新的读取资格。先检查引用数、再无条件删除不合格。物理删除前再次核验保护、归属及全部共享引用；只回收无持久依赖、无有效在途保护且符合保留政策的产物，并支持幂等重试。

可使用租约/持久 pin 等实现，但必须定义续期、崩溃恢复及失效后的 Worker 隔离：保护失效后停止继续读取/提交，重新取得并验证同一版本后才能恢复，不能只凭超时认定 Worker 已停止。明确授权删除/撤权可使任务失效，保留允许保留的诊断，不切换证据。

具体保留时长、配额、索引存储产品和租约参数仍待后续工程/产品决策；本节约束不授权自动删除历史版本。物理约束由迁移实现并验证。

#### 5.3.1 读取与回收协议

依赖注册表区分持久引用（版本清单、研究/综述、有效导出）和在途 pin（排队任务、请求/流）。创建持久引用或取得 pin 与标记对象可回收须在相同依赖记录的锁/条件更新边界内完成：对象已标记回收则拒绝新增保护；保护有效则拒绝普通回收。分页每页取得保护，不能凭游标越过当前权限和生命周期。

回收器先在短事务核验明确政策/授权、所有共享引用、有效 pin 及候选恢复保留范围，再原子标记回收并登记 CleanupJob；提交后执行外部幂等删除，最后更新结果/重试记录。删除失败保持回收标记，不允许新读者把半删除对象当正常就绪对象。若准备取消回收，必须在尚无物理删除且完整性复验通过后由受控流程完成，不能单凭租约恢复。

pin 需要续期时使用持有者和 epoch 条件更新；到期后旧持有者不能续用旧资格读取新片段或提交，重取同版保护失败则诊断退出，不换版。已有下载副本不能撤回；后续读取/长流授权按04检查。发布把候选依赖保护转换为正式依赖，与发布记录一致；发布前失权的外部迟到产物只能作为孤立残留处理。

显式撤权或已授权治理删除可使读取失效，按领域允许范围优先拒绝新读取，不借普通保留保护扩张继续访问权。物理共享内容仍须核验其他 Project 的有效依赖；删除某 Project 的私有引用不等于删除全局共享字节。

### 5.4 引用身份与版本选择事实

不可变引用记录保存 Project、KnowledgeVersion、资产修订、具体文件/文本/片段或图谱视图及节点/边、定位和校验依据；文本/图谱/资产级采用条件约束，不要求摘要具备 PDF。同一证据 ID 不可被改指向，跨版重新引用分配新 ID，可关联同 Project 来源证据；原引用及人工确认保持原样。该引用记录由 Research/Review 保存不等于写知识库，引用目标仍只能来自已发布清单。

访问结果、完整性检查时间和风险提示为独立动态投影，不修改不可变证据。统计与版本卡片分开保存/投影发布事实和运行事实：成员/文本来源来自版本清单，本次检索来源/范围/执行时间来自构建输入及结果，不能由最新配置倒推；累计版本和手工输入独立说明。状态缓存携带校验时间并在实际使用时重验权限/依赖。持久字段及逻辑约束见第 3–4 节，物理索引由后续迁移落实，接口结构见 [04-01 §5.1](04-01_p0_operation_contracts.md#51-版本摘要与引用解析补充)。

### 5.5 Review 当前稿与下载一致性

P0 终稿保存单一完整 Markdown 正文、revision、accepted/rejected、来源大纲/章节修订、每项来源证据版本、本次生成版本和最小修改元数据。摘要/关键词/参考文献是同一正文修订的派生投影，不成为第二份可写正文。审查记录绑定正文修订，不存覆盖率、豁免或 strict 配置，不因正文改写复用旧审查结论。

不新增 ReviewExportableVersion/ExportableSnapshot 生命周期，不要求保存每次编辑完整历史；已有独立 accepted 终稿成果不因新稿失败删除。编辑条件更新只允许未完成 Run 的 accepted 稿，不能复活 rejected。完成与保存/启动任务按 Run、稿件和来源修订原子裁决，完成后只读。

P0 Markdown 下载在鉴权并匹配当前 revision 后取得一致正文副本/受保护读取句柄，后续保存不能混入同一响应；失配 412，不提供任意旧修订下载能力。P1 格式转换固定该次输入并记录产物来源，属于内部执行一致性，不是用户需管理的导出快照。字段和归属见第 3 节，实际表及约束由后续迁移落实，不代表已建表或运行验收。

## 6. 命令受理、执行资格与外部同步

### 6.1 可靠受理和投递

首版采用关系持久层的命令去重记录、Task 和 outbox 原子受理模式；队列产品可替换，至少一次投递不等于业务 exactly-once。应用先按 05 鉴权与前置检查，再在短事务争用命令唯一键：同键同参数重放持久结果，同键异参数拒绝。参数摘要按 04 规范化，敏感字段使用不可逆受保护摘要且不写日志；原始密钥不进入可重放响应。

异步新命令同事务保存类型化输入/所需快照、任务、适用的确认消费及 outbox；事务提交后才按 04 返回对应状态码。同步操作仅提交其业务结果和必要去重记录，不凭空建立 Task/outbox；只读查询不进入命令受理流程。尚未取得构建槽时保留排队输入意图，不能提前冻结最新基线。outbox 投递失败可重投同任务，不能新建业务命令或更换幂等键。Worker 领取使用条件更新并取得独立 attempt 资格；重复投递查已领取/已完成事实，不启动第二个有效执行者。

外部计算不占长事务。结果以固定 (command,attempt,提交步骤) 身份回应用提交入口，短事务同时记录业务变更、提交结果及持久事件。提交响应丢失先查该身份；已提交返回原结果，未提交且资格仍有效才能继续同次提交。Provider 请求结果未知与数据库提交未知分开：不能把有副作用的 Provider 调用盲目重试；既定技术重试不得开放 P1 用户恢复。

### 6.2 槽、租约与迟到写隔离

Project 有独立的槽记录，业务占槽不由 Run 状态的含糊部分索引推导。应用在 Project 裁决锁下判空槽/定向预约，条件设置 occupant_run_id，并推进内部 epoch；queued 不占槽，取得后才冻结输入/基线和转 running。waiting_user 保槽但没有任意后台推进权限；P1 paused 同样保槽，租约到期不释放业务槽。

每次 attempt 绑定槽 epoch、Project 治理 epoch 和有效输入修订。所有业务提交在同一裁决边界验证这些值及当前权限；取消、归档、删除或输入修订失效先持久撤销资格/推进 epoch，之后旧 Worker 无论进程是否退出均不能提交。外部写入只允许 attempt 私有、不可覆盖的对象键；迟到完成最多留下不可发布残留，不可写入另一个 attempt 的对象或修改已就绪对象。

取消与完成竞争由共同短事务锁/条件更新串行裁决。P1 定向重跑保留预约记录，新 Run queued 时不占槽但第三方不得争用预约；确认旧资格已撤销且新实例准入成立才接管。新建/准入明确失败或新实例取消时按 02-02 §10.2 关闭预约，不复活旧 Run；结果不明先查持久记录。P0 不因此增加暂停、原 Run 失败恢复或通用重跑入口。

### 6.3 外部同步记录

同步项持久化 Project、Run/attempt、输入/候选修订、目标产物逻辑身份、依赖摘要、对象键/视图引用、校验值、状态、失败分类和检查时间。同一同步项重投只核对或完成同一不可变目标，不覆盖旧对象。

| 状态 | 必须可证明的事实 |
| --- | --- |
| pending | 已登记目标，尚未证明完整可读 |
| synced | 对应依赖/配置/摘要一致且经可读屏障验证；不是永久发布授权 |
| failed | 写入/解析/读取失败及安全原因已保存，不能对正式读取开放 |
| stale | 依赖或有效输入变化，旧成功不能用于新候选发布 |
| deleted | 所属目标已清理或不可再访问；不复用旧对象键表示新内容 |

VectorStore/GraphStore 必须支持版本隔离、不可变视图和可读核验；不满足则拒绝启用，不能以全局过滤替代。Graph、向量、文本及引用关键项就绪后才进入发布裁决；单项合法摘要降级/排除不豁免整体一致性。通知/非必要临时清理是独立副作用，不能反写 Run 或默认版本。

### 6.4 当前政策与受控操作的存储裁决（A06）

本节扩展§5.2.1及§6的逻辑互斥协议。沿账号治理→Project→槽/Run/所属内容→依赖对象的原顺序，在Project裁决范围内纳入当前主体政策记录；来源分类随依赖对象按稳定身份排序。政策不存在也必须有可竞争的默认记录身份/等价条件，避免首次PUT与默认读取竞态。实际锁粒度可以细化，但分类/政策更新、实际读取/派发交接、新结果提交必须能证明等价串行顺序，所有模块不得私自commit。

Agent使用产生的新结果提交在同一短事务/等价原子边界验证全部实际输入的当前政策/分类和资格；必要安全接收/静态提取保存按05 §3.3的可信操作分流，仅在原scope/资格与完整依赖登记下保存受限产物，不因此取得Agent消费资格。上述适用检查不是“先读版本号、再无条件写结果”。修订变化时重新解析与判定全部输入；输入仍允许且资格有效才提交。依赖集合改变导致原就绪证明失效；不能在验收后追加未核验来源。已提交结果的去重查询与新提交分开，按当前结果可见性返回原事实，不产生新内容或事件。操作结果未知按§6.1核查同一提交身份。

政策/分类更新不能依赖异步失效消息才能生效；缓存/Worker每次边界核验权威事实。读取保护只保护字节存活，不冻结权限。派发排序遵循[05 §3.3](05_application_use_cases.md#33-当前资料政策的受理派发与提交裁决a06)，不能让一个数据库短事务产生可在以后任意使用的发送许可；实际不可撤回交接不覆盖网络等待/推理。无长事务、双向竞争和崩溃窗口均须由B03真实适配器验收。

物理表、唯一约束、锁实现、缓存失效机制和旧数据迁移仍未实现。B02须证明Project隔离、不可复用修订及服务内部commit隔离；B03须提供实际读取/发送/提交屏障；B04须证明完整依赖传播与放宽后的缓存范围，具体场景见09的A06交接。不得用顺序mock或文档中的“原子”二字关闭运行验收。

## 9. 迁移、隔离与实现准入

物理字段类型、外键、索引、约束和数据回填脚本以后由同一套版本化迁移维护。初始化与升级均由该入口执行；不恢复被删除 SQL 草案，不从历史源码猜测生产结构。表名可调整，但第 3–4 节的归属和约束必须逐项映射到迁移与测试 ID。

迁移顺序：身份/配置与 Project → 命令/槽/执行记录 → 候选与不可变资产/版本 → 研究/综述及证据依赖 → 投影与必要索引。循环关系先建记录再加外键，不能永久关闭归属校验；加入非空或唯一约束前先核验/回填历史数据。升级采用先兼容读取/扩展结构，再切换写入，最后清理旧字段；持久任务载荷 schema_version 与文档版本独立。

每次迁移必须记录前置版本、变更、校验、失败处理及回滚边界。不可逆数据变换先备份并验证恢复；不能把 down migration 存在当作数据可恢复证明。代码回滚必须兼容已写入的新数据和在途任务，否则停止旧进程接入，走明确恢复方案；不自动回退知识默认指针。

数据库测试显式提供独立测试连接和测试库/schema标识，缺失立即拒绝，禁止读取业务数据库回落。使用独立命名空间/数据库及对象存储前缀覆盖应用内部 commit；不能仅依赖测试外层 transaction rollback。清理按测试运行标识执行并验证残留，外部 Provider 默认 mock。具体安装和迁移命令在新核心选定后验证记录，不在此虚构可运行入口。

| 故障/交错 | 必须保存/返回的结果 | 验收入口 |
| --- | --- | --- |
| 受理事务前失败、提交后派发失败 | 前者不返回任务、不调用 Provider；后者同一任务可查询并安全补投 | 09 ARC-03 |

| 索引延迟可见、文件写好但发布事务失败 | 不暴露半版本；保留旧默认；候选残留按归属安全处理 | KV-I05 |

## A09 首版向量与图谱持久方案

技术选择及具名结构唯一见[06 A09](06_agent_knowledge_services.md#a09-首版知识构建与graph-rag方案)。本节把§5/6既有不可变/发布/回收规则映射到PostgreSQL 17、pgvector精确检索和关系图谱，不创建实际表或迁移。

| 逻辑记录 | 首版约束/索引与不可变边界 |
| --- | --- |
| BuildProfile / EmbeddingProfile | profile_id唯一且内容不可改；权重/配置摘要保持，模型凭据不保存；旧版本依赖原profile |
| ChunkRevision / EmbeddingObject | Project、文本/范围/chunker唯一语义键；embedding另按chunk/profile唯一；维度768及有限非零值，原始向量与归一化校验；不建ANN索引 |
| VectorView / VectorViewMember | (Project,view,chunk,profile)唯一，所有成员profile与视图相同；完整membership摘要/计数；不以可变Project集合替代 |
| GraphView / Node / Label / Assertion / Support | 所有外键带Project及view；节点身份与各来源标签/断言分离；端点存在，support指同清单资产/文本/范围；不能无依据并入其他Project或最新版 |
| CandidateManifest / KnowledgeReadyProof | proof绑定candidate_revision、attempt、所有profile、摘要、视图和读屏障；变化则失效，不能复用旧synced标志 |
| PublishedManifest / Version / Dependency | 版本绑定封存视图及全部依赖；只由Construction短事务登记发布，空视图是显式对象；旧绑定不更新 |

准入、写入、封存都核验attempt写资格，数据表权限只给受控适配器；已封存视图禁止追加/更新/删除成员，修订产生新view_id。共享不可变embedding/chunk可引用，图视图首版复制完整membership以避免可变增量叠加读取。封存事实为内部存储状态，不新增业务Run状态。发布前视图只能经构建scope访问，正式Reader必须从已发布manifest解析view；ID存在不授权读取。业务图表不开放任意SQL/LLM Cypher。

精确检索先在同一查询快照按Project、view、profile及A06当前允许集物化行集合，然后计算距离/词法排名并LIMIT；禁止先对全局vector索引取邻居。图每一步都只查同view且已允许的节点标签、断言及其支持；允许集合以本次政策判定身份绑定，多语句查询须检测修订漂移并按06重算或失败。查询过程中不持有跨模型/网络的长事务；取得/续持pin不冻结权限，实际读取/派发/提交仍按§6.4串行边界。

精确性验收必须在真实PostgreSQL检查EXPLAIN计划及结果：大量近距离但无权/别版向量不能挤掉允许集top-k；以后加ANN索引必须另审该路径，不能仅依赖禁用planner某开关。不返回私有行计数或影响分值的全局统计。

本地FileStore先持久写入不可变对象并校验摘要；关系库视图封存后由独立连接读回全量成员/向量/支持闭包及就绪摘要，不能用同事务未提交对象证明可读。发布短事务按既有账号→Project→槽/Run→候选→依赖顺序，重验proof与保护后一次写入。全在PostgreSQL的向量/图事实可以参与同库提交，但文件仍无跨介质ACID；完整可见仍依赖先准备、不可变与保护。崩溃留下未发布孤立物不向查询公开。

同一发布身份重试读原决定；清理仍按持久引用/pin互斥核验，不能由向量/图适配器自行级联删共享资产。新版本移除节点不删历史图；运行失败只清理允许清理的所属候选。H03保留期未定，不新增按天自动删除；H02旧数据迁入未授权，不接触旧业务库。
