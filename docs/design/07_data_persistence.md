# Data Persistence 设计

文档版本：v1.7
更新日期：2026-10-16
依据文档：`00_layers.md`、`01_functional_requirements.md`

## 1. 设计目标

数据设计服务于 Domain Core 和 Application Use Cases，重点保证用户隔离、Project 私有资产、共享论文身份、Knowledge Version 绑定、长任务可恢复和外部存储同步可诊断。

## 2. 存储分工

| 存储 | 用途 | 说明 |
| --- | --- | --- |
| PostgreSQL 或等价关系库 | 账号、配置元数据、Project、Run/Session、论文身份、版本、状态、审计 | 业务事实的权威来源 |
| 文件存储 | PDF、解析文本、导出文件、临时产物 | 通过对象 key 引用，不暴露真实路径 |
| 向量库 | Project 内按候选运行或已发布 Knowledge Version 隔离的文档向量 | 与关系库通过同步状态关联，不以可变 Project 单一集合覆盖旧版本 |
| 图谱存储 | 论文、作者、关键词、概念、方法节点边 | 可由关系库/图数据库/文件图谱实现 |
| Secret Store | API key、SMTP 密码、系统密钥 | 关系库只保存密钥引用或密文标识 |
| 队列/调度状态 | 异步任务与重试 | MVP 可由关系表承载，后续可替换队列 |

## 3. 关系数据模块

| 模块 | 表/实体 |
| --- | --- |
| 用户与权限 | `users`, `user_sessions`, `audit_logs` |
| 配置 | `user_llm_configs`, `user_data_source_configs`, `user_notification_configs`, `system_configs`, `runtime_config_snapshots` |
| Project | `projects`, `construction_workspaces`, `search_terms` |
| Run/Session | `construction_runs`, `research_sessions`, `research_messages`, `review_runs`, `review_outlines`, `review_chapters`, `review_final_versions` |
| 论文与知识 | `papers`, `project_papers`, `document_assets`, `knowledge_versions`, `knowledge_sync_items`, `citations` |
| 任务与产物 | `locks`, `export_jobs`, `email_push_jobs`, `job_attempts` |
| 协作 | `viewpoints` |

## 4. 身份与隔离

- `papers` 表保存全局论文身份和可复用元数据。
- `project_papers` 保存 Project 私有关联、评分、有效性、推送状态和 AI 分析。
- 文件资产必须绑定 Project 或导出任务，清理时按拥有者和引用关系判断。
- 普通用户查询必须通过 Project 权限过滤。
- 管理员可治理账号和系统配置，但不得读取用户私人密钥明文。

## 5. Knowledge Version 数据规则

`knowledge_versions` 应保存 Project、版本号、来源 Construction Run、发布时间、状态、关系库论文快照范围、向量索引引用、图谱引用和发布诊断摘要。

Research Session 和 Review Run 保存稳定的 `knowledge_version_id`；采用新知识创建关联新 Session 或新版 Review，不改写原对象绑定。完整边界见 [知识库并行构建与版本更新领域附录](02-02_construction_versioning_appendix.md)；本草案不代表数据模型或迁移已完成。

版本固化论文与资料集合、正文来源、分析、引用定位、向量和图谱引用。候选写入与已发布读取隔离；允许复用未变化资产，但不得改变旧版本内容。旧版本仍被研究或导出依赖时，不得因常规清理破坏必要证据；权限撤销或必须删除时保留原因并安全拒绝访问。

ConstructionRun 成功结果保存 `published` 或 `no_change`（非生命周期状态）：published 关联本 Run 新发布版本；no_change 保存核验既有版本、范围、时间及核验依据，不创建新 KnowledgeVersion 或切换默认指针。no_change 的候选以“已废弃／核验无变化”收尾，不得误标已发布；published 的候选保持已发布；具体字段由数据模型细化。两类成功的决定都要与取消排他并校验当前权限、写资格、基线和完整性。failed 放弃恢复保存独立的放弃/清理事实，保留失败状态和诊断，不转换 cancelled。

### 5.1 资产原子单元与修订闭包

本节是 [已确认快照方案](02-02_construction_versioning_appendix.md#25-不可变逻辑快照与资产复用边界)的数据实现边界，非 SQL/迁移定稿。数据原子化指可独立标识、验证、引用和回收的修订单元，不要求把所有内容拆成最细字段。

| 单元 | 修订与复用规则 |
| --- | --- |
| ProjectPaper / ProjectMaterial 成员及元数据 | 稳定身份与发布修订分离；版本清单固定成员、排除/来源状态和元数据，不读取可变当前行还原历史 |
| 文件与正文 | 不可变对象引用、内容校验值、来源及解析配置；更换内容必须生成新修订；项目私有归属独立于物理去重 |
| 分块与引用定位 | 绑定正文修订、切片配置及稳定片段 ID；偏移/页码绑定具体文件或文本修订；重切片不能复用旧片段 ID 表示新内容 |
| 分析 | 绑定输入修订、生成配置及人工修订/确认依据；修改产生新修订，不改变旧分析或继承失效确认 |
| 向量与图谱 | 记录所依赖分块/分析修订、模型/构建配置和视图标识；同正文但嵌入模型不同不可当作相同向量；节点/边的证据归属必须可验证 |
| 版本清单 | 固定完整成员关系、上述修订/视图及完整性校验；必须可确定性解析全部依赖，不能靠当前表或 latest 补全 |

资产身份、内容修订标识、业务编辑 revision 和 KnowledgeVersion ID 互不替代。内容哈希用于完整性/复用判定，不替代身份、授权及处理配置。首版可保存完整成员清单并共享不可变内容；不要求增量清单链。即使后续采用增量清单，也须保护祖先依赖，不能因清理祖先使仍保留版本无法解析。

上述修订单元用于候选处理及移除后显式重新导入，不授权更新已入库论文或资料内容。入库确认受理时保存固定候选/确认修订并锁定内容，失败保留草稿和诊断；当前已发布成员禁止 metadata/text/analysis 修订入口。移除保留全局身份、旧版本成员及引用闭包；重新纳入形成新内容修订，不继承旧人工确认。人工排除决定须持久化以阻止自动检索复活，显式重新纳入单独记录。

### 5.2 发布原子性与故障边界

1. Construction 在隔离候选范围准备全部资产，外部对象完成持久写入和可读验证；验证绑定候选修订、清单及依赖校验值。已就绪对象不可再原地修改，发布前不得对正式读取开放。
2. 在关系库短事务或等价原子边界内，重验权限、构建资格、候选/确认修订及基线；关联同一清单与就绪证明，提交版本发布记录、默认指针、Run 成功结果、依赖登记及持久事件。以唯一发布身份和条件更新裁决重复请求、取消和过时基线。
3. 跨文件、向量、图谱不承诺分布式 ACID；对用户保证的是“完整版本一次可见”。适配器须保证发布前验证的对象不可被覆盖/回收；不能只依据曾经 synced 的标志发布。最终一致存储须完成可读屏障后才可发布。
4. 发布前失败保留旧默认，仅按运行归属清理无依赖候选；提交结果不明先查询同一发布决定，不能重新发版。发布后外部服务故障报告该版本依赖不可用，不回退默认、不拼接其他版本；恢复相同对象须校验内容一致。通知失败不撤销发布。

关联移除命令持久保存确认集合、成员修订、已授权终止的具体冲突运行及幂等结果；未展示冲突不能沿用授权终止。全排除成功保存 published 和完整空清单/空索引/空图谱的就绪依据，并原子切换默认指针，保留旧闭包。空版本不等于缺失版本，Research/Review 可绑定它，成员为零不是创建约束；无证据提示不改变绑定。

数据库事务不能覆盖整个 LLM 或检索执行期；长时间一致性由不可变依赖和读取保护实现。

### 5.3 在途读取与回收的并发边界

持久依赖保护默认版本、保留的研究/综述/引用及导出所需证据；在途保护覆盖任务排队、执行、分页读取和重试期间所需范围。普通短请求至少在读取期间持有保护；分页请求每页重新取得保护，失效游标不能授权读取已回收内容。具备持久依赖的对象不依赖短租约维持历史保留。

取得读取保护与标记可回收必须在同一互斥或条件提交边界裁决：先取得保护则清理不可删除；先进入回收则拒绝新的读取资格。先检查引用数、再无条件删除不合格。物理删除前再次核验保护、归属及全部共享引用；只回收无持久依赖、无有效在途保护且符合保留政策的产物，并支持幂等重试。

可使用租约/持久 pin 等实现，但必须定义续期、崩溃恢复及失效后的 Worker 隔离：保护失效后停止继续读取/提交，重新取得并验证同一版本后才能恢复，不能只凭超时认定 Worker 已停止。明确授权删除/撤权可使任务失效，保留允许保留的诊断，不切换证据。

具体保留时长、配额、索引存储产品、租约时限和 SQL 约束仍待后续细化；本节不授权自动删除历史版本。

### 5.4 引用身份与版本选择事实

不可变引用记录保存 Project、KnowledgeVersion、资产修订、具体文件/文本/片段或图谱视图及节点/边、定位和校验依据；文本/图谱/资产级采用条件约束，不要求摘要具备 PDF。同一证据 ID 不可被改指向，跨版重新引用分配新 ID，可关联同 Project 来源证据；原引用及人工确认保持原样。该引用记录由 Research/Review 保存不等于写知识库，引用目标仍只能来自已发布清单。

访问结果、完整性检查时间和风险提示为独立动态投影，不修改不可变证据。统计与版本卡片分开保存/投影发布事实和运行事实：成员/文本来源来自版本清单，本次检索来源/范围/执行时间来自构建输入及结果，不能由最新配置倒推；累计版本和手工输入独立说明。状态缓存携带校验时间并在实际使用时重验权限/依赖。持久字段、约束和索引在后续 SQL 映射阶段落实，接口结构见 [04-01 §5.1](04-01_p0_operation_contracts.md#51-版本摘要与引用解析补充)。

### 5.5 Review 当前稿与下载一致性

P0 终稿保存单一完整 Markdown 正文、revision、accepted/rejected、来源大纲/章节修订、KnowledgeVersion 和最小修改元数据。摘要/关键词/参考文献是同一正文修订的派生投影，不成为第二份可写正文。审查记录绑定正文修订，不存覆盖率、豁免或 strict 配置，不因正文改写复用旧审查结论。

不新增 ReviewExportableVersion/ExportableSnapshot 生命周期，不要求保存每次编辑完整历史；已有独立 accepted 终稿成果不因新稿失败删除。编辑条件更新只允许未完成 Run 的 accepted 稿，不能复活 rejected。完成与保存/启动任务按 Run、稿件和来源修订原子裁决，完成后只读。

P0 Markdown 下载在鉴权并匹配当前 revision 后取得一致正文副本/受保护读取句柄，后续保存不能混入同一响应；失配 412，不提供任意旧修订下载能力。P1 格式转换固定该次输入并记录产物来源，属于内部执行一致性，不是用户需管理的导出快照。上述概念待后续 SQL 映射，不代表已建表或迁移。

## 6. 外部存储一致性

关系库与向量库/图谱/文件存储无法天然同事务提交，采用同步项策略：

| 状态 | 含义 |
| --- | --- |
| `pending` | 已在关系库登记，等待外部写入 |
| `synced` | 外部写入成功并可读取 |
| `failed` | 外部写入失败，有错误分类 |
| `stale` | 外部内容不再匹配当前关系数据 |
| `deleted` | 外部资源已清理或不可再访问 |

发布 Knowledge Version 前，关键同步项必须达到 `synced` 且完整可读；Graph 未完成、失败或仍有待续连断点时不得发布。允许单项资料使用合法摘要降级或排除失败候选，但不得以降级豁免版本的向量、Graph 或引用一致性门槛。默认版本仅在发布成功时一次切换；发布检查与切换必须保证候选基线仍匹配当前默认版本，防止旧运行恢复后覆盖期间新增知识。具体事务和跨存储协议仍待细化。

## 7. 文件与导出生命周期

- PDF、解析文本、Graph 文件和向量 namespace 是 Project 私有资产。
- 已完成导出文件是用户主动生成产物，Project 私人资产清理默认保留。
- 删除导出文件通过导出中心或生命周期策略执行。
- 所有下载/打开入口必须经过鉴权或签名 URL。

## 8. 数据清理

Project 私人资产清理范围包括 Project 私有运行记录、Research Session、Review Run、Project-Paper 关联、Project 私有 PDF、解析文本、图谱、向量索引和临时任务产物。

不得清理全局 `papers` 论文身份、其他 Project 或其他用户仍引用的资源、默认保留的导出文件。

## 9. 迁移与索引要求

- 所有表包含 `created_at` 和 `updated_at`。
- 所有用户可见资源包含 owner 或 Project 权限路径。
- Run/Session 状态、Project 状态、Knowledge Version 状态需要索引。
- `papers` 应对 DOI、arXiv ID、来源 ID 建唯一或部分唯一索引。
- `project_papers` 对 `(project_id, paper_id)` 唯一。
- Construction Run 占槽唯一性必须涵盖 paused，执行租约过期不等于业务槽释放；具体约束与安全交接机制待细化。
