## 1. 引言

### 1.1 编写目的

本文档旨在详细描述 Research Paper Base 系统的功能需求、非功能需求和约束条件，为系统设计、开发、测试和验收提供依据。

### 1.2 项目背景

学术研究人员需要定期跟踪相关领域的最新论文，并实时查询论文中的相关内容，但手动检索、筛选、下载和分析论文的过程耗时耗力。本系统旨在通过 AI Agent 自动化这一流程，实现课题组级的论文BASE库构建，提供论文的检索、下载、解析、互动问答、自动推送、综述生成等功能，成为科研人员安全、可靠、有用的学术论文信息平台。

## 2. 项目概述

### 2.1 产品目标

构建一个可供课题组级人员共享、以 Project 为长期研究容器的多 Agent 学术论文研究系统。

**核心设计原则**：
- 支持小组级科研人员使用和论文库共享、观点分享和帐号管理
- 以研究主题（Project）为长期研究容器，支持构建 Agent、深度研究 Agent、主题综述 Agent 等多种 AI Agent 模式
- **Agent 实例化**：构建模式以每 Project 唯一 Construction Workspace 承载长期配置，每次执行生成 Construction Run；深度研究以 Research Session 承载开放式对话；主题综述以 Review Run 承载流程式写作运行
- **并发控制**：系统对知识库写入、同一实例内容写入和同一对话流式回复等冲突点做并发限制
- **模式扩展性**：系统架构设计预留扩展性，支持未来扩展为更多模式，无需对核心架构进行重大改造

**基础层设计（独立于Agent功能）**：
- 用户和用户信息管理：用户注册、登录、权限管理等，全局通用
- 用户配置管理：用户信息维护、LLM模型连接配置维护、论文数据库API配置维护等，全局通用
- 管理员配置管理：首位注册用户自动成为管理员，管理员可配置发送邮箱、系统级默认模型、系统级默认论文库API，并管理其他用户账号
- 界面管理：独立于Agent模式，可随时进行信息面板的打开和关闭
  - 课题选择栏：（可以展开或折叠）显示用户的所有课题列表选项
  - Agent Run/Session 选择栏：（可以展开或折叠）显示当前所选课题的所有 Agent Run/Session 选项，以及各自的运行状态
  - 主体流程栏：（可以为空，不可折叠）显示当前所选 Run/Session 的主体内容
  - 课题论文库自动检索设置栏：（可以展开或折叠）显示当前 Project 的 Construction Workspace 自动更新设置（如哪些检索词参与自动更新、每个检索词适用哪些论文检索数据库等）
  - 课题相关信息：（可以展开或折叠）显示当前课题的论文数据库；知识关系图谱等
  - Run/Session 相关信息：（可以展开或折叠）显示当前 Run/Session 的相关信息
  - 观点广场：（可以跳入新的页面）查看其他用户发表的观点，或者发表观点（禁止讨论，显示发布者的用户名或邮箱）

**Agent 工作台设计原则**：
1. **Project 长期容器**：Project 作为 Agent Run/Session 的长期容器，其下有且仅有一个 Construction Workspace 用于整个容器的知识库背景。但可同时存在或运行多个其他模式的 Run/Session，具体的并发限制参考各 Agent 的设计。
2. **工作台控制**：用户可以访问系统主页面，也可以中断或销毁 Run/Session。
3. **构建配置与执行分离**：Construction Workspace 保存 Project 级长期构建配置；其管理和记录所有历史和正在运行的 Construction Run， 每个 Construction Run 表示一次手动或自动构建执行。
4. **读写区分**：Construction Run 是知识库写入者，负责项目的知识库维护；Research Session 和 Review Run 是知识库消费者，只记录历史会话或综述内容。
5. **知识库版本并行更新**：构建 Run 完成后更新 Project 默认知识库版本；新建 Research Session / Review Run 默认使用最新版本；依赖旧版本的 active Research Session / Review Run 不被打断，待最后一个依赖旧版本的 active 实例结束后再提示刷新依赖。
6. **冲突控制**：同一 Project 的知识库写入、同一 Run/Session 的同一内容写入、同一对话的流式回复追加等冲突点进行互斥控制，禁止发起冲突操作。
7. **扩展性**：Agent 类型和 Run/Session 模型预留扩展性，支持未来添加新的 Agent 能力。

---

目前的 Agent 类型设计包含三类：

**构建 Agent / Construction Workspace + Construction Run**：
- 用户借助Agent工具结合研究主题自动生成检索词
- 从多个学术数据库检索论文
- 智能评分和筛选相关论文
- 自动下载和解析论文
- 用户可补充论文或手动上传资料
- Agent自动完成分析和后台入库
- 根据论文数据库构建 Graph 知识图谱数据库
- 将自动下载和分析的结果通过邮件推送给用户
- 每个 Project 有且仅有一个 Construction Workspace，用于长期维护检索词、检索词级数据源策略、检索待确认列表、检索历史结果和自动更新开关等内容
- 每次手动构建或系统自动更新都会创建一个 Construction Run，作为一次构建流水线执行记录
- 系统级调度器会扫描 active Project 的 Construction Workspace，按自动更新检索词创建自动 Construction Run
- 同一 Project 可保留多个历史 Construction Run，但只允许一个 active Construction Run 写入知识库

**深度研究 Agent / Research Session**：
- 基于某个 Project 知识库版本进行 Graph-RAG 检索，作为 LLM 的知识库背景
- LLM 基于 Graph-RAG 与用户提供深度理论与技术讨论，除了普通的聊天模式，也内置三种输出倾向：
  - 创新：进行联想，倾向于提出新研究方向的可能
  - 实验：考虑周密的实验方案设计以验证猜想或方向
  - 总结：记录对话探讨历史和结论
- Research Session 主要读取知识库并写入自己的对话历史，同一 Project 下可多开并发。同一 Research Session 内一次只允许一个流式回复追加，避免对话轮次顺序冲突

**主题综述 Agent / Review Run**：
- 基于某个 Project 知识库版本进行 Graph-RAG 检索，作为 LLM 的知识库背景
- 根据用户的课题设计综述文章架构
- 撰写每章内容并引用相关论文
- 自动审查并迭代优化每章内容
- 将每章内容汇总成完整的综述文章
- 支持用户对综述文章进行修改和完善
- 支持导出综述文章为多种格式（Markdown、PDF、Word）
- 提供综述文章的版本管理
- Review Run 主要读取知识库并写入自己的大纲、章节、审查记录和导出版本，同一 Project 下可多开并发。同一 Review Run 内同一章节或同一最终稿不能被多个任务同时写入

### 2.2 用户特征

| 用户类型 | 特征 | 主要需求 |
|---------|------|---------|
| 学术研究人员 | 需要跟踪最新研究进展 | 自动化、准确性、可定制 |
| 研究生 | 需要收集相关文献，学习新技术 | 易用性、全面性 |
| 科研团队 | 需要共享检索结果，协作研究 | 多用户支持、数据共享 |
| 系统管理员 | 负责系统部署和维护，通常是团队负责人 | 统一配置管理、用户账号管控 |

### 3.3 基础层功能需求

#### FR-001 用户账号与认证

**需求描述：**
系统应支持多用户注册、登录、登出和账号状态管理，为 Project 数据隔离和管理员权限提供基础。

**功能范围：**
- 用户使用用户名、邮箱和密码注册账号。
- 用户可使用用户名或邮箱登录。
- 用户可登出当前会话。
- 用户可查看和修改自己的基础信息。
- 系统应识别账号启用/禁用状态，禁用账号不得继续登录。
- 账号被禁用后，已存在的登录会话应在下一次鉴权或刷新时失效。
- 首位注册用户自动成为管理员，具体治理能力见 `FR-005`。
- 密码找回属于 P1 支撑能力，应在 API 和邮件设计确认后实现。
- 用户信息必须长久留存，只有管理员用户有权限对其他用户的信息进行修改。

**验收标准：**
- 新用户可成功注册并登录。
- 用户可使用用户名或邮箱登录，并可正常登出当前会话。
- 用户可查看和修改自己的基础信息，修改后再次读取结果一致。
- 错误凭证登录失败，并返回明确错误提示。
- 密码不得明文存储、明文返回或在已保存后被恢复为明文；注册、登录、重置密码等输入框可提供仅限当前输入内容的显示/隐藏切换。
- 禁用账号不能继续登录。
- 禁用账号的既有会话不得继续访问受保护资源。
- 首位注册用户应获得管理员身份。
- 并发注册场景下只能有一个首位注册用户获得管理员身份。
- 密码找回未实现前，不得在 UI 或 API 中暴露不可用入口；实现后应通过邮件或等效安全流程完成验证。

#### FR-002 用户 LLM 配置管理

**需求描述：**
用户应能配置个人 LLM 连接，用于构建、深度研究和综述模式中的 Agent 调用。

**功能范围：**
- 支持配置多种 provider 的 base URL、API key 和基础参数。支持的 provider 应当包含 OpenAI、Anthropic、Gemini、deepseek 以及自定义 provider。
- 支持测试连接、刷新并显示当前 provider 的可用模型列表。
- 已保存模型不可用、被系统白名单移除或密钥轮换后失效时，应在任务启动前提示用户重新选择或修复配置。
- 用户应当能够同时使用个人配置或系统配置；具体解析规则见 `FR-007`。
- 支持多个 provider，并在系统的可选模型列表中同时列出所有个人配置和系统配置中连接成功的可用模型的配置来源和模型名称。
- 支持在主页面通过系统的可选模型列表更改当前的 Agent 调用连接模型。
- 用户当前选择的模型是 Agent 任务启动时的显式运行参数；系统级默认配置只作为可选模型来源和缺省配置来源，不应静默替代用户未选择的当前模型。
- 用户配置必须可保存和复用。
- 支持重新登录后自动选择用户上次选择过的模型

**验收标准：**
- 用户可新增、查看、修改、删除个人 LLM 配置。
- 用户的个人配置长期有效，且只有用户可以修改自己的个人 LLM 配置。
- 用户可维护多个 provider，并可测试任意 provider 的连接以及查看其可用模型列表。
- 用户可测试连接并刷新可用模型列表，结果能区分成功和失败，若失败需给出失败原因。
- API key 存储和展示必须脱敏。
- Agent 任务能根据用户当前选择的选项来配置模型；配置需正确，不应与用户选择的配置来源和模型相违背。
- 用户未选择当前模型时，Agent 任务不得静默回落到系统默认模型，应提示用户选择模型；系统默认模型可作为可选项出现在模型列表中。
- 用户配置变更不得修改系统级默认配置。
- 用户重新登录时能够自动恢复上次退出会话时的模型选择。
- 用户上次选择的模型失效或不再满足系统硬限制时，系统应提示重新选择，不得静默替换为其他模型。

#### FR-003 用户论文数据库 API 配置管理

**需求描述：**
用户应能配置个人学术数据库 API，以控制构建模式使用的数据源和访问参数。

**功能范围：**
- 基础支持 arXiv、OpenAlex、Semantic Scholar、ADS。
- 支持新增加学术搜索引擎的多个 API 配置。
- 支持启用/禁用数据源、API key、API base url、速率限制配置。
- 数据源被禁用、密钥失效或超过速率限制时，运行时解析应能识别并返回可诊断原因。
- 对支持匿名访问的数据源，API key 可为空但仍需记录其访问模式和速率限制；对必须使用 API key 的数据源，缺少 key 时不得解析为可用数据源。
- 支持连接测试和状态展示。
- 用户可以选择使用个人数据源配置或系统默认数据源配置；具体解析规则见 `FR-007`。

**验收标准：**
- 用户可新增、查看、修改、删除个人数据源配置。
- 用户的个人配置长期有效，且只有用户可以修改自己的个人数据源配置。
- 用户可启用或禁用 arXiv、OpenAlex、Semantic Scholar、ADS 中的任一数据源。
- API key、端点和速率限制保存后能被再次读取和脱敏展示。
- 支持匿名访问的数据源在无 API key 时可通过连接测试并标记为匿名模式；必须使用 API key 的数据源在 key 缺失时应测试失败并给出原因。
- 连接测试能返回成功、失败和失败原因。
- 数据源连接失败时应给出可诊断提示。
- 构建模式只使用已启用且运行时可解析的数据源。
- 被禁用、密钥缺失、密钥失效或超过系统硬限制的数据源不得被解析为可用数据源。
- 用户配置变更不得修改系统级默认数据源配置。

#### FR-004 用户邮件与通知配置

**需求描述：**
用户应能维护个人收件人和通知偏好，用于接收新论文推送、测试邮件和必要通知。本 FR 只定义用户侧收件人、接收内容和通知偏好，不定义系统级自动构建调度周期，也不定义具体邮件发送流程；自动调度由 `FR-013` 定义，邮件生成与发送由 `FR-022` 定义。

**功能范围：**
- 用户可维护一个或多个收件邮箱。
- 用户可对每个收件邮箱设置是否接受论文推送。
- 用户可配置是否接收构建完成、推送失败、自动任务失败等通知。
- 用户可配置接受论文时的信息维度，只接收标题/标题+摘要/数据库储存的论文元数据/是否需要论文文件附件等。
- 用户可配置通知接收偏好，例如是否汇总通知、是否接收失败通知或仅接收成功推送结果。
- 用户可发送测试邮件验证收件配置。
- 测试邮件发送失败时应展示失败原因，且不得改变用户已保存的通知偏好。
- 邮件模板自定义属于 P2 扩展能力。

**验收标准：**
- 用户可保存并查看自己的收件邮箱列表和通知偏好。
- 用户可维护多个收件邮箱，并能删除无效或不需要的收件邮箱。
- 是否接受论文推送的设置在用户更改保存后生效。
- 构建完成、推送失败、自动任务失败等通知开关保存后生效。
- 接受论文的信息维度设定在用户更改并保存设置后生效。
- 用户通知偏好不得改变系统级自动构建调度周期；调度周期由 `FR-013` 管理。
- 用户通知偏好不得绕过 `FR-022` 的邮件发送范围、预览、空邮件保护和推送状态规则。
- 测试邮件使用系统发件配置发送到用户收件人。
- 系统 SMTP 缺失或不可用时，测试邮件应失败并提示需要管理员修复系统发件配置。
- 邮件模板自定义未实现前，不得作为 P0/P1 阻塞项。

#### FR-005 管理员账号管理

**需求描述：**
基础层应提供管理员账号治理能力，允许管理员维护用户账号状态和管理员权限，同时确保系统不会丢失最后管理员。

**功能范围：**
- 首位注册用户自动成为管理员。
- 首位注册用户的管理员授予必须具备并发保护，避免多个并发注册请求同时获得首位管理员身份。
- 管理员可查看用户列表和用户基础状态。
- 管理员可启用、禁用或删除普通用户账号。
- 管理员禁用用户后，该用户既有会话不得继续访问受保护资源。
- 管理员可重置用户密码或触发密码重置流程。
- 管理员可授予或撤销其他用户的管理员权限。
- 系统至少保留一个启用状态的管理员账号。

**验收标准：**
- 非管理员不能访问用户管理入口和接口。
- 首位注册用户自动成为管理员；并发注册场景下只能有一个首位注册用户自动获得管理员身份。
- 管理员可查看用户列表和用户基础状态。
- 管理员可启用、禁用或删除普通用户账号。
- 管理员可重置用户密码或触发密码重置流程。
- 管理员可授予或撤销其他用户管理员权限。
- 管理员不能禁用、删除或撤销自己的最后管理员身份。
- 系统在并发管理员权限变更时仍必须保留至少一个启用状态管理员。
- 被禁用用户不能登录。
- 被禁用用户的既有会话应失效或被拒绝继续访问受保护资源。
- 管理员账号操作应可审计。
- 并发管理员权限变更、禁用或删除操作仍不得破坏最后一个启用管理员账号。

#### FR-006 管理员系统级配置管理

**需求描述：**
基础层应提供管理员系统级配置管理能力，用于维护普通用户未配置个人参数时的回落配置和平台运行基础。

**功能范围：**
- 管理员可维护系统级默认 LLM 配置。LLM 配置的详细需求见 `FR-002`
- 管理员可维护系统级论文数据库 API 配置。论文数据库 API 配置的详细需求见 `FR-003`
- 管理员可维护系统发件邮箱和 SMTP 配置。
- MVP 阶段管理员可维护的系统级限制范围包括模型白名单、允许的数据源范围、系统级速率上限、系统级并发上限和必要全局开关。
- 系统级硬限制变更后，后续任务启动必须重新校验用户配置是否仍满足限制。
- 默认阈值、成本预算、复杂安全策略和用量仪表盘可作为后续增强，不应扩大 MVP 系统级配置范围。
- P2 支撑能力：支持管理员查看系统级 LLM 用量仪表盘及论文数据库 API 用量仪表盘。暂不考虑实现。
- 管理员可测试系统级配置连接状态。
- 系统级密钥应脱敏展示，并按安全设计加密存储。
- 管理员不得查看用户的私人配置

**验收标准：**
- 非管理员不能访问系统级配置入口和接口。
- 管理员可维护系统级默认 LLM、论文数据库 API、SMTP、模型白名单、允许的数据源范围、系统级速率上限、系统级并发上限和必要全局开关。
- 管理员可测试系统级 LLM、数据源和 SMTP 配置连接状态。
- 系统级配置变更不得覆盖用户个人配置。
- 系统级密钥不得明文返回前端或日志。
- 配置变更应记录操作者、时间、配置类型和结果。
- 模型白名单、允许数据源、速率上限或并发上限变更后，系统应能在后续任务启动前拒绝不满足限制的配置并给出原因。
- 除了用户的账号管理（用户名、密码以及启用状态）外，管理员不得查看用户的个人配置信息。

#### FR-007 用户配置与系统配置解析规则

**需求描述：**
系统应明确用户配置与管理员系统级配置之间的运行时解析、回落、覆盖和限制关系，避免构建、深度研究、综述和邮件推送在不同模块中使用不一致的配置来源。

**功能范围：**
- LLM和论文数据库 API都必须定义运行时配置来源。
- 论文数据库 API 配置中用户个人配置优先于系统默认配置。仅用户缺失搜索论文数据库 API 配置时才回落系统默认配置。
- 系统级配置不得覆盖用户已保存的个人配置，但可以提供硬限制，例如允许的数据源范围、最大并发、速率上限和模型白名单。
- 已保存的用户配置在任务启动时必须重新经过系统级硬限制校验。
- 邮件配置采用组合策略：用户收件人和偏好来自用户配置，SMTP 发件能力来自系统级配置。
- 密钥类配置必须按所有权隔离：用户密钥只能由该用户任务使用，系统密钥可作为回落配置但普通用户不可读取明文。
- 系统应能在任务启动前生成一次解析后的配置快照，用于诊断、审计和任务复现。

**验收标准：**
- 任一 Agent 任务启动前能明确解析出实际使用的 LLM、数据源、邮件和限制配置。
- 用户缺失个人配置时能使用系统默认配置继续执行。
- 用户已有个人配置时，系统默认配置变更不应静默改变该用户任务的配置来源。
- 系统级硬限制能限制用户配置的可用范围，例如模型白名单、数据源范围、速率上限或最大并发。
- 邮件运行时配置能组合用户收件人与系统 SMTP 发件能力。
- 普通用户不能通过配置解析结果读取系统密钥明文。
- 任务启动时应生成配置快照，并可用于诊断、审计和任务复现。
- 配置快照不得保存或返回用户密钥、系统密钥、SMTP 密码等任何密钥明文；需要审计来源时只能记录配置来源、脱敏标识或密钥引用。
- 配置解析失败时，任务不得启动，并应返回缺失项和修复建议。
- 配置解析失败场景应能区分缺失配置、密钥不可用、超出白名单、数据源被禁用、速率或并发超过上限等原因。

#### FR-008 系统级页面入口与 Project 可用性约束

**需求描述：**
系统应在用户登录后提供系统级页面入口和 Project 入口管理能力，支持用户创建、选择、维护 Project，并在满足权限和可用性约束时进入对应 Project Workspace。本 FR 定义系统级入口、Project 管理、Project 状态和进入 Workspace 的前置条件，不定义 Project Workspace 内部布局、Run/Session 切换、运行控制或知识库版本刷新。

**功能范围：**
- 用户可创建、查看、更新、软删除或归档自己的 Project。
- Project 应支持 `active`、`paused`、`archived`、`deleted` 状态，并可由用户进行切换。
  - `active` Project 可进入 Workspace 进行交互，并可参与系统级自动构建调度。
  - `paused` Project 可进入 Workspace 进行交互，但不参与系统级自动构建调度。
  - `archived` Project 默认只读保留历史，只可查看历史，不可使用互动功能，不参与系统级自动构建调度。
  - `deleted` Project 为软删除状态，不得进入 Workspace，不参与自动构建调度，默认不在普通 Project 列表展示。
- 系统级入口应至少包含 Project 列表/创建入口、用户配置入口、观点广场入口；管理员用户还应看到管理员配置入口。
- 用户可从 Project 列表选择自己有权限访问的 Project，并进入该 Project Workspace。且在 Project Workspace 中，用户应当能够看到或通过简单操作看到全部系统级入口。
- 进入 Project Workspace 前，系统应完成 Project 可用性检查。
- Project 状态切换、软删除和归档操作必须经过权限校验。
- Project 列表应展示进入 Workspace 所需的基础可用性信息，例如 Project 状态、是否存在可用 Knowledge Version、最近构建时间、最近活动时间。

**验收标准：**
- 用户可创建、查看、更新、软删除或归档自己的 Project。
- 用户只能访问自己的 Project。
- 登录后用户能看到 Project 列表/创建入口、用户配置入口和观点广场入口。
- 管理员用户能看到及访问管理员配置入口，非管理员不能看到或访问管理员配置入口。
- 用户选择有权限且未删除的 Project 后，可进入该 Project Workspace。
- 无权限或已删除 Project 不能进入 Workspace，并应给出明确原因。
- `deleted` Project 应作为软删除状态处理；软删除不得物理破坏其他 Project、全局论文记录或其他用户数据。
- Project 列表能展示 Project 状态、Knowledge Version 是否可用、最近构建、最近活动和自动追踪状态。
- 用户可将 Project 从 `active` 暂停为 `paused`，暂停后系统级自动构建调度不再扫描该 Project。
- 用户可将 `paused` Project 恢复为 `active`，恢复后可重新参与系统级自动构建调度。
- `archived` Project 默认只读展示历史，不参与自动构建调度。
- 无权限用户不得切换 Project 状态；被拒绝时应给出明确原因。
- `FR-008` 不定义 Run/Session 列表、工作台切换、暂停/恢复/取消/重试、知识库版本刷新或导出流程。
- 软删除或归档 Project 不得破坏其他 Project 的数据。

#### FR-013 系统级自动构建调度与推送

**需求描述：**
系统应提供系统级自动构建调度器，周期性扫描所有用户的 active Project，读取其 Construction Workspace 中参与自动更新的检索词，创建自动 Construction Run，在无人值守情况下后台增量更新论文库。本 FR 定义系统级调度、Project 过滤、自动 Run 创建和自动任务结果通知触发条件；用户收件偏好由 `FR-004` 定义，邮件内容生成、发送和推送状态由 `FR-022` 定义。

**功能范围：**
- 系统级 scheduler 应周期性扫描所有用户的 Project。
- scheduler 只调度 `active` Project，跳过 `paused`、`archived`、`deleted` Project。
- scheduler 对每个 active Project 读取其唯一 Construction Workspace。
- 仅当 Construction Workspace 中存在至少一个 `auto_update_enabled=true` 的检索词时，系统才创建自动 Construction Run。
- 自动 Construction Run 使用自动更新检索词集合，并按每个检索词的数据源策略解析可用数据源。
- 自动 Construction Run 启动时应保存配置快照，包括检索词、检索词数据源策略、解析后的数据源、用户/系统配置来源和调度时间。
- 自动任务执行构建模式全流程，并使用自动确认策略跳过人工等待。
- 如果自动确认策略无法安全处理某个人工等待点，自动 Construction Run 应转入等待用户处理或失败待诊断状态，不得静默跳过高风险确认。
- 同一 Project 已有 active Construction Run 时，应跳过本次调度或延后执行，不得并发写入同一 Project 知识库。
- 自动 Construction Run 成功后按 `FR-WORKSPACE-008` 提示知识库版本刷新。
- 自动 Construction Run 完成后向 `FR-022` 提供本次新增有效论文范围，触发邮件推送流程。
- 自动 Construction Run 失败时应记录失败原因，并可在 Construction Workspace 查看。
- 自动 Construction Run 失败时应根据 `FR-004` 的用户通知偏好触发失败通知。

**验收标准：**
- 系统级 scheduler 能周期性扫描所有用户的 Project。
- scheduler 的全局启用状态、周期、时间窗口和并发上限能由管理员系统级配置控制。
- `paused`、`archived`、`deleted` Project 不会被系统级自动构建调度。
- 没有自动更新检索词的 active Project 不会创建自动 Construction Run，并能记录跳过原因。
- 自动 Construction Run 使用 `auto_update_enabled=true` 的检索词和对应数据源策略。
- 自动 Construction Run 启动时保存配置快照。
- 自动 Construction Run 能执行构建模式全流程，并按自动确认策略处理人工等待点。
- 自动确认策略失败或遇到必须人工判断的风险项时，系统应记录原因并转入等待用户处理或失败待诊断状态。
- 不同 Project 的调度互不影响。
- 自动调度不会在同一 Project 上并发创建多个 active Construction Run。
- 调度器在并发扫描或重复触发时，应通过项目级调度锁或等效机制避免重复创建同一 Project 的自动 Construction Run。
- 同一 Project 已有 active Construction Run 时，本次调度应明确记录为跳过或延后，并不得创建第二个 active 写入者。
- 任务完成后能更新上次执行和下次执行信息。
- 自动 Construction Run 成功后能生成新的 Knowledge Version，并向 `FR-022` 传递本次新增有效论文范围。
- 自动 Construction Run 可在 Construction Workspace 中查看状态、配置快照和结果。
- 自动执行失败时能记录错误并通知用户查看。
- 自动确认策略失败时不得继续静默入库或推送，应保留可诊断等待项或失败项。

#### FR-014 观点广场

**需求描述：**
系统应提供独立于 Project Workspace 的观点广场页面，允许用户单向发布研究观点、结论或实验思路，供其他用户参考，但不提供站内讨论能力。

**功能范围：**
- 用户可发布、查看、搜索和筛选观点。
- 观点默认公开给系统内有权限访问观点广场的登录用户。
- 管理员可隐藏明显违规或不应公开的观点；隐藏动作应可审计。
- 观点可包含类型、标题、正文、标签和联系信息。
- 联系信息仅允许用户名或邮箱。
- 观点广场入口由 `FR-008` 的系统级页面入口提供。
- 支持查看次数和点赞属于 P2 能力。
- 禁止评论、回复、讨论串和实时聊天。

**验收标准：**
- 用户可查看、搜索和筛选公开观点。
- 用户可发布和删除自己的观点。
- 用户删除自己的观点后，普通用户不得继续看到该观点。
- 管理员隐藏观点后，普通用户不得继续看到该观点，作者应能看到隐藏状态或原因。
- 观点可保存类型、标题、正文、标签和联系信息。
- 用户可从系统级入口进入观点广场。
- 从 Project Workspace 跳转到观点广场不会改变当前 Project 的 Run/Session 状态。
- 系统不提供任何评论或回复入口。
- 联系信息不得展示用户名/邮箱以外的私密联系方式。
- 查看次数和点赞未实现前，不得阻塞观点发布、查看、搜索和删除。

### 3.4 Project Workspace 功能需求

#### FR-WORKSPACE-001 Project Workspace 内部入口、框架与对象切换

**需求描述：**
系统应在用户进入某个 Project 后提供 Project Workspace（项目工作台），用于承载 Project 内的研究入口、主体工作区、信息面板、Research Session 列表、Review Run 列表和顶层对象切换。Workspace Shell 负责用户打开或切换当前 Project 的唯一 Construction Workspace、Research Session、Review Run；Construction Run 历史入口由 Construction Workspace 内部承载，上下文恢复由 `FR-WORKSPACE-003` 定义。

**功能范围：**
- Project Workspace 必须绑定用户当前选择的 Project。
- Workspace 应展示当前 Project 状态，包括 active、paused、archived、deleted 中的可见状态。
- Workspace 应提供切换 Project 状态的入口；具体 Project 状态规则由 `FR-008` 定义。
- Workspace 应展示 Construction Workspace、Research Session、Review Run 的入口。
- 当 Project 为 `archived` 状态时，Workspace 入口应进入只读查看模式：历史 Construction Run、Research Session 和 Review Run 可查看；新建、启动、继续生成、上传、删除、重跑、刷新依赖和导出外的写操作默认禁用。
- 构建入口打开当前 Project 唯一 Construction Workspace。
- 深度研究和主题综述入口在 Project 存在可用 Knowledge Version 时可用；不可用时应显示原因和返回构建入口的建议。
- Workspace 应展示当前 Project 下已有 Research Session 和 Review Run 的列表入口。
- Workspace 总列表不直接展示历史 Construction Run；历史 Construction Run 入口、配置快照、日志和重跑来源由 Construction Workspace 内部承载。
- 用户可从 Workspace 的入口或列表打开 Construction Workspace、Research Session 或 Review Run。
- 打开或切换 Workspace 对象时，主体流程栏和 Run/Session 信息面板应同步到目标对象。
- 打开 Construction Workspace 时，应显示长期检索词、自动更新设置、最近 Construction Run 摘要和可启动操作。
- 打开 Research Session 时，应显示对话、历史轮次、知识库摘要和可提问入口。
- 打开 Review Run 时，应显示大纲、章节、审查状态、导出状态和可继续操作。
- 如果目标对象运行中，应显示运行状态、阶段和等待用户输入项。
- 如果目标入口没有历史实例，应显示新建入口和启动说明。
- 如果 Construction Run 正在运行，Research Session 和 Review Run 可继续读取已绑定的 Knowledge Version，并提示 Project 默认知识库正在更新。
- Workspace 应提供主体流程栏，用于展示当前选中的 Construction Workspace、Research Session 或 Review Run 内容。
- Workspace 应提供 Project 信息面板和 Run/Session 信息面板。
- Workspace 应展示当前 Project 的 Construction Workspace 自动更新设置摘要，例如哪些检索词参与自动更新、每个检索词适用哪些论文检索数据库等。
- 各信息面板应支持展开/折叠，且展开/折叠状态不应破坏当前 Run/Session 上下文。
- Workspace 不得绕过对应 Agent 工作台直接执行上传、删除、重建、重试、生成、推送或导出等写操作。

**验收标准：**
- 用户从系统级 Project 入口进入某 Project 后，Workspace 只展示该 Project 的研究入口和数据。
- Workspace 能展示当前 Project 的 active、paused 或 archived 状态。
- 用户可在 Workspace 中暂停或恢复 Project 自动追踪，且不会删除历史 Run、Research Session、Review Run 或 Knowledge Version。
- 用户可看到 Construction Workspace、Research Session 和 Review Run 的入口。
- 无可用 Knowledge Version 时，深度研究和主题综述入口禁用并显示需要至少一次 Construction Run 完成作为前置条件的提示。
- 构建入口打开当前 Project 唯一 Construction Workspace。
- 用户可查看当前 Project 下已有 Research Session 和 Review Run 的列表入口。
- 用户选择一个入口后，主体流程栏和 Run/Session 信息面板展示对应对象内容。
- 用户能在 Construction Workspace、Research Session 和 Review Run 之间切换。
- Project Workspace 总列表不会把历史 Construction Run 与 Research Session / Review Run 平级展示。
- 用户进入 Construction Workspace 后，才能查看历史 Construction Run 的快照、结果、日志、复制配置和重跑入口。
- 有运行中任务时，系统明确提示任务状态，不静默中断。
- 未选择入口时，主体流程栏不会展示错误上下文，可展示空状态或新建入口。
- 用户可展开或折叠 Project 信息面板、Run/Session 信息面板和自动检索设置摘要。
- 面板展开、折叠、切换和跳转不应中断正在运行的 Construction Run、Research Session 或 Review Run。
- `archived` Project 中的 Construction Workspace、Research Session 和 Review Run 入口应明确展示只读状态，并禁用新建、启动、继续生成、上传、删除、重跑和刷新依赖等写操作。
- `archived` Project 中任何被禁用写操作被触发时，系统应拒绝执行并展示只读原因。
- Workspace 不提供绕过 Agent 工作台的写操作入口。

#### FR-WORKSPACE-002 Project 知识资产面板

**需求描述：**
用户应能在 Project Workspace 中只读查阅当前 Project 的知识资产，包括论文库、论文详情、PDF 访问入口、Graph 关系图谱和 Knowledge Version 信息。该能力通常由 `FR-WORKSPACE-001` 的 Project 信息面板承载，但不负责面板布局。

**功能范围：**
- 展示当前 Project 的论文统计、列表、详情、评分、有效性、推送状态和 AI 分析。
- 支持标题、摘要、作者、来源、评分、有效性、推送状态、引用状态等筛选。
- 展示论文 PDF 本地或远程访问入口；远程访问必须经过鉴权或签名 URL，不允许暴露无权限文件地址。
- 展示当前 Project 的 Graph 关系图谱，包括论文、作者、关键词、概念、方法等节点和关系边。
- 展示当前 Project 默认 Knowledge Version，以及当前 Run/Session 绑定的 Knowledge Version。
- 当 Graph、PDF 或 Knowledge Version 不存在、缺失或不可访问时，应展示安全空态、缺失原因和可用下一步建议，不得展示错误上下文或无权限文件地址。
- 支持在论文详情和 Graph 图谱节点展示间切换。
- 支持从 Research Session 或 Review Run 的引用跳转到论文详情、PDF/远程访问入口或 Graph 节点。
- Project 知识资产面板只提供查阅、跳转、筛选、下载/打开，不提供上传、删除、重新下载、重新解析、重新评分、重新分析、入库、推送或图谱重建动作。

**验收标准：**
- 论文库和 Graph 图谱只展示当前 Project 数据。
- 用户可查看论文统计、列表、详情、评分、有效性、推送状态和 AI 分析。
- 用户可按标题、摘要、作者、来源、评分、有效性、推送状态、引用状态筛选论文。
- 用户可从论文详情打开有权限访问的 PDF 或远程文件。
- 用户可在论文详情与 Graph 节点之间互相跳转。
- 用户可看到当前 Project 默认 Knowledge Version 和当前 Run/Session 绑定的 Knowledge Version。
- Graph 不可用、PDF 缺失或 Knowledge Version 缺失时，系统能展示空态、降级原因和可用下一步建议。
- PDF 远程访问入口必须使用鉴权或签名 URL；无权限访问时不得暴露真实文件地址。
- 用户可从 Research Session 或 Review Run 的引用跳转到对应论文详情、PDF/远程访问入口或 Graph 节点。
- 越权、缺失或过期引用跳转应进入安全空态，并展示不可访问或版本不匹配原因。
- 深度研究和主题综述工作台下，Project 知识资产查阅保持只读。
- Project 知识资产面板不提供上传、删除、重新下载、重新解析、重新评分、重新分析、入库、推送或图谱重建操作。

#### FR-WORKSPACE-003 Workspace 上下文管理与恢复

**需求描述：**
系统应提供 Workspace Context Manager，用于记录和恢复用户打开任意 Workspace 对象时的可继续工作状态。Context Manager 是横切能力，不区分“Session 上下文”和“步骤上下文”两个管理器；它按用户打开的对象类型恢复视图状态。对象打开和切换由 `FR-WORKSPACE-001` 定义。本 FR 拆分为 P0 最小闭环和 P1 增强能力：P0 只要求恢复上次打开对象、基础面板状态和未提交输入草稿；更细粒度的滚动位置、日志位置、步骤结果落点和复杂侧栏状态属于 P1 增强。

**功能范围：**
- P0：Context Manager 应按用户、Project、Workspace 对象类型和对象 ID 记录最近打开对象。
- P0：打开 Project Workspace 时，应恢复上次打开的 Construction Workspace、Research Session 或 Review Run；若无有效记录则打开安全默认对象。
- P0：打开 Construction Workspace 时，应恢复基础面板展开/折叠状态和未提交的检索词编辑草稿。
- P0：打开 Research Session 时，应恢复当前会话对象和未发送的输入草稿。
- P0：打开 Review Run 时，应恢复当前 Review Run、当前章节或大纲对象，以及未提交的编辑草稿。
- P1：打开 Construction Workspace 时，可恢复上次查看的检索词区域、自动更新设置面板和最近 Run 摘要位置。
- P1：打开 Construction Run 时，可恢复上次查看的步骤、步骤结果、错误位置、日志位置和右侧上下文面板状态。
- P1：打开 Research Session 时，可恢复上次查看的对话轮次、滚动位置、引用面板和论文详情面板状态。
- P1：打开 Review Run 时，可恢复上次查看的大纲、章节、审查、导出步骤、右侧引用面板和编辑器滚动位置。
- 用户可在恢复后的对象内继续工作；恢复动作不得自动触发重跑、重新生成、重新检索、导出或覆盖。
- 若目标对象已删除、无权限、归档只读或状态不允许继续，系统应降级到安全空态，并说明原因。
- 若记录的上下文落点已经失效，系统应恢复到该对象的默认安全位置，例如最近可查看步骤、最近对话轮次或对象概览。
- Context Manager 不定义具体步骤业务内容，也不替代 `FR-WORKSPACE-006` 的步骤页面展示能力。

**验收标准：**
- 用户再次打开 Project Workspace 时，P0 能恢复上次打开的 Workspace 对象或安全默认对象。
- 用户再次打开 Construction Workspace 时，P0 能恢复基础面板状态和未提交的检索词编辑草稿。
- 用户再次打开 Research Session 时，P0 能恢复当前会话对象和未发送输入草稿。
- 用户再次打开 Review Run 时，P0 能恢复当前章节或大纲对象，以及未提交的编辑草稿。
- P1 实现后，如果用户上次停留在 Construction Workspace 内的某个历史 Construction Run 详情页，系统可恢复到该 Run 的步骤、结果或日志位置。
- P1 实现后，系统可恢复对话滚动位置、引用面板、论文详情面板、编辑器滚动位置和复杂右侧面板状态。
- 恢复上下文不会自动启动任何写操作、重跑、重新生成、重新检索、导出或覆盖。
- 失效上下文能降级到安全空态或对象概览，并向用户说明原因。
- 已删除、无权限、归档只读或状态不允许继续的上下文不得恢复为可写状态。
- P0 必须恢复当前选中对象和基础面板展开/折叠状态；复杂右侧信息面板状态属于 P1 增强。
- Context Manager 不绕过对象状态、权限检查、人工修改保护和知识库版本刷新规则。

#### FR-WORKSPACE-004 Run/Session 实例操作

**需求描述：**
用户应能在 Workspace 中执行 Run/Session 的用户可见实例操作。P0 覆盖进入、创建、继续和历史查看；复制、重跑、归档和删除属于 P1 受控增强。完整状态转换、并发锁和幂等语义不在本 FR 展开，由 `05_state_workflow.md` 定义。

**功能范围：**
- 用户可进入当前 Project 唯一 Construction Workspace。
- 用户可从 Construction Workspace 手动选择本次检索词集合并创建 manual Construction Run。
- P0：用户可查看历史 Construction Run。
- P1：用户可从历史 Construction Run 复制配置创建新的 Construction Run。
- P0：用户可创建新的 Research Session，或继续已有 Research Session。
- P1：用户可归档或删除已有 Research Session。
- P0：用户可创建新的 Review Run，或继续已有 Review Run。
- P1：用户可复制、重跑、归档或删除已有 Review Run。
- P1 操作执行前，系统应说明重跑、复制、新版本、删除、归档等操作的影响范围。
- P1 删除实例必须要求权限校验和二次确认。
- Construction Workspace 本身不作为可复制的新实例。
- 自动 Construction Run 由 `FR-013` 创建，但应能在 Workspace 中查看。

**验收标准：**
- 用户进入构建模式时默认进入该 Project 的唯一 Construction Workspace。
- 用户手动启动 Construction Run 前必须选择本次使用的检索词集合。
- 手动 Run 的 selected 检索词集合不改变自动更新检索词集合。
- 自动 Run 由 `FR-013` 基于自动更新检索词集合创建，并能在 Workspace 中查看。
- 用户能区分 `Construction Workspace`、`Construction Run`、`Research Session` 和 `Review Run`。
- 用户能查看各类实例的历史列表和最近实例。
- P0：用户能新建、继续和查看适用实例历史。
- P1：用户能复制、重跑、归档或删除适用实例。
- 新建、复制或重跑不会破坏原实例。
- P1 删除实例前必须进行权限校验和二次确认。
- 所有重跑、复制、归档、删除类操作都应在执行前说明影响范围。

#### FR-WORKSPACE-005 Run/Session 状态展示与运行控制

**需求描述：**
用户应能查看已有 Construction Run、Research Session 和 Review Run 的运行状态，并对可控实例执行运行控制。P0 覆盖状态展示、等待项、错误、日志摘要和取消；暂停、恢复、重试属于 P1 受控增强。状态枚举、状态转换、并发互斥和幂等语义由 `05_state_workflow.md` 定义。

**功能范围：**
- 展示当前 Run/Session 的状态、阶段、开始时间、更新时间、错误信息、等待用户输入项和阶段结果。
- P0：支持对可控的 Construction Run、Research Session 生成任务、Review Run 生成任务执行取消。
- P1：支持对可控的 Construction Run、Research Session 生成任务、Review Run 生成任务执行暂停、恢复或重试。
- 支持查看历史阶段记录、运行日志摘要和失败原因。
- 支持展示深度研究流式回复状态。
- 支持展示 Review Run 中章节生成、终审、导出等任务状态。
- 取消、暂停、恢复或重试应给出明确反馈，不应让用户误以为同时存在多个重复运行任务。
- 当当前状态不允许暂停、恢复、取消或重试时，对应控制应禁用，并向用户说明不可用原因。

**验收标准：**
- 用户可查看当前 Run/Session 的状态、阶段、时间、等待项、错误信息和阶段结果。
- P0 可控 Run/Session 支持取消，并能给出明确结果。
- P1 可控 Run/Session 支持暂停、恢复和重试，并能给出明确结果。
- 不可暂停、不可恢复、不可取消或不可重试的 Run/Session 必须禁用对应控制，并展示不可用原因。
- 取消或重试操作不产生用户不可见的重复任务。
- 重复点击取消、暂停、恢复或重试时应保持幂等或返回明确的不可操作原因。
- 用户可查看历史阶段记录、运行日志摘要和失败原因。
- 深度研究流式回复状态可见。
- Review Run 的章节生成、终审和导出任务状态可见。
- 失败任务应展示可诊断错误和下一步建议。
- 控制操作不得绕过状态机、权限检查、人工修改保护或知识库版本刷新规则。

#### FR-WORKSPACE-006 流程式 Agent 步骤容器

**需求描述：**
Project Workspace 应为构建模式和主题综述模式这类流程式 Agent 提供统一的步骤容器能力，使主体流程栏能够承载当前步骤页面，并允许用户查看当前步骤、已完成步骤和失败步骤的结果。该 FR 只定义步骤页面展示、步骤动作承载和步骤结果查看，不负责记录或恢复用户上次查看位置；上下文恢复由 `FR-WORKSPACE-003` 定义。

**功能范围：**
- 主体流程栏应能展示流程式 Agent 当前步骤页面。
- 步骤页面应展示步骤名称、步骤状态、输入摘要、输出摘要、等待用户确认项、错误信息和下一步操作。
- 构建模式的步骤动作和展示内容应由 `FR-015~022` 定义。
- 主题综述模式的步骤动作和展示内容应由 `FR-027~031` 定义。
- 深度研究模式不是固定步骤流，仍可使用主体流程栏承载对话页面，但不强制使用步骤容器。
- 用户可在同一流程式 Run 内查看当前步骤、最近步骤和已完成步骤结果。
- 当前步骤变化时，Run/Session 信息面板应展示该步骤的结果摘要，例如检索词、候选论文、下载解析状态、章节引用、审查问题或导出状态。
- 用户应能从步骤页面跳转到对应 Project 知识资产面板或 Run/Session 信息面板中的相关上下文，但跳转不得触发越权写操作。
- 失败步骤应展示失败原因和可用恢复动作；具体是否允许重试由对应 Agent FR 和状态机设计约束。

**验收标准：**
- 构建模式和主题综述模式的当前步骤能在主体流程栏中清晰展示。
- 用户能看到当前步骤名称、状态、输入摘要、输出摘要、等待项、错误和下一步操作。
- Workspace 中展示的步骤动作均能追溯到对应 Agent FR。
- 步骤页面不得提供绕过 `FR-015~022`、`FR-027~031`、权限检查或人工修改保护的写操作。
- 步骤容器不得提供任何不能追溯到对应 Agent FR 的上传、删除、重建、重试、生成、推送、导出或回退写操作。
- 用户确认门槛未满足时，步骤容器不得允许进入下一业务步骤。
- 当前步骤变化后，Run/Session 信息面板同步展示当前步骤结果摘要。
- 用户可查看已完成步骤的结果，但查看历史结果不得自动重跑或覆盖当前结果。
- 失败步骤能展示失败原因和可用恢复动作。
- 步骤容器不负责记录或恢复用户上次查看位置；该能力由 `FR-WORKSPACE-003` 提供。

#### FR-WORKSPACE-007 内容修改保护基座

**需求描述：**
系统应允许用户修改 Agent 生成或中间确认内容，并保护人工修改成果不被后续 Agent 运行静默覆盖。本 FR 只定义跨 Construction Run、Research Session 和 Review Run 复用的内容保护基座，包括用户可见的内容状态、覆盖确认和最小修改追溯；具体状态转换和冲突处理由 `05_state_workflow.md` 定义。综述大纲、章节、终稿等 Review Run 专属 P0 最小追溯由 `FR-030` 定义；版本管理增强由 `FR-031` 定义。

**功能范围：**
- 用户可修改检索词、筛选结果、论文有效性和 AI 分析。
- 用户可修改深度研究对话标题、标签和总结文件。
- 用户可修改综述大纲、章节正文、审查建议处理状态和最终稿。
- 用户修改后的内容应标记为人工修改。
- Agent 重新生成前，如涉及覆盖人工确认或人工修改内容，必须提示用户确认。
- 本 FR 不提供面向用户的版本列表、版本差异或回退能力。
- 本 FR 不定义综述大纲、章节或终稿的版本管理；P0 最小追溯由 `FR-030` 承接。版本历史、差异和回退由 `FR-031` 承接。
- 系统应保留最小修改历史，至少能追溯最后修改人、时间、来源和当前内容状态。
- 对文本内容，P0 只要求保存当前内容和必要的修改元数据，不要求自动提炼用户更改意图。
- 冲突时应按 `人工修改 > 人工确认 > Agent 草稿` 的优先级保护内容。

**验收标准：**
- 人工修改内容不会被 Agent 静默覆盖。
- 内容保护优先级为 `人工修改 > 人工确认 > Agent 草稿`。
- 重新生成涉及人工确认或人工修改内容时必须要求用户确认。
- 用户能看到哪些内容是 Agent 草稿、哪些是人工确认、哪些是人工修改。
- 最小历史记录能支持回溯关键修改的最后修改人、时间、来源和内容状态。
- 未实现版本列表、版本差异或回退时，不得影响人工修改保护和重新生成确认。
- Review Run 的综述最小追溯、章节审查历史和未来版本增强不得塞回本 FR，应分别由 `FR-030` 和 `FR-031` 承接。
- 失败或取消的重新生成不得破坏原内容。

#### FR-WORKSPACE-008 知识库版本刷新提示与不打断规则

**需求描述：**
当 Construction Run 成功发布新的 Knowledge Version 后，系统应向用户清楚展示哪些 Research Session / Review Run 仍依赖旧版本，何时可以刷新，以及刷新后会影响哪些后续生成内容。该 FR 只定义用户可见提示、确认和不打断规则；版本生成、稳定 ID、旧版本清理和并发策略由 `03_architecture_decisions.md`、`05_state_workflow.md` 和 `06_data_requirements.md` 定义。

**功能范围：**
- Construction Run 成功后，Workspace 应提示 Project 默认 Knowledge Version 已更新。
- 正在运行的 Research Session / Review Run 不应被强制切换 Knowledge Version。
- 用户应能看到当前 Research Session / Review Run 绑定的 Knowledge Version。
- 用户应能从 Project Knowledge Version 信息、Research Session / Review Run 的绑定版本提示或旧版本依赖提示中主动打开知识库版本刷新交互，而不只能等待系统自动弹出提示。
- 当依赖旧版本的 active Research Session / Review Run 结束后，系统应提示用户知识库依赖可刷新到最新版本。
- 用户确认刷新后，系统将非 active Research Session / Review Run 的知识库依赖刷新到新版本。
- 用户可以拒绝刷新或选择稍后刷新；拒绝或稍后刷新时，相关 Research Session / Review Run 继续绑定旧 Knowledge Version，并应持续展示旧版本提示。
- 当多个 Research Session / Review Run 依赖旧 Knowledge Version 时，系统应逐项展示对象、状态、当前绑定版本和可刷新状态。
- 如果存在用户拒绝刷新或稍后刷新造成的旧版本依赖，用户再次启动 Construction Run 前，系统应进行知识库版本基线预检查，明确展示 Project 默认 Knowledge Version、仍绑定旧版本的对象和本次 Construction Run 将使用的构建基线。
- 版本基线预检查提示应至少包含：Project 默认 Knowledge Version、仍绑定旧版本的 Research Session / Review Run 列表、每个对象是否可刷新、继续构建将不会改写旧对象已完成内容、以及本次 Construction Run 将基于 Project 默认最新 Knowledge Version 写入新的 Knowledge Version。
- 版本基线预检查应提供清晰操作选择：刷新可刷新依赖后继续、保持旧版本依赖并继续构建、取消本次 Construction Run；当仍有 active 对象不可刷新时，应说明只能保持其旧版本依赖或取消构建。
- 旧版本依赖未解决时，系统不得将 Research Session / Review Run 绑定的旧 Knowledge Version 隐式作为新 Construction Run 的写入基线；用户必须先刷新可刷新依赖，或明确确认本次 Construction Run 继续基于 Project 默认最新 Knowledge Version 执行。
- 已完成的 Research 回复、Review 章节和导出产物不会因知识库刷新而自动改写。
- 如果用户选择在同一 Review Run 内中途刷新知识库，应提示后续章节可能使用新版本，已有章节仍保持原内容。

**验收标准：**
- Construction Run 成功后，用户能看到 Project 默认 Knowledge Version 已更新。
- 用户能看到当前 Research Session / Review Run 绑定的 Knowledge Version。
- 用户可主动从 Knowledge Version 信息面板或当前 Run/Session 的绑定版本提示打开知识库版本刷新交互。
- active Research Session / Review Run 在运行期间不会被强制切换 Knowledge Version。
- 依赖旧版本的最后一个 active Research Session / Review Run 结束后，系统能提示用户刷新知识库依赖。
- 用户确认后，非 active Research Session / Review Run 的知识库依赖刷新到最新版本。
- 用户拒绝刷新或选择稍后刷新时，系统不得切换该 Research Session / Review Run 的知识库版本，并应保留旧版本依赖提示。
- 用户拒绝刷新或选择稍后刷新后，再次打开对应对象时仍应能看到旧版本依赖提示。
- 多个实例依赖旧 Knowledge Version 时，系统能展示每个实例的旧版本依赖和可刷新状态。
- 存在旧版本依赖时再次启动 Construction Run，系统能展示版本基线预检查，并说明新 Run 的构建基线与旧版本依赖对象之间的关系。
- 版本基线预检查提示中，用户能看清哪些对象仍在旧版本、哪些可刷新、继续构建会基于哪个版本、继续后哪些内容不会被自动改写。
- 版本基线预检查至少提供刷新后继续、保持旧版本并继续、取消构建三类操作；不可刷新对象存在时，系统能解释不可刷新原因。
- 用户未刷新旧版本依赖且未确认使用 Project 默认最新 Knowledge Version 作为构建基线时，系统不得启动新的 Construction Run。
- 已完成的 Research 回复、Review 章节和导出产物内容保持不变。
- 中途刷新 Review Run 知识库版本时，系统明确提示后续生成与既有章节可能来自不同 Knowledge Version。

#### FR-WORKSPACE-009 Project/Run/Session 导出

**需求描述：**
用户应能按 Project 或具体 Run/Session 导出关键研究资产，用于本地备份、汇报和论文写作。导出能力可以由 `FR-WORKSPACE-001` 提供入口，但不负责界面容器布局，也不负责生成 Research/Review 内容。本 FR 只定义通用导出中心、导出范围预览、权限过滤、异步导出和失败项处理；Review Run 的终稿生成、终审和可导出版本形成由 `FR-029` 定义。

**功能范围：**
- 按 Project 导出论文库结构化数据。
- 按 Project 导出已下载 PDF 集合。
- 按 Research Session 导出对话、引用列表或总结文件。
- 按 Review Run 导出已经由 `FR-029` 生成并确认的可导出版本，包括大纲、章节、终审稿、参考文献或完整综述产物。
- 导出应支持筛选条件、导出范围预览和导出统计。
- 大文件或多文件导出应作为异步任务执行，并通过 `FR-WORKSPACE-005` 展示导出任务状态。
- 缺失文件、无权限文件或生成失败项应记录为跳过项或失败项，不导致可导出部分整体失败。
- 导出内容必须绑定当前用户有权限访问的 Project 或 Run/Session。

**验收标准：**
- 导出内容只包含用户有权限访问的数据。
- 用户可按 Project 导出论文库结构化数据和已下载 PDF 集合。
- 用户可按 Research Session 导出对话、引用列表或总结文件。
- 用户可按 Review Run 导出已经生成并确认的可导出版本，包括大纲、章节、终审稿、参考文献或完整综述产物。
- 用户可设置导出筛选条件，并在导出前查看导出范围和统计。
- 导出中心不得绕过 `FR-029` 直接生成或改写 Review Run 终稿。
- 大文件或多文件导出不阻塞用户继续使用系统，并能在 `FR-WORKSPACE-005` 中查看导出任务状态。
- 缺失文件、无权限文件或生成失败项应记录为跳过项或失败项，不导致可导出部分整体失败。
- 导出失败报告应区分缺失文件、无权限文件、生成失败和任务取消。
- 导出完成后用户能获取文件或失败报告。

### 3.5 构建模式功能需求

#### FR-015 检索词生成与构建检索词管理

**需求描述：**
构建模式应在每个 Project 的 Construction Workspace 中生成并维护可解释、可编辑、可复用的检索词集合。检索词用于手动 Construction Run 的 selected 检索词选择，也可单独配置是否参与系统自动更新任务。

**功能范围：**
- Agent 基于 Project 名称、描述、研究范围和用户补充要求生成检索词。
- 检索词应包含自然语言关键词、布尔表达式、同义词/缩写和排除词建议。
- 系统应展示每组检索词的生成理由、预期覆盖方向和适用数据源。
- 检索词属于当前 Project 的唯一 Construction Workspace。
- 检索词版本至少应包含内容快照、确认时间、修改来源、是否参与自动更新和适用数据源策略。
- 用户可审查、编辑、删除或新增检索词。
- 每个检索词可设置是否参与系统自动更新任务。
- 每个检索词可设置适用数据源策略。
- 检索词数据源策略支持默认使用当前用户和系统可解析的全部数据源。
- 检索词数据源策略支持用户显式选择 arXiv、OpenAlex、Semantic Scholar、ADS 等具体数据源。
- 不设置独立的检索词 `enabled` 标签；手动 Construction Run 通过本次 selected 检索词集合决定使用哪些检索词。
- 自动更新开关不影响用户手动构建时选择该检索词。
- 右侧数据侧栏的构建模式上下文应展示当前检索词版本、待确认状态、自动更新状态、检索词级数据源策略和最近自动运行摘要。
- 用户确认后，检索词版本应保存到 Construction Workspace，用于手动 selected 构建和系统自动构建。

**验收标准：**
- 检索词生成结果可被用户查看、修改和确认。
- 检索词结果包含自然语言关键词、布尔表达式、同义词/缩写和排除词建议。
- 每组检索词应展示生成理由、预期覆盖方向和适用数据源。
- 用户可新增、编辑或删除检索词。
- 用户可为每个检索词设置是否参与系统自动更新任务。
- 用户可为每个检索词设置适用数据源；未显式设置时默认使用用户和系统当前可解析的全部数据源。
- 手动 Construction Run 可选择任意已保存检索词作为本次 selected 检索词，不受自动更新开关限制。
- 右侧数据侧栏能展示当前检索词版本、待确认状态、自动更新状态、检索词级数据源策略和最近自动运行摘要。
- 未确认检索词时，手动构建不得进入多源检索阶段。
- 检索词确认记录应可追溯到当前 Project。
- 检索词确认记录应包含内容快照、确认时间、修改来源、是否参与自动更新和适用数据源策略。
- 历史 Construction Run 应能基于其配置快照复现当时使用的检索词内容和数据源策略，即使当前检索词已被修改或删除。
- 检索词生成失败时，用户可手动输入检索词继续流程。

#### FR-016 多源论文检索

**需求描述：**
构建模式应根据 Construction Run 的启动方式解析本次检索词集合和数据源集合，调用多个学术数据库，汇总当前 Project 的候选论文集合。手动 Run 使用用户本次 selected 检索词；自动 Run 使用 `auto_update_enabled=true` 的检索词。

**功能范围：**
- 支持 arXiv、OpenAlex、Semantic Scholar、ADS 等已启用数据源。
- 手动 Construction Run 使用用户本次选择的 selected 检索词集合。
- 自动 Construction Run 使用 Construction Workspace 中 `auto_update_enabled=true` 的检索词集合。
- 每个检索词使用自己的数据源策略解析可用数据源。
- 检索词未显式选择数据源时，默认使用当前用户和系统可解析的全部数据源。
- Construction Run 启动时应生成配置快照，包括检索词内容、检索词来源、数据源策略、解析后的数据源、用户/系统配置来源。
- 系统根据数据源能力转换检索表达式和请求参数。
- 支持在 Run 启动参数中配置检索时间范围和返回数量上限。
- 数据源可用性由 `FR-003`、`FR-007` 和检索词级数据源策略共同解析，不维护 Project 默认数据源。
- 单个数据源失败时应记录原因，并允许其他数据源继续。
- 如果本次 Run 的所有实际数据源均失败或不可解析，系统不得进入去重、评分与筛选阶段，应记录失败项并允许用户调整配置后重试或新建 Run。
- 配置解析失败的检索词或数据源应记录为失败项，不应破坏其他可执行检索词。
- 检索完成后展示各数据源命中数量、失败原因、候选列表和下一步操作。
- 右侧数据侧栏的构建模式上下文应展示查询结果摘要，包括各数据源命中数、失败数据源、候选论文数量和可跳转的检索结果分组。
- 检索结果应记录来源检索词和来源数据源，便于邮件解释、去重审计和后续诊断。
- 用户可确认进入去重评分，也可调整检索词后重新发起新的 Construction Run。

**验收标准：**
- 检索请求只使用已启用数据源，并能覆盖 arXiv、OpenAlex、Semantic Scholar、ADS。
- 手动 Construction Run 只使用用户本次 selected 检索词集合。
- 自动 Construction Run 只使用 `auto_update_enabled=true` 的检索词集合。
- 检索词级数据源策略能正确解析为本次 Run 的实际数据源集合。
- Run 配置快照能记录检索词内容、来源、数据源策略、解析后的数据源和配置来源。
- 系统能按数据源能力转换检索表达式和请求参数。
- 用户可配置本次 Run 的检索时间范围和返回数量上限。
- 实际数据源集合来自用户/系统配置解析和检索词级数据源策略，不依赖 Project 默认数据源。
- 检索结果包含标题、作者、日期、来源、摘要、外部 ID 或 URL 等基础元数据。
- 数据源失败有明确提示，不应导致已成功数据源结果丢失。
- 部分数据源失败时，成功数据源结果可继续进入下一步，但失败数据源、失败原因和受影响检索词必须可见。
- 所有数据源均失败或不可解析时，系统不得进入去重、评分与筛选阶段，并应展示失败项、失败原因和可修复建议。
- 检索完成后能展示各数据源命中数量、失败原因、候选列表和下一步操作。
- 右侧数据侧栏能展示查询结果摘要、失败数据源、候选论文数量和可跳转结果分组。
- 用户能区分每篇候选论文来自哪些数据源。
- 用户能区分每篇候选论文来自哪些检索词。
- 用户确认后，候选论文才能进入去重、评分与筛选阶段。

#### FR-017 论文去重、评分与筛选

**需求描述：**
系统应对候选论文进行去重、评分和筛选，形成当前 Project 的有效论文集合。

**功能范围：**
- 基于 DOI、arXiv ID、外部 ID、标准化标题进行去重。
- 候选论文应先进行 identity resolution，识别其是否命中论文库中已存在论文。
- 命中论文库中已存在论文的候选项应标记为已存在，并从本次增量处理流水线中排除。
- Agent 根据标题、摘要等信息评估理论价值、技术价值和 Project 相关性。
- 系统根据阈值判断论文是否有效。
- 评分阈值来源应明确展示，可来自系统默认、管理员系统级配置、Run 配置快照或用户本次调整。
- 用户可查看评分理由并手动调整评分、有效性或去重合并结果。
- 用户可触发重新评分或返回检索阶段补充检索词。
- 右侧数据侧栏的构建模式上下文应展示候选、重复、有效、无效、待确认和失败论文数量，并支持跳转到对应筛选结果。

**验收标准：**
- 同一 Project 内不会重复关联同一论文。
- 去重逻辑至少使用 DOI、arXiv ID、外部 ID、标准化标题进行判断。
- 命中论文库中已存在论文的候选项不会进入下载、解析、AI 分析、入库、图谱更新或推送流程。
- 评分结果包含分数、是否有效和理由。
- 评分阈值来源应可追溯，并在用户确认筛选前展示。
- 用户可查看评分理由并手动调整评分、有效性或去重合并结果。
- 用户可撤销或修正误判的去重合并结果，修正后候选、重复、有效和无效统计应同步更新。
- 用户可触发重新评分或返回检索阶段补充检索词。
- 右侧数据侧栏能展示候选、重复、有效、无效、待确认和失败论文数量，并支持跳转筛选。
- 用户手动调整后，Project 有效论文统计应同步更新。
- 用户人工调整评分或有效性后，候选、有效、无效和 Project 有效论文统计应同步更新。
- 命中已有论文库记录的候选项应可追溯其被排除原因和已有论文关联。
- 用户确认筛选结果后，系统才能进入下载解析和后续入库流程。

#### FR-018 论文补充与手动上传

**需求描述：**
用户应能在构建模式中补充系统未检索到但对课题重要的论文或资料。论文上传、补充、移除当前 Project 关联等会改变论文库内容的操作只能在构建模式中执行。

**功能范围：**
- 支持通过 DOI、arXiv ID、URL 添加论文。
- 支持上传 PDF 文件。
- 上传文件应校验文件大小、文件类型和基础可读性；失败时不得创建已确认论文记录。
- 支持批量上传属于 P1 能力。
- DOI、arXiv ID 或 URL 添加时，系统应基于用户提供的外部标识调用可用数据源补全论文元数据。
- PDF-only 上传时，系统应先基于 PDF 文件本身进行本地元数据提取，包括 PDF 内嵌 metadata、首页/前几页文本、文件名线索、DOI、arXiv ID、标题、作者、摘要等候选信息。
- PDF-only 本地解析提取出 DOI、arXiv ID、较可信标题或标题+作者等查询锚点后，系统才调用可用外部数据源进行元数据补全与校验。
- PDF-only 本地解析和外部补全后关键元数据仍不完整时，系统可调用独立的 LLM 元数据抽取函数生成结构化元数据草稿，并标记置信度、缺失字段和证据来源。
- 系统完成本地解析、外部补全或 LLM 元数据抽取后，应进入待确认状态，用户确认后才能进入去重、解析、分析、入库流程。
- PDF-only 上传且系统无法提取 DOI、标题或作者时，用户至少必须补充标题、作者或来源说明中的必要元数据后才能确认加入当前 Project。
- 用户可编辑自动提取的论文元数据并确认是否加入当前 Project。
- 支持从当前 Project 移除论文关联，但不删除全局 `papers` 记录。
- 支持清空当前 Project 的论文关联，操作前必须二次确认。
- 右侧数据侧栏的构建模式上下文应展示手动补充、上传解析、待确认元数据和移除结果摘要。

**验收标准：**
- 用户可通过 DOI、arXiv ID、URL 添加论文，或上传 PDF 文件。
- 批量上传未实现前，不得阻塞单篇补充和单文件上传。
- DOI、arXiv ID 或 URL 添加时，系统能基于外部标识补全论文元数据。
- PDF-only 上传时，系统必须先从 PDF 文件本身提取候选元数据，不得在没有 DOI、arXiv ID、标题或作者等查询锚点时直接依赖外部 API 查询。
- PDF-only 本地解析产生查询锚点后，系统可调用外部数据源补全与校验元数据。
- 关键元数据不完整时，系统可调用独立 LLM 元数据抽取函数生成待确认结构化草稿，且不得把 LLM 草稿直接作为用户已确认元数据。
- 系统能提取或要求用户补充元数据，并在用户确认后将补充论文送入去重、解析、分析、入库流程。
- PDF-only 上传无法自动提取关键元数据时，系统必须要求用户补充最小元数据后才能继续。
- 成功添加的论文会关联到当前 Project。
- 上传或解析失败时应展示失败原因。
- 大文件、非 PDF、损坏 PDF 或本地解析失败时，应展示失败原因并允许用户重新上传或改用 DOI/arXiv ID/URL。
- 用户补充论文不得绕过去重和权限检查。
- 用户确认后的补充论文应进入与检索论文一致的后续流程。
- 移除论文关联后其他 Project 不受影响。
- 清空当前 Project 论文关联前必须二次确认。
- 右侧数据侧栏能展示手动补充、上传解析、待确认元数据和移除结果摘要。
- 深度研究、主题综述和基础层只读查阅入口不得执行论文上传或移除操作。

#### FR-019 PDF 下载与文本解析

**需求描述：**
系统应尽量获取论文全文并解析为后续 AI 分析和 RAG 检索可用的文本。

**功能范围：**
- 根据论文元数据尝试自动下载 PDF。
- 解析 PDF 文本，并保存文件路径和解析状态。
- 下载失败或解析失败时记录原因，并使用摘要作为降级文本。
- 摘要降级文本可进入后续 AI 分析；进入向量化或 RAG 时应标记为摘要降级来源，避免用户误认为已使用全文。
- 用户可对失败论文触发重试，或上传本地 PDF 替代自动下载结果。
- 保存可供基础层查阅使用的 PDF 本地路径、远程访问地址或签名 URL 元数据。
- 下载解析阶段完成后，应展示成功、失败、降级统计供用户确认。
- 右侧数据侧栏的构建模式上下文应展示 PDF 下载、文本解析、失败降级和待重试论文摘要。

**验收标准：**
- 成功下载的论文可查看或下载 PDF。
- 系统能根据论文元数据尝试自动下载 PDF。
- 系统能解析 PDF 文本并保存文件路径和解析状态。
- 下载失败或解析失败时应记录原因，并使用摘要作为降级文本。
- 摘要降级文本可用于后续 AI 分析；用于向量化或 RAG 时必须标记其来源为摘要降级。
- 用户在论文详情、RAG 引用或综述引用中应能识别该文本来自摘要降级而非全文解析。
- 用户可对失败论文触发重试，或上传本地 PDF 替代自动下载结果。
- 基础层论文详情可打开有权限访问的 PDF 或远程文件入口。
- 下载解析阶段完成后能展示成功、失败、降级统计供用户确认。
- 右侧数据侧栏能展示 PDF 下载、文本解析、失败降级和待重试论文摘要。
- 解析文本可被后续 AI 分析使用。
- 失败论文不会阻断整个构建流程。
- 用户确认下载解析结果后，系统才能进入 AI 分析阶段。

#### FR-020 论文 AI 分析生成

**需求描述：**
系统应对论文文本生成结构化 AI 分析，帮助用户快速判断论文价值。

**功能范围：**
- 生成一句话总结。
- 提取亮点解析。
- 提取与 Project 的相关性要点。
- 提取技术方法与创新点。
- AI 分析结果应使用可验证的结构化字段；字段缺失、格式错误或部分生成失败时应记录状态并允许重试或人工补全。
- 用户可编辑、确认或重新生成分析。
- 重新生成前应提示是否覆盖用户已保存的手动修改。
- 右侧数据侧栏的构建模式上下文应展示 AI 分析完成、失败、待确认和用户已修改论文摘要。

**验收标准：**
- AI 分析结果可在论文详情中查看。
- AI 分析结果至少包含一句话总结、亮点解析、Project 相关性要点、技术方法与创新点。
- AI 分析结果字段缺失、格式错误或部分生成失败时，系统应标记失败或部分失败状态，并允许重试或人工补全。
- 用户可编辑、确认或重新生成分析结果。
- 重新生成不会丢失用户明确保存的手动修改，除非用户确认覆盖。
- 右侧数据侧栏能展示 AI 分析完成、失败、待确认和用户已修改论文摘要。
- 分析失败应记录状态并允许重试。
- 人工补全后的 AI 分析字段应标记为人工修改，重新生成前必须遵守 `FR-WORKSPACE-007` 的覆盖确认规则。
- 用户确认后的分析结果才能作为入库和后续综述/深研上下文使用。

#### FR-021 知识库入库与图谱构建

**需求描述：**
系统应将 Construction Run 产出的有效论文写入 Project 知识库，并维护后续 Graph-RAG 所需的向量库、知识图谱和知识库版本。

**功能范围：**
- 将论文元数据、Project 关联、评分、AI 分析和文件路径持久化。
- 将论文文本切分并写入向量检索库。
- 基于论文、作者、关键词、概念、方法等实体构建或增量更新知识图谱。
- 图谱创建、增量更新、重建、修复只能由 Construction Run 触发。
- 入库前向用户展示即将入库的有效论文、跳过项和风险提示。
- 入库过程应支持增量更新和失败回滚/补偿。
- 入库完成后展示入库、向量化、图谱更新结果和失败项。
- 入库、向量化、图谱更新和 Knowledge Version 生成应分别展示成功、跳过、失败和可恢复状态。
- 成功完成入库和图谱更新后，当前 Construction Run 应生成新的 Project Knowledge Version，并按 `FR-WORKSPACE-008` 提示知识库版本刷新。
- Construction Workspace 不直接生成 Knowledge Version。
- 右侧数据侧栏的构建模式上下文应展示入库、向量化、Graph 节点/边更新和失败项摘要，并支持跳转到基础层论文库或 Graph 图谱查看结果。

**验收标准：**
- 系统能持久化论文元数据、Project 关联、评分、AI 分析和文件路径。
- 系统能将论文文本切分并写入向量检索库。
- 系统能基于论文、作者、关键词、概念、方法等实体构建或增量更新知识图谱。
- 入库前用户能看到即将入库的有效论文、跳过项和风险提示。
- 入库成功后，论文可在 Project 论文库中查看。
- 向量化成功后，已同步文本可被后续检索使用；未同步或失败文本不得被误标为可检索。
- 图谱更新成功后，基础层 Graph 图谱可展示最新节点和关系。
- Knowledge Version 只能在入库、向量化和必要图谱更新结果达到可发布条件后生成；生成后应将 Project 默认知识库版本更新到最新成功构建版本。
- Construction Workspace 本身不应被当作 Knowledge Version。
- 入库过程支持增量更新，并在失败时能回滚或补偿。
- 向量库或图谱无法与关系库同事务提交时，系统应记录同步状态、补偿任务或失败项，不得把未同步数据标记为可检索或图谱可用。
- Research Session 和 Review Run 只能使用已入库且有效的数据对应的知识库版本。
- Research Session、Review Run 和基础层只读查阅入口不得触发图谱重建或写入。
- 向量库或图谱更新失败时应可诊断并可恢复。
- Knowledge Version 只有在关系库、向量同步和必要图谱更新达到可发布条件后才能发布；未达到条件时应保留失败或待修复状态。
- 入库、向量化、图谱更新和 Knowledge Version 生成的结果应分别可诊断，失败项不得被静默混入成功项。
- 用户能明确看到哪些论文成功进入知识库，哪些论文被跳过或失败。
- 右侧数据侧栏能展示入库、向量化、Graph 节点/边更新和失败项摘要，并支持跳转到论文库或 Graph 图谱。

#### FR-022 邮件推送服务

**需求描述：**
系统应将当前 Project 未推送的有效论文整理为邮件，发送给用户配置的收件人。本 FR 只定义邮件内容生成、发送范围、预览、空邮件保护和推送状态；用户收件人与通知偏好由 `FR-004` 定义，自动构建调度和本次新增有效论文范围由 `FR-013` 提供。

**功能范围：**
- 自动 Construction Run 完成后，系统基于 `FR-013` 提供的本次新增有效论文范围自动触发邮件推送。
- 手动 Construction Run 完成后，用户可在结果页预览并手动触发邮件发送。
- 邮件内容包含 Project 名称、有效论文统计和论文摘要列表。
- 自动 Construction Run 完成后只推送本次新增有效论文。
- 手动 Construction Run 完成后可由用户预览并手动触发发送。
- 仅发送当前 Project 中未推送且用户有权限接收的有效论文。
- 发送前应允许用户预览本次推送范围；自动任务可按默认策略直接发送。
- 邮件内容应能展示论文来源检索词和来源数据源。
- 发送成功后记录推送状态。
- 邮件发送失败时应记录失败原因，不得将未成功发送的论文标记为已推送。
- 多个收件人或多篇论文部分发送成功时，应分别记录成功项和失败项。
- 手动重发属于 P1 支撑能力。

**验收标准：**
- 自动 Construction Run 成功后，系统能基于本次新增有效论文范围自动触发邮件推送。
- 手动 Construction Run 成功后，用户能在结果页预览并手动触发邮件发送。
- 邮件内容包含 Project 名称、有效论文统计和论文摘要列表。
- 自动 Construction Run 成功后，邮件只包含本次新增有效论文。
- 邮件只包含当前 Project 中未推送且用户有权限接收的有效论文。
- 发送前用户能预览本次推送范围；自动任务可按默认策略直接发送。
- 邮件能展示论文来源检索词和来源数据源。
- 无未推送有效论文时不发送空邮件。
- 发送成功后能记录推送状态。
- 邮件发送失败不应回滚已完成的论文入库。
- 推送状态必须与发送结果一致；发送失败的论文不得标记为已推送，部分发送成功时应能区分成功项和失败项。
- 无未推送有效论文时，系统应记录空邮件跳过原因而不是发送空邮件。
- 手动构建场景下，用户能看到本次邮件推送范围和发送结果。
- 手动重发未实现前，不得阻塞正常自动推送和手动首次发送。

### 3.6 深度研究模式功能需求

#### FR-023 Graph-RAG 对话式研究

**需求描述：**
深度研究模式应以 Research Session 形式基于某个 Project 知识库版本，为用户提供多轮、流式、可引用的研究对话。

**功能范围：**
- 用户可创建和管理多个 Research Session。
- 每个 Research Session 应绑定一个知识库版本。
- 每轮对话基于该 Session 绑定的知识库版本自动执行 Graph-RAG 检索。
- Agent 回复应结合对话历史和检索上下文。
- 回复支持流式输出。
- 流式回复中断、用户取消、检索为空或 LLM 失败时，应保留可诊断状态，不得把半成品回复保存为成功对话轮次。
- 回复应展示引用论文、PDF/远程访问入口或图谱节点信息。
- 右侧数据侧栏的深度研究模式上下文应展示当前对话使用的知识库版本、引用论文、引用文段、Graph-RAG 命中来源和相关图谱节点摘要。
- 用户可从回复引用跳转到基础层论文详情或 Graph 图谱节点。
- Construction Run 完成并产生新知识库版本时，已有 Research Session 应提示可刷新，但不得中断当前会话或正在生成的回复。
- Research Session 的知识库版本刷新应遵守 `FR-WORKSPACE-008`。

**验收标准：**
- 无可用知识库版本时不能创建新的 Research Session。
- 用户可创建和管理多个 Research Session。
- 新建 Research Session 默认绑定 Project 当前默认知识库版本。
- 每轮对话基于 Session 绑定的知识库版本自动执行 Graph-RAG 检索，并结合对话历史和检索上下文生成回复。
- Agent 回复支持流式输出。
- 回复能展示引用论文、PDF/远程访问入口或图谱节点信息。
- 右侧数据侧栏能展示当前对话使用的知识库版本、引用论文、引用文段、Graph-RAG 命中来源和相关图谱节点摘要。
- 每轮成功对话都应保存用户输入、Agent 回复和引用信息。
- 流式回复中断或用户取消时，系统应记录中断/取消状态；未完成回复不得作为成功轮次写入。
- Graph-RAG 检索为空时，系统可提示无检索结果并允许用户继续普通回复或调整问题；若继续回复，应明确标记无引用上下文。
- LLM 失败、检索失败或流式中断时，用户输入和失败状态可追溯，但 Agent 半成品不得写入成功回复。
- 对话引用必须能跳转到当前 Project 的论文详情或图谱节点。
- 新 Construction Run 完成后，已有 Research Session 不自动切换知识库版本。
- Research Session 的知识库依赖刷新应在 active Research Session 任务结束后按 `FR-WORKSPACE-008` 执行。
- LLM 或检索失败时不得写入成功态半成品对话轮次。

#### FR-024 深度研究输出倾向设置

**需求描述：**
深度研究模式应提供输出倾向设置按钮，允许用户通过选择不同倾向来控制当前 Research Session 的整体对话风格。该能力属于 P1 增强，不改变 Research Session 的知识库版本绑定、对话历史或 Graph-RAG 主流程。

**功能范围：**
- Research Session 工作台应提供输出倾向设置按钮或等效控件。
- 系统至少支持创新、实验、总结三类输出倾向。
- 创新倾向用于控制整体对话风格偏向提出潜在研究方向、假设和组合思路。
- 实验倾向用于控制整体对话风格偏向设计实验方案、变量、指标和验证步骤。
- 总结倾向用于控制整体对话风格偏向整理已有讨论、结论、未决问题和下一步计划。
- 用户可在 Research Session 中切换输出倾向，切换不清空对话上下文或知识库版本绑定。
- 输出倾向只影响后续 Agent 回复风格，不自动改写历史回复。

**验收标准：**
- 用户能通过按钮或等效控件明确选择当前输出倾向。
- 系统至少支持创新、实验、总结三类输出倾向。
- 不同倾向下后续回复的组织方式和关注点应体现对应风格。
- 切换倾向后仍能引用同一对话历史和同一知识库版本。
- 切换倾向不会自动改写历史回复。
- 输出倾向只影响后续回复；历史消息、引用、总结和知识库版本绑定均不得因倾向切换而改变。
- 创新倾向应偏向研究方向、假设和组合思路。
- 实验倾向应偏向实验方案、变量、指标和验证步骤。
- 总结倾向应偏向已有讨论、结论、未决问题和下一步计划。

#### FR-025 对话历史、总结文件与导出

**需求描述：**
系统应保存 Research Session 的深度研究过程，并支持将对话和阶段性结论整理为可导出的研究资料。

**功能范围：**
- 保存对话列表、轮次、标题、标签、摘要和最后活跃时间。
- 保存 Research Session 绑定的知识库版本。
- 支持搜索、筛选和归档对话。
- 支持按需生成对话总结。
- 支持导出对话或总结文件。

**验收标准：**
- 对话历史按时间顺序完整可追溯。
- 系统能保存对话列表、轮次、标题、标签、摘要和最后活跃时间。
- 系统能保存每个 Research Session 绑定的知识库版本。
- 用户可搜索、筛选和归档对话。
- 用户可按需生成对话总结。
- 用户可导出对话或总结文件。
- 归档对话不得继续追加消息。
- 总结内容应能反映对话中的关键结论和未决问题。
- 总结生成失败时应记录失败原因，并不得覆盖已有成功总结。
- 归档 Research Session 后不得继续追加用户消息、Agent 回复或总结生成结果。

#### FR-026 研究引用与图谱跳转

**需求描述：**
用户应能在 Research Session 中围绕对话引用只读探索当前 Project 及其绑定知识库版本中的论文、PDF 访问入口和 Graph 图谱关系。Graph 图谱本身属于基础层全局可视化能力，本 FR 只定义深度研究模式中的引用上下文和跳转体验。

**功能范围：**
- 展示当前对话轮次使用过的论文引用、文段来源和图谱节点。
- 展示当前 Research Session 绑定的知识库版本。
- 当引用来自旧 Knowledge Version 时，应展示引用对应的版本标识，并提示该引用来自历史知识库版本。
- 上述引用、文段来源和图谱节点应作为右侧数据侧栏的深度研究上下文展示，帮助用户在对话过程中持续查看当前证据来源。
- 支持从对话引用跳转到基础层论文详情。
- 支持从对话引用跳转到基础层 Graph 图谱，并高亮相关节点和边。
- 支持从论文详情打开有权限访问的 PDF 或远程文件入口。
- 不允许在 Research Session 中修改论文库、上传论文、移除论文关联或触发图谱重建。

**验收标准：**
- 系统能展示当前对话轮次使用过的论文引用、文段来源和图谱节点。
- 系统能展示当前 Research Session 绑定的知识库版本。
- 深度研究上下文能在右侧数据侧栏持续展示当前证据来源。
- 引用跳转只展示当前 Project 的数据。
- 引用跳转应尊重 Research Session 绑定的 Knowledge Version；引用来自旧 Knowledge Version 时，系统应展示版本提示并避免误指向新版本语境。
- 用户可从对话引用跳转到基础层论文详情。
- 用户可从对话引用跳转到基础层 Graph 图谱，并高亮相关节点和边。
- 用户可从论文详情打开有权限访问的 PDF 或远程文件入口。
- Research Session 不得修改论文库、上传论文、移除论文关联或触发图谱重建。
- 深度研究中的图谱跳转不改变论文库、向量库或图谱存储。
- 图谱数据缺失或过期时应提示用户返回构建模式更新。
- 越权、缺失、旧版本或图谱节点不存在的引用跳转应展示安全提示，不得暴露其他 Project 数据。

### 3.7 主题综述模式功能需求

#### FR-027 综述架构设计

**需求描述：**
综述模式应以 Review Run 形式基于 Project 主题和某个知识库版本，帮助用户生成、审查并确认综述文章架构。

**功能范围：**
- Agent 扩写研究主题、范围和背景。
- Review Run 应绑定一个知识库版本。
- Agent 生成综述标题、摘要提示和章节结构。
- Agent 对大纲覆盖度、章节顺序、主题边界和论文支撑度进行自审。
- 用户可查看审查结果，编辑章节标题、类型、顺序和要点。
- 用户可查看当前 Project 论文库和 Graph 图谱提供的综述支撑情况。
- 对低支撑章节，系统应展示风险提示和建议补充方向；用户仍可确认大纲，但确认动作应记录低支撑风险。
- 右侧数据侧栏的主题综述模式上下文应展示知识库版本、大纲章节、每章论文支撑度、低支撑章节和建议补充的论文方向。
- 用户可重新生成、局部修改或确认架构。
- 用户确认架构后，系统才能开始章节撰写。
- Review Run 的知识库版本刷新应遵守 `FR-WORKSPACE-008`。

**验收标准：**
- 无可用知识库版本时不能创建新的 Review Run。
- 新建 Review Run 默认绑定 Project 当前默认知识库版本。
- Agent 能扩写研究主题、范围和背景。
- Agent 能生成综述标题、摘要提示和章节结构。
- Agent 能对大纲覆盖度、章节顺序、主题边界和论文支撑度进行自审。
- 用户可查看审查结果，并编辑章节标题、类型、顺序和要点。
- 用户可查看当前 Project 论文库和 Graph 图谱提供的综述支撑情况。
- 右侧数据侧栏能展示知识库版本、大纲章节、每章论文支撑度、低支撑章节和建议补充方向。
- 用户可确认包含低支撑章节的大纲，但系统必须提示风险、展示建议补充方向，并记录用户确认。
- 大纲确认记录应绑定当前大纲版本和 Review Run 的 Knowledge Version。
- 架构确认前不得自动撰写章节。
- 确认后的架构应保存版本记录。
- 架构审查结果必须和当前大纲版本绑定，不得覆盖历史版本。
- 新 Construction Run 完成后，已有 Review Run 不自动切换知识库版本。
- Review Run 的知识库依赖刷新应在 active Review Run 任务结束后按 `FR-WORKSPACE-008` 执行。

#### FR-028 章节撰写、引用与修订

**需求描述：**
系统应按已确认的综述架构和 Review Run 绑定的知识库版本撰写章节内容，自动引用 Project 论文库中的相关论文，并支持章节级审查和人工修订。

**功能范围：**
- Agent 按章节逐章生成 Markdown 正文。
- 每章撰写前基于 Review Run 绑定的知识库版本检索相关论文或文段作为上下文。
- 章节内容应包含可追溯引用。
- 用户可从章节引用跳转到基础层论文详情、PDF/远程访问入口或 Graph 图谱节点。
- 右侧数据侧栏的主题综述模式上下文应展示知识库版本、当前章节引用论文、引用段落、引用覆盖状态、未引用的重要论文和相关 Graph 节点摘要。
- Agent 对章节准确性、完整性、逻辑结构和引用规范进行自审。
- 用户可查看审查问题、接受建议、手动编辑、重新审查或重新生成章节。
- 同一 Review Run 内可并行处理不同章节，但同一章节在同一时间只允许一个生成、审查或写入任务。
- 引用不足默认提示风险但不强制阻断章节确认；若用户开启严格引用覆盖要求，则引用不足应阻断确认直到用户处理或显式降低要求。
- 系统记录章节审查历史和修订次数。

**验收标准：**
- 章节只能基于已确认大纲生成。
- Agent 能按章节逐章生成 Markdown 正文。
- 每章撰写前应基于 Review Run 绑定的知识库版本检索相关论文或文段作为上下文。
- 章节内容应包含可追溯引用。
- 引用必须能映射到当前 Project 论文库。
- 用户可从章节引用跳转到基础层论文详情、PDF/远程访问入口或 Graph 图谱节点。
- 右侧数据侧栏能展示知识库版本、当前章节引用论文、引用段落、引用覆盖状态、未引用的重要论文和相关 Graph 节点摘要。
- Agent 能对章节准确性、完整性、逻辑结构和引用规范进行自审。
- 用户可查看审查问题、接受建议、手动编辑、重新审查或重新生成章节。
- 同章写入互斥：同一章节不得同时存在多个生成、审查或保存任务写入当前内容。
- 引用不足时系统应提示风险和建议补充来源；默认不强制阻断确认，用户启用严格引用覆盖要求时除外。
- 章节引用跳转不得修改论文库或图谱。
- 用户编辑后的章节内容应保存。
- 用户未确认前，不得静默覆盖用户手动修改。
- 审查结果应与章节版本对应，不能覆盖其他章节。
- 系统应记录章节审查历史和修订次数。
- 同一章节的生成、审查、保存或重新生成任务重复提交时，系统应拒绝冲突写入或返回已有任务状态。
- 严格引用覆盖要求开启时，引用不足必须阻断章节确认，直到用户处理或显式降低要求。

#### FR-029 综述汇总、终审与可导出版本生成

**需求描述：**
系统应将 Review Run 中已完成章节汇总为完整综述文章，执行全文级终审，并生成可供导出中心使用的最终版本。本 FR 定义综述终稿生成、终审和可导出版本形成；具体导出入口、范围预览、权限过滤、异步任务和文件获取由 `FR-WORKSPACE-009` 定义。

**功能范围：**
- 自动合并已确认章节。
- 自动生成摘要、关键词和参考文献列表。
- Agent 执行全文一致性、重复内容、引用完整性和格式规范终审。
- 用户可查看终审问题、编辑完整文章、重新生成摘要/参考文献或确认最终稿。
- 右侧数据侧栏的主题综述模式上下文应展示知识库版本、全文引用覆盖、参考文献完整性、未解决终审问题和可导出版本状态。
- 用户确认最终稿后，系统生成可导出版本，供 `FR-WORKSPACE-009` 导出为 Markdown、PDF、Word 等格式。
- Review Run 应能明确哪些章节是汇总最终文章的必需章节；可选章节缺失不得阻断汇总，必需章节缺失或未确认时不得汇总。

**验收标准：**
- 所有必需章节完成并确认后才能汇总最终文章。
- 必需章节范围应来自已确认大纲，并在汇总前展示给用户。
- 系统能自动合并已确认章节。
- 系统能自动生成摘要、关键词和参考文献列表。
- Agent 能执行全文一致性、重复内容、引用完整性和格式规范终审。
- 用户可查看终审问题、编辑完整文章、重新生成摘要/参考文献或确认最终稿。
- 右侧数据侧栏能展示知识库版本、全文引用覆盖、参考文献完整性、未解决终审问题和可导出版本状态。
- 参考文献应覆盖文章中实际引用的论文。
- 终审问题必须展示给用户，用户确认后才能生成最终可导出版本。
- 最终可导出版本应包含完整文章、摘要、关键词、参考文献和终审状态。
- 未解决终审问题应在最终稿确认前展示；用户确认忽略或处理后，系统应记录处理状态。
- 可导出版本应记录生成时间、来源 Review Run、绑定 Knowledge Version 和最终稿确认状态。
- Markdown、PDF、Word 等文件导出由 `FR-WORKSPACE-009` 承载，导出内容应与本 FR 生成的可导出版本一致。

#### FR-030 综述最小追溯管理

**需求描述：**
系统应在主题综述模式内承接 Review Run 主流程所需的 P0 最小追溯能力，用于追踪大纲确认、章节当前内容、章节审查历史和最终稿确认状态。该能力建立在 `FR-WORKSPACE-007` 的通用内容保护基座之上，但不提供面向用户的完整版本列表、版本差异或历史回退；这些增强能力由 `FR-031` 定义。

**功能范围：**
- 追溯范围以 Review Run 为边界，不跨 Review Run 合并历史。
- 系统应追踪 Review Run 的大纲确认记录、章节当前内容、章节审查历史和最终稿确认状态。
- 用户修改大纲、章节或最终稿后，系统应记录最后修改人、最后修改时间、来源动作和内容状态。
- 章节审查历史应至少能关联到当时的章节内容状态或修订次数，避免后续修改让审查上下文完全丢失。
- 后续章节重新生成、章节审查或终稿汇总不得静默覆盖人工修改内容；覆盖规则以 `FR-WORKSPACE-007` 为准。
- 本 FR 不要求提供版本历史列表、只读快照、版本差异、历史回退或用户更改摘要。
- 边界：本 FR 不负责通用内容保护状态和覆盖确认规则；这些由 `FR-WORKSPACE-007` 定义。
- 边界：本 FR 不负责综述终稿生成和可导出版本形成；这些由 `FR-029` 定义。
- 边界：本 FR 不负责导出入口、导出范围预览、权限过滤或异步导出任务；这些由 `FR-WORKSPACE-009` 定义。
- 边界：本 FR 不负责 P2 版本历史、只读快照、版本差异、历史回退或用户更改摘要；这些由 `FR-031` 定义。

**验收标准：**
- 系统至少能追踪已确认大纲、当前章节内容、章节审查历史和最终稿确认状态。
- 用户修改大纲、章节或最终稿后，系统能记录最后修改人、最后修改时间、来源动作和内容状态。
- 章节审查历史能关联到当时的章节内容状态或修订次数。
- 未实现版本列表、版本快照、版本差异或回退时，不得阻塞大纲确认、章节撰写、章节审查、终稿生成和人工修改保护。
- 后续章节重新生成、章节审查或终稿汇总不得静默覆盖人工修改内容；覆盖规则以 `FR-WORKSPACE-007` 为准。

#### FR-031 综述版本管理与变更摘要增强

**需求描述：**
主题综述模式可在 P2 阶段提供 Review Run 专属的完整版本管理与变更摘要增强，用于查看大纲、章节和全文的历史演进、差异、回退和用户更改摘要。本 FR 不阻塞 `FR-027`、`FR-028`、`FR-029` 和 `FR-030` 的 P0 主流程。

**功能范围：**
- 系统可提供 Review Run 内的大纲版本、章节版本和全文版本历史列表。
- 系统可支持将历史版本作为只读快照查看。
- 系统可支持大纲结构、章节 Markdown 文本和全文 Markdown 文本的版本差异查看。
- 系统可支持历史版本回退；回退前必须二次确认，并说明影响的大纲、章节、终稿或导出版本。
- 回退历史版本时应生成新的当前版本，不得删除原历史版本。
- 系统可基于文本 diff 和上下文提炼用户更改摘要，例如“用户补充了方法局限性”或“用户调整了章节论证顺序”。
- 用户更改摘要只能作为辅助阅读和后续 Agent 上下文提示，不得作为内容覆盖、权限判断、自动回退或验收通过的依据。

**验收标准：**
- 未实现本 FR 时，不得阻塞大纲确认、章节撰写、章节审查、终稿生成、最小追溯和人工修改保护。
- 用户能查看 Review Run 内的大纲、章节或全文版本历史列表，并识别版本类型、来源动作、创建时间和创建人。
- 用户查看历史版本时，系统以只读快照展示，不得静默覆盖当前内容。
- 版本差异能展示大纲结构、章节正文或全文内容的变化。
- 历史版本回退必须二次确认，并生成新的当前版本。
- 若实现用户更改摘要，摘要内容必须标记为辅助说明，且不得替代原始内容、修改元数据或人工确认动作。

#### 5.3 Web App FR 审查知识点

- FR 应描述用户可见能力和业务规则，不应直接承担数据库字段、API 响应或前端 ViewModel 字段定义。
- 每条 FR 的验收标准必须覆盖功能范围中的主要动作、权限边界、状态变化、失败路径和不可做事项。
- P0 FR 的验收标准应能驱动 UI、状态机、数据、API、权限和 QA 的后续闭环设计。
- P0 范围应严格服务最小主路径；复制、重跑、回退、复杂恢复、完整版本历史等能力若不阻塞主流程，应优先标为 P1/P2 或拆出增强 FR。
- 入口型 FR 要区分“入口展示”和“业务写操作”；入口可以跳转或筛选，但不应绕过模式工作区执行写操作。
- 长任务 FR 必须明确运行态、等待态、失败态、取消/重试结果和并发边界。
- AI Agent FR 必须明确人工确认点、失败原子性、引用可追溯性和生成内容覆盖规则。
- 只读查询能力和写入维护能力应拆开表达，避免基础层查阅入口和构建模式维护入口发生设计冲突。
- P1/P2 能力可以出现在功能范围中，但验收标准必须明确其不阻塞 MVP 主路径。
- 追踪矩阵不是文档装饰：P0 FR 必须能映射到 UI、状态/流程、数据、API、权限和 QA，否则仍不是可开发闭环。
- 验收标准需要进一步转译为 Given/When/Then 测试，尤其覆盖失败路径、权限拒绝、并发竞争、幂等重复提交和不可做事项。
- `FR-WORKSPACE-003` 的上下文恢复应持续保持 P0/P1 分层，避免把滚动位置、日志位置和复杂右侧面板状态误纳入 MVP 必需能力。
- `FR-024` 应保持 P1 输出倾向设置定位，不应阻塞 `FR-023` 的 Graph-RAG 对话主流程。
- `FR-004 / FR-013 / FR-022` 应持续保持“通知偏好 / 自动调度 / 邮件发送”三层边界。
- `FR-WORKSPACE-009 / FR-029` 应持续保持“导出中心 / 综述可导出版本生成”分层表达。
- `FR-031` 承接 P2 版本管理增强，`FR-030` 承接 P0 最小追溯；后续其他设计层需要同步该编号与边界。
- 当前阶段只审查 FR 设计内部闭环；UI、状态、数据、API、权限和 QA 的外部追踪矩阵后续再补。
