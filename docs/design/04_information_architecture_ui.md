## 1. 设计目标

本版 UI 设计围绕以下事实展开：

- 登录后先进入系统级页面，而不是直接进入某个 Agent 模式。
- `Project` 是长期研究容器；构建、深度研究、主题综述都在同一个 `Project Workspace` 内切换。
- `Construction Run`、`Research Session`、`Review Session` 都是可继续、可恢复、可审计的实例。
- `Project` 信息和 `Session` 信息必须分层展示。
- 知识库版本、导出、自动构建、人工修改保护、并发锁提示都必须在 UI 上有明确落点。

本文件覆盖：

- 系统级页面与导航
- Project Workspace 总体框架
- 构建、深研、综述三类工作台
- 论文库、图谱、知识库版本、导出、观点广场、配置中心
- 关键弹窗、空态、错误态、锁定态、响应式与可访问性约束

## 2. 页面清单与推荐路由

旧稿中的以下路由视为过时：

- `/projects/:projectId`
- `/projects/:projectId/dialogue`
- `/projects/:projectId/review`

推荐改为以单一 Workspace Shell 为中心：

| 页面编号 | 页面名称 | 推荐路由 | 说明 |
| --- | --- | --- | --- |
| P01 | 登录 / 注册 | `/login` | 未登录入口 |
| P02 | Project Hub | `/projects` | 登录后首页，管理与进入 Project |
| P03 | 观点广场 | `/plaza` | 系统级独立页面 |
| P04 | 个人设置 / 账户 | `/settings/profile` | 个人资料与安全 |
| P05 | 个人设置 / LLM 配置 | `/settings/llm` | 用户 LLM provider 与模型配置 |
| P06 | 个人设置 / 数据源配置 | `/settings/sources` | 用户论文数据库 API 配置 |
| P07 | 个人设置 / 通知配置 | `/settings/notifications` | 收件邮箱与通知偏好 |
| P08 | 管理员 / 用户管理 | `/admin/users` | 仅管理员可见 |
| P09 | 管理员 / 系统配置 | `/admin/system` | 默认 LLM、默认数据源、SMTP、安全 |
| P10 | 健康检查 | `/settings/health` | 诊断页，管理员优先可见 |
| P11 | Project Workspace | `/projects/:projectId/workspace` | 单一 Project 研究工作台 |

Workspace 内部状态不建议再拆成模式级独立页面，改用查询参数或内部状态表达：

- `?mode=construction&instance=cr_001`
- `?mode=research&instance=rs_023`
- `?mode=review&instance=rv_008`
- `?panel=paper:paper_19`
- `?panel=graph`
- `?panel=export`

这样可以满足：

- 工作台切换不销毁上下文
- 可深链到具体实例、具体论文、具体图谱面板
- 浏览器返回行为与 UI 状态一致

## 3. 全局信息架构

### 3.1 一级导航

登录后，系统始终保留以下一级入口：

- `Projects`
- `观点广场`
- `个人设置`
- `管理员设置`（仅管理员）
- `健康检查`

在 Workspace 内，这些入口不需要占据大面积空间，但必须可被“一步打开”，例如：

- Topbar 中的全局菜单
- 左上角系统抽屉
- 键盘快捷入口

### 3.2 二级导航

二级导航根据所处上下文变化：

| 上下文 | 二级导航 |
| --- | --- |
| Project Hub | 全部 / 我创建的 / 最近访问 / 已归档 |
| 设置中心 | Profile / LLM / Sources / Notifications |
| 管理员中心 | Users / System / SMTP / Security / Health |
| Workspace | Construction / Research / Review |

### 3.3 Workspace 信息分层

Workspace 采用四层结构，而不是旧稿的“模式专属页面”：

1. `Project 选择层`：当前 Project 与快捷切换
2. `Agent 实例层`：当前模式下的 Run/Session 列表
3. `主体工作台层`：当前实例的主要流程或内容
4. `信息面板层`：
   - Project 信息面板：论文库、图谱、Knowledge Version、自动构建
   - Session 信息面板：状态、日志摘要、引用、章节、错误、导出

## 5. 关键交互原则

### 5.1 模式切换不是模式跳转

- 切换 `Construction / Research / Review` 只切换当前工作台上下文。
- 切换时不销毁已有实例。
- 切换后默认恢复该模式最近使用的实例。
- 无可用知识库版本时，`Research / Review` 入口展示为禁用态并说明原因。

### 5.2 写操作只能在主体工作台内触发

以下区域只读：

- Project 论文库
- 论文详情
- Graph
- Knowledge Version 面板

以下操作必须在对应工作台中执行：

- 启动构建
- 确认检索词
- 重新检索 / 重跑 / 增量构建
- 深研发问与总结
- 综述大纲确认、章节撰写、终审与导出

### 5.3 人工修改保护必须可见

所有可被 Agent 二次写入的内容都要有明确状态徽标：

- `Agent Draft`
- `Human Confirmed`
- `Human Edited`
- `Refresh Required`
- `Version Locked`

### 5.4 并发冲突必须前置提示

必须显式提示的冲突包括：

- 同一 Project 已有 active `Construction Run`
- 同一 `Research Session` 已有流式回复进行中
- 同一 `Review Session` 的同一章节正在生成或审查
- 当前实例依赖旧版知识库，但存在新默认版本可刷新

目标：满足 `FR-001`，不暴露尚未实现的密码找回入口。

```

│ Research Paper Base                                         │
│                                                              │
│  ┌──────────────────────────────────────────────────────┐    │
│  │ [登录] [注册]                                        │    │
```

### 7.1 Project Rail

功能：

- 搜索并切换 Project
- 最近访问 Project
- 创建 Project
- 当前 Project 高亮

默认宽度窄，可折叠为图标栏。

### 7.2 Mode / Instance Rail

上半区为模式分段控件：

- `Construction`
- `Research`
- `Review`

下半区为实例列表：

- 当前模式下最近实例
- 状态标签：`idle / running / waiting / failed / archived`

主体区顶部固定展示：

- 当前 Project 名称

- 模式级主操作按钮

### 7.4 Info Panels

右侧始终是两段式，不混合：

1. `Project Panel`
2. `Session Panel`

通过 Tab 或上下折叠区切换。

## 8. Project Panel 设计

Project Panel 是只读资产视图 + 配置入口，不直接发起 Agent 写操作。

包含四个 Tab：

| Tab | 内容 |
| --- | --- |
| `Papers` | 论文库列表、筛选、论文详情入口、PDF 入口 |
| `Graph` | 知识图谱浏览器、节点检索、关联论文跳转 |
| `Versions` | Knowledge Version 列表、默认版本、依赖关系摘要 |
| `Automation` | 自动构建与推送设置、执行历史摘要 |

### 8.1 Papers

```
Project Panel / Papers
- valid papers / total / unread push count
- search
- filters: status / source / year / pushed
- row: title, score, source, year, push state
- click row -> paper detail drawer
```

### 8.2 Graph

```
Project Panel / Graph
- node/edge counts
- filters: paper / concept / author / method
- search node
- graph canvas
- click node -> related papers list
```

注意：不提供“重建图谱”按钮。

### 8.3 Versions

展示：

- 默认版本
- 历史版本列表
- 每个版本的论文数、构建时间、来源 run
- 哪些 Session 正在依赖该版本
- 是否允许刷新非 active Session

### 8.4 Automation

展示：

- 自动构建开关
- 计划周期
- 启用的检索词版本
- 启用的数据源范围
- 最近一次自动运行结果
- 最近一次推送结果

编辑方式：

- 使用右侧表单抽屉或弹窗
- 保存前展示影响范围

## 9. Session Panel 设计

Session Panel 随模式变化，但结构统一：

| 区块 | Construction | Research | Review |
| --- | --- | --- | --- |
| Summary | 当前阶段、进度、错误 | 当前流式状态、轮次、总结状态 | 当前章节、终审状态、导出状态 |
| Version | 当前 run 产出版本预期 | 当前 session 绑定版本 | 当前 session 绑定版本 |
| References | 检索词版本、数据源快照 | 当前回复引用论文/文段 | 当前章节或全文引用覆盖 |
| Logs | 阶段日志摘要 | 轮次生成日志摘要 | 章节 / 导出任务日志摘要 |
| Actions | 暂停/恢复/取消/重试 | 中断生成/刷新依赖/导出 | 暂停任务/重试章节/导出 |

## 10. Construction Run 工作台

目标：满足 `FR-015~FR-022`，同时遵守 `FR-WORKSPACE-*`。

## P12 · Construction Workbench

```
┌────────────────────────────────────────────────────────────────────────────┐
│ Construction Run: CR-2026-05-01-01                                       │
│ Knowledge output: Pending new version                                     │
│ [继续] [暂停] [取消] [重跑] [复制新建]                                   │
├────────────────────────────────────────────────────────────────────────────┤
│ Stage Stepper:                                                            │
│ 1 检索词确认 -> 2 多源检索 -> 3 去重评分 -> 4 下载解析 ->                │
│ 5 AI 分析 -> 6 入库建图 -> 7 邮件推送                                     │
├────────────────────────────────────────────────────────────────────────────┤
│ Stage Content                                                             │
└────────────────────────────────────────────────────────────────────────────┘
```

### 10.1 阶段 1：检索词确认

主体区：

- Project 主题摘要
- Agent 生成的检索词卡片
- 每个检索词的解释
- 数据源范围预览
- 启用/禁用切换
- 手动添加 / 编辑 / 删除

操作：

- `重新生成`
- `保存草稿`
- `确认并开始检索`

不提供：

- `跳过`

### 10.2 阶段 2：多源检索

主体区：

- 各数据源状态表
- 候选论文数
- 去重进度
- 最近错误
- 可暂停但不可编辑检索词

### 10.3 阶段 3：去重、评分与筛选

主体区：

- 候选论文表格
- 评分维度列
- 有效/无效判定
- 批量选择
- 单篇详情抽屉
- 阈值调节

操作：

- `应用阈值`
- `手动调整`
- `确认有效论文集`

### 10.4 阶段 4：补充论文与下载解析

考虑 `FR-018` 和 `FR-019`，UI 合并成一个阶段工作面：

- 上半区：自动下载与解析进度
- 下半区：手动补充入口
  - PDF 上传
  - DOI
  - arXiv ID
  - URL

失败项必须单列展示：

- 下载失败
- PDF 不可读
- 降级为摘要解析

### 10.5 阶段 5：AI 分析生成

每篇论文生成以下结果预览：

- 一句话总结
- 亮点
- 相关性要点
- 方法与创新

支持：

- 单篇重试
- 批量重试失败项

### 10.6 阶段 6：入库与图谱构建

主体区：

- 待入库统计
- 已入库统计
- 新论文 / 已存在论文 / 跳过论文
- 向量化进度
- 图谱构建进度
- 预期新 `Knowledge Version`

完成后必须明确显示：

- 新默认版本是否已经发布
- 是否有旧版本 active Session 仍在运行

### 10.7 阶段 7：邮件推送

主体区：

- 收件人列表
- 本次待推送论文数
- 推送内容粒度
- 邮件发送结果
- 失败项列表

操作：

- `发送`
- `重发失败项`

## 14. 空态、错误态、等待态

每个系统级页面和 Workspace 都必须有一致的状态模板。

### 14.1 空态

| 场景 | 空态主文案 | 主操作 |
| --- | --- | --- |
| 无 Project | 还没有研究课题 | 创建 Project |
| 无 Knowledge Version | 需要先完成至少一次构建 | 新建 Construction Run |
| 无 Research Session | 还没有研究会话 | 新建 Research Session |
| 无 Review Session | 还没有综述会话 | 新建 Review Session |
| 无观点 | 还没有公开观点 | 发布观点 |

### 14.2 错误态

错误区必须包含：

- 简短错误标题
- 可诊断摘要
- 重试入口
- 查看日志摘要入口

### 14.3 等待态

等待态不得只显示转圈，必须同时显示：

- 当前阶段 / 当前任务名称
- 已完成数量 / 总数量
- 最近完成时间点或最近事件

## 15. 响应式规则

### 15.1 Desktop `>= 1440px`

- 四栏完整展示
- `Project Rail` 默认展开
- `Info Panels` 右侧常驻

### 15.2 Laptop `1024px ~ 1439px`

- `Project Rail` 默认折叠
- `Info Panels` 保留 Tab，不同时展开两块

### 15.3 Tablet / Small Desktop `< 1024px`

- `Project Rail` 收纳到左侧抽屉
- `Mode / Instance Rail` 收纳为顶部二级抽屉
- `Info Panels` 改为右侧抽屉或底部面板

### 15.4 Mobile

移动端不建议承担重度编辑，但必须可完成：

- 查看 Project
- 查看论文详情
- 查看深研对话
- 审阅综述章节
- 触发简单操作

复杂表格和图谱采用：

- 全屏抽屉
- 分步筛选
- 只读优先

## 16. 可访问性与视觉约束

- 所有状态颜色必须配合文字，不允许只靠颜色区分。
- Stepper、Tab、分段控件、对话流、表格行都必须支持键盘聚焦。
- 流式回复和阶段进度需要可读的屏幕阅读器文本。
- 对话引用、论文标题、版本号必须是可复制文本，不做纯图形化处理。
- 图谱节点悬停时必须提供文字摘要。
- 禁用态按钮要说明原因，尤其是 `Research / Review` 入口禁用时。

## 17. 本版设计对旧稿的替换结论

旧稿中的以下设计被正式废弃：

- 三模式使用独立主页面作为长期容器
- Workspace 内直接出现“跳过阶段”
- 深度研究图谱页提供“重建图谱”
- 模式切换时以“退出当前模式”思路设计
- 用旧的项目状态表达实例状态

本版正式采用：

- 系统级页面与 Workspace 分层
- 单一 Workspace Shell
- `Project + Run/Session + Knowledge Version` 结构
- `Project Panel` 与 `Session Panel` 双信息面板
- 实例化 Agent 工作台，而不是“Project 当前模式”
