## 1. 引言

### 1.1 编写目的

本文档旨在详细描述 Research Paper Base 系统的功能需求、非功能需求和约束条件，为系统设计、开发、测试和验收提供依据。

### 1.2 项目背景

学术研究人员需要定期跟踪相关领域的最新论文，并实时查询论文中的相关内容，但手动检索、筛选、下载和分析论文的过程耗时耗力。本系统旨在通过 AI Agent 自动化这一流程，实现课题组级的论文BASE库构建，提供论文的检索、下载、解析、互动问答、自动推送、综述生成等功能，成为科研人员安全、可靠、有用的学术论文信息平台。

## 2. 项目概述

### 2.1 产品目标

构建一个基于可供课题组级人员共享，以课题为主体的AI Agent的三模式学术论文研究系统。

**核心设计原则**：
- 支持小组级科研人员使用和论文库共享、观点分享和帐号管理
- 以研究主题（Project）为基础单元进行设计Agent互动模式，分为三套模式：构建模式、深度研究模式、主题综述模式
- **模式互斥性**：对于每个研究主题，同一时间只能处于一种模式，且必须处于其中一种模式
- **模式扩展性**：系统架构设计预留扩展性，支持未来扩展为更多模式，无需对核心架构进行重大改造

**基础层设计（独立于三模式）**：
- 用户和用户信息管理：用户注册、登录、权限管理等，全局通用
- 用户配置管理：用户信息维护、LLM模型连接配置维护、论文数据库API配置维护等，全局通用
- 管理员配置管理：首位注册用户自动成为管理员，管理员可配置发送邮箱、系统级默认模型、系统级默认论文库API，并管理其他用户账号
- 界面管理：独立于Agent模式，可随时进行信息面板的打开和关闭
  - 课题选择栏：（建议位于左侧上边栏，可以通过点击展开或折叠）显示用户的所有课题
  - Agent状态栏：（建议位于左侧下边栏，可以通过点击展开或折叠）显示当前Agent模式的运行状态信息
  - 数据库：（建议位于右侧）显示当前所选课题的可视化论文数据库
  - 观点广场：（建议通过按钮打开新的页面）查看其他用户发表的观点，或者发表观点（禁止讨论，显示发布者的用户名或邮箱以用于私下交流）

---

目前的Agent模式设计包含三种模式：

**构建模式**：
- 用户借助Agent工具结合研究主题自动生成检索词
- 从多个学术数据库检索论文
- 智能评分和筛选相关论文
- 自动下载和解析论文
- 用户可补充论文或手动上传资料
- Agent自动完成解析和后台入库
- 根据论文数据库构建 Graph 知识图谱数据库
- 每日0时自动在后台运行检索-评估-下载-解析-入库的全流程，并根据课题关联将新的论文自动发送邮件推送给用户
- 附加功能包含任务管理、分步骤交互、数据导出等功能

**深度研究模式**：
- 基于构建模式已建立的知识图谱进行 Graph-RAG 检索，作为 LLM 的知识库背景
- LLM 基于 Graph-RAG 与用户提供深度理论与技术讨论，除了普通的聊天模式，也内置三种输出倾向：
  - 创新：进行联想，倾向于提出新研究方向的可能
  - 实验：考虑周密的实验方案设计以验证猜想或方向
  - 总结：记录对话探讨历史和结论
- 附加功能包含总结文件生成模块、数据导出等功能

**主题综述模式**：
- 基于构建模式已建立的知识图谱进行 Graph-RAG 检索，作为 LLM 的知识库背景
- 根据用户的课题设计综述文章架构
- 撰写每章内容并引用相关论文
- 自动审查并迭代优化每章内容
- 将每章内容汇总成完整的综述文章
- 支持用户对综述文章进行修改和完善
- 支持导出综述文章为多种格式（Markdown、PDF、Word）
- 提供综述文章的版本管理
- 包含任务管理、分步骤人工交互与修改、数据导出等功能

**模式设计原则**：
1. **互斥性**：每个研究主题在同一时间只能处于构建模式、深度研究模式或主题综述模式中的一种，不能同时处于多种模式
2. **完整性**：每个研究主题必须处于一种模式中，不能处于"无模式"状态
3. **可切换性**：用户可以在三种模式之间自由切换，系统会保存当前模式的状态，切换后自动初始化新模式的上下文
4. **扩展性**：系统架构采用枚举类型设计模式，预留扩展性，支持未来添加新的Agent模式

### 2.2 用户特征

| 用户类型 | 特征 | 主要需求 |
|---------|------|---------|
| 学术研究人员 | 需要跟踪最新研究进展 | 自动化、准确性、可定制 |
| 研究生 | 需要收集相关文献，学习新技术 | 易用性、全面性 |
| 科研团队 | 需要共享检索结果，协作研究 | 多用户支持、数据共享 |
| 系统管理员 | 负责系统部署和维护，通常是团队负责人 | 统一配置管理、用户账号管控 |

### 3.3 基础层功能需求

#### FR-001 用户账号与认证

**需求描述：**
系统应支持多用户注册、登录、登出和账号状态管理，为 Project 数据隔离和管理员权限提供基础。

**功能范围：**
- 用户使用用户名、邮箱和密码注册账号。
- 用户可使用用户名或邮箱登录。
- 用户可登出当前会话。
- 用户可查看和修改自己的基础信息。
- 系统应识别账号启用/禁用状态，禁用账号不得继续登录。
- 首位注册用户自动成为管理员，具体治理能力见 `FR-005`。
- 密码找回属于 P1 支撑能力，应在 API 和邮件设计确认后实现。
- 用户信息必须长久留存，只有管理员用户有权限对其他用户的信息进行修改。

**验收标准：**
- 新用户可成功注册并登录。
- 用户可使用用户名或邮箱登录，并可正常登出当前会话。
- 用户可查看和修改自己的基础信息，修改后再次读取结果一致。
- 错误凭证登录失败，并返回明确错误提示。
- 密码不得默认明文存储或明文返回，但可通过显示按钮切换成明文。
- 禁用账号不能继续登录。
- 首位注册用户应获得管理员身份。
- 密码找回未实现前，不得在 UI 或 API 中暴露不可用入口；实现后应通过邮件或等效安全流程完成验证。

#### FR-002 用户 LLM 配置管理

**需求描述：**
用户应能配置个人 LLM 连接，用于构建、深度研究和综述模式中的 Agent 调用。

**功能范围：**
- 支持配置多种 provider 的 base URL、API key 和基础参数。支持的 provider 应当包含 OpenAI、Anthropic、Gemini、deepseek 以及自定义 provider。
- 支持测试连接、刷新并显示当前 provider 的可用模型列表。
- 用户应当能够同时使用个人配置或系统配置；具体解析规则见 `FR-007`。
- 支持多个 provider，并在系统的可选模型列表中同时列出所有个人配置和系统配置中连接成功的可用模型的配置来源和模型名称。
- 支持在主页面通过系统的可选模型列表更改当前的 Agent 调用连接模型。
- 用户配置必须可保存和复用。
- 支持重新登录后自动选择用户上次选择过的模型

**验收标准：**
- 用户可新增、查看、修改、删除个人 LLM 配置。
- 用户可维护多个 provider，并可测试任意 provider 的连接以及查看其可用模型列表。
- 用户可测试连接并刷新可用模型列表，结果能区分成功和失败，若失败需给出失败原因。
- API key 存储和展示必须脱敏。
- Agent 任务能根据用户当前选择的选项来配置模型；配置需正确，不应与用户选择的配置来源和模型相违背；未选择时应当默认选择 [empty] 并提示用户进行模型选择。
- 用户配置变更不得修改系统级默认配置。
- 用户重新登录时能够自动恢复上次退出会话时的模型选择。

#### FR-003 用户论文数据库 API 配置管理

**需求描述：**
用户应能配置个人学术数据库 API，以控制构建模式使用的数据源和访问参数。

**功能范围：**
- 支持 arXiv、OpenAlex、Semantic Scholar、ADS。
- 支持启用/禁用数据源、API key、端点、速率限制配置。
- 支持连接测试和状态展示。
- 用户可以选择使用个人数据源配置或系统默认数据源配置；具体解析规则见 `FR-007`。

**验收标准：**
- 用户可新增、查看、修改、删除个人数据源配置。
- 用户可启用或禁用 arXiv、OpenAlex、Semantic Scholar、ADS 中的任一数据源。
- API key、端点和速率限制保存后能被再次读取和脱敏展示。
- 连接测试能返回成功、失败和失败原因。
- 数据源连接失败时应给出可诊断提示。
- 构建模式只使用已启用且运行时可解析的数据源。
- 用户配置变更不得修改系统级默认数据源配置。

#### FR-004 用户邮件与通知配置

**需求描述：**
用户应能维护个人收件人和通知偏好，用于接收新论文推送、测试邮件和必要通知。

**功能范围：**
- 用户可维护一个或多个收件邮箱。
- 用户可配置是否接收构建完成、推送失败、自动任务失败等通知。
- 用户可发送测试邮件验证收件配置。
- 系统发件 SMTP 配置由管理员维护，普通用户不维护发件账号。
- 邮件模板自定义属于 P2 扩展能力。

**验收标准：**
- 用户可保存并查看自己的收件人列表和通知偏好。
- 用户可维护多个收件邮箱，并能删除无效或不需要的收件人。
- 构建完成、推送失败、自动任务失败等通知开关保存后生效。
- 测试邮件使用系统发件配置发送到用户收件人。
- 普通用户无法查看或修改系统 SMTP 密钥。
- 邮件模板自定义未实现前，不得作为 P0/P1 阻塞项。

#### FR-005 管理员账号管理

**需求描述：**
基础层应提供管理员账号治理能力，允许管理员维护用户账号状态和管理员权限，同时确保系统不会丢失最后管理员。

**功能范围：**
- 首位注册用户自动成为管理员。
- 管理员可查看用户列表和用户基础状态。
- 管理员可启用、禁用或删除普通用户账号。
- 管理员可重置用户密码或触发密码重置流程。
- 管理员可授予或撤销其他用户的管理员权限。
- 系统至少保留一个启用状态的管理员账号。

**验收标准：**
- 非管理员不能访问用户管理入口和接口。
- 首位注册用户自动成为管理员。
- 管理员可查看用户列表和用户基础状态。
- 管理员可启用、禁用或删除普通用户账号。
- 管理员可重置用户密码或触发密码重置流程。
- 管理员可授予或撤销其他用户管理员权限。
- 管理员不能禁用、删除或撤销自己的最后管理员身份。
- 被禁用用户不能继续访问受保护资源。
- 管理员账号操作应可审计。

#### FR-006 管理员系统级配置管理

**需求描述：**
基础层应提供管理员系统级配置管理能力，用于维护普通用户未配置个人参数时的回落配置和平台运行基础。

**功能范围：**
- 管理员可维护系统级默认 LLM 配置。
- 管理员可维护系统级论文数据库 API 配置。
- 管理员可维护系统发件邮箱和 SMTP 配置。
- 管理员可维护系统安全配置、速率限制、默认阈值或全局开关。
- 管理员可测试系统级配置连接状态。
- 系统级密钥应脱敏展示，并按安全设计加密存储。

**验收标准：**
- 非管理员不能访问系统级配置入口和接口。
- 管理员可维护系统级默认 LLM、论文数据库 API、SMTP、安全配置、速率限制、默认阈值和全局开关。
- 管理员可测试系统级 LLM、数据源和 SMTP 配置连接状态。
- 系统级配置变更不得覆盖用户个人配置。
- 系统级密钥不得明文返回前端或日志。
- 配置变更应记录操作者、时间、配置类型和结果。

#### FR-007 用户配置与系统配置解析规则

**需求描述：**
系统应明确用户配置与管理员系统级配置之间的运行时解析、回落、覆盖和限制关系，避免构建、深度研究、综述和邮件推送在不同模块中使用不一致的配置来源。

**功能范围：**
- LLM、论文数据库 API、邮件发送、安全阈值和速率限制都必须定义运行时配置来源。
- 用户个人配置优先于系统默认配置；用户缺失配置时才回落系统默认配置。
- 系统级配置不得覆盖用户已保存的个人配置，但可以提供硬限制，例如允许的数据源范围、最大并发、速率上限和模型白名单。
- 邮件配置采用组合策略：用户收件人和通知偏好来自用户配置，SMTP 发件能力来自系统级配置。
- 密钥类配置必须按所有权隔离：用户密钥只能由该用户任务使用，系统密钥可作为回落配置但普通用户不可读取明文。
- 系统应能在任务启动前生成一次解析后的配置快照，用于诊断、审计和任务复现。

**验收标准：**
- 任一 Agent 任务启动前能明确解析出实际使用的 LLM、数据源、邮件和限制配置。
- 用户缺失个人配置时能使用系统默认配置继续执行。
- 用户已有个人配置时，系统默认配置变更不应静默改变该用户任务的配置来源。
- 系统级硬限制能限制用户配置的可用范围，例如模型白名单、数据源范围、速率上限或最大并发。
- 邮件运行时配置能组合用户收件人与系统 SMTP 发件能力。
- 普通用户不能通过配置解析结果读取系统密钥明文。
- 任务启动时应生成配置快照，并可用于诊断、审计和任务复现。
- 配置解析失败时，任务不得启动，并应返回缺失项和修复建议。

#### FR-008 Project 管理与模式切换

**需求描述：**
系统应以 Project 为核心业务单元，支持用户创建、选择、维护 Project，并在构建、深度研究、主题综述三种模式间安全切换。

**功能范围：**
- 用户可创建、查看、更新、删除或归档自己的 Project。
- 用户可在全局课题选择栏切换当前 Project。
- 每个 Project 必须且只能处于一种 Agent 模式。
- 切换到深度研究或综述模式前，Project 必须已有有效论文库。
- 有运行中任务时，模式切换必须先提示用户等待、暂停或取消任务。
- 模式切换不得删除构建历史、对话历史或综述草稿。

**验收标准：**
- 用户可创建、查看、更新、删除或归档自己的 Project。
- 用户只能访问自己的 Project。
- 每个 Project 任一时刻只能处于一种 Agent 模式。
- `valid_papers = 0` 时不能进入深度研究或综述模式。
- 运行中任务未处理前不得静默切换模式。
- 用户在全局课题选择栏切换 Project 后，页面和侧栏数据应同步到目标 Project。
- 切换模式后能恢复目标模式已有上下文。
- 删除或归档 Project 不得破坏其他 Project 的构建历史、对话历史或综述草稿。

#### FR-009 全局左右侧栏与入口管理

**需求描述：**
系统应提供独立于三种 Agent 模式的全局左右侧栏管理能力。左侧任务侧栏用于 Project 选择、Project 摘要、Agent 模式选择和模式状态；右侧数据侧栏用于打开论文库、Graph 图谱、导出入口和当前模式上下文入口。

**功能范围：**
- 左侧任务侧栏展示用户可访问的 Project，并支持选择、展开/折叠和查看当前 Project 摘要。
- 左侧任务侧栏展示三种 Agent 模式入口、当前启用模式、模式运行状态、阶段、等待确认项和错误提示。
- 左侧任务侧栏中的模式切换必须遵守 FR-008 的有效论文、运行任务和上下文恢复规则。
- 右侧数据侧栏展示论文库入口、Graph 图谱入口、导出入口和当前模式上下文入口。
- 论文库、Graph 图谱、导出入口和模式上下文均绑定当前 Project，不展示其他 Project 数据。
- 右侧数据侧栏中的论文库和 Graph 图谱是基础层全局入口，任意模式下均可打开。
- 右侧数据侧栏中的模式上下文入口应按当前 Agent 模式展示用户可理解的上下文摘要：构建模式展示检索结果、论文处理状态和入库/图谱更新状态；深度研究模式展示当前对话引用、文段来源和 Graph-RAG 命中来源；主题综述模式展示章节引用覆盖、引用段落和参考文献状态。
- 右侧数据侧栏只负责展示、跳转、筛选和打开上下文，不直接执行上传、删除、重建、重试、生成或导出等写操作；写操作必须回到对应模式工作区或明确的导出确认流程。
- 观点广场作为独立页面或全局入口打开。
- 面板展开、关闭、切换和跳转不应破坏当前 Agent 运行上下文。

**验收标准：**
- 任意模式下均可查看当前 Project 和 Agent 状态。
- 状态栏能区分空闲、运行中、等待确认、失败等状态。
- 用户能明确区分左侧任务侧栏和右侧数据侧栏的职责。
- 左侧任务侧栏能展示 Project 列表、当前 Project 摘要、三种 Agent 模式入口、当前启用模式、阶段、等待确认项和错误提示。
- 任意模式下均可通过右侧数据侧栏打开当前 Project 的论文库和 Graph 图谱。
- 右侧数据侧栏能展示论文库、Graph、导出和当前模式上下文入口。
- 切换 Agent 模式后，右侧数据侧栏的模式上下文摘要应切换为目标模式对应内容。
- 打开和关闭论文库、Graph 图谱、导出入口或模式上下文面板不触发模式切换或任务中断。
- 右侧数据侧栏不得提供绕过模式流程的写操作入口。

#### FR-010 Project 论文库与图谱只读查阅

**需求描述：**
用户应能在基础层通过右侧数据侧栏随时只读查阅当前 Project 的论文库、论文详情、PDF 访问入口和 Graph 关系图谱。论文上传、移除、重下载、重解析、重评分、重分析和图谱更新属于构建模式能力，不在基础层查阅入口执行。

**功能范围：**
- 展示论文统计、列表、详情、评分、有效性、推送状态和 AI 分析。
- 支持标题、摘要、作者、来源、评分、有效性、推送状态、引用状态等筛选。
- 展示论文 PDF 本地或远程访问入口；远程访问必须经过鉴权或签名 URL，不允许暴露无权限文件地址。
- 展示当前 Project 的 Graph 关系图谱，包括论文、作者、关键词、概念、方法等节点和关系边。
- 支持从论文详情跳转到 Graph 图谱节点，也支持从 Graph 节点跳转回论文详情。
- 根据当前模式展示上下文信息：构建模式展示检索结果、论文状态、下载解析、AI 分析、入库和图谱更新摘要；深度研究模式展示对话引用来源、引用文段和 Graph-RAG 命中来源；主题综述模式展示章节引用覆盖、引用段落、未覆盖章节和参考文献状态。
- 模式上下文摘要支持跳转到对应论文详情、PDF/远程访问入口、Graph 节点、构建阶段、对话轮次或综述章节。
- 基础层只提供查阅、跳转、筛选、下载/打开，不提供修改论文库或重建图谱的动作。

**验收标准：**
- 论文库和 Graph 图谱只展示当前 Project 数据。
- 用户可查看论文统计、列表、详情、评分、有效性、推送状态和 AI 分析。
- 用户可按标题、摘要、作者、来源、评分、有效性、推送状态、引用状态筛选论文。
- 用户可从论文详情打开有权限访问的 PDF 或远程文件。
- 用户可在论文详情与 Graph 节点之间互相跳转。
- 用户可从右侧数据侧栏的模式上下文摘要跳转到对应只读详情或对应模式工作区。
- 模式上下文能分别展示构建、深度研究、主题综述对应的摘要信息。
- 深度研究和主题综述模式下，基础层论文库与图谱保持只读。
- 基础层查阅入口不提供上传、移除、删除、重新下载、重新解析、重新评分、重新分析、入库或图谱重建操作。

#### FR-011 任务与 Agent 状态管理

**需求描述：**
用户应能查看和控制当前 Project 的 Agent 任务状态，避免长任务不可见、不可取消或不可恢复。

**功能范围：**
- 展示构建和综述任务的当前阶段、运行状态、开始时间、错误信息和阶段结果。
- 支持对可控任务执行暂停、恢复、取消、重试。
- 支持查看历史阶段记录和任务日志摘要。
- 深度研究对话不作为 Project 运行中任务，但应展示当前流式回复状态。

**验收标准：**
- 任务状态变化能及时反映到界面。
- 用户可查看构建和综述任务的当前阶段、运行状态、开始时间、错误信息和阶段结果。
- 可控任务支持暂停、恢复、取消和重试，并能给出明确结果。
- 取消或重试操作应有明确结果，不产生重复运行的隐性任务。
- 用户可查看历史阶段记录和任务日志摘要。
- 深度研究流式回复状态可见，但不把普通对话标记为 Project 运行中任务。
- 失败任务应展示可诊断错误和下一步建议。

#### FR-012 Project 数据导出

**需求描述：**
用户应能导出当前 Project 的关键研究资产，用于本地备份、汇报和论文写作。

**功能范围：**
- 导出论文库结构化数据。
- 导出已下载 PDF 集合。
- 导出深度研究对话或总结文件。
- 导出综述文章产物。
- 导出应支持筛选条件和导出统计。

**验收标准：**
- 导出内容只包含用户有权限访问的数据。
- 用户可导出论文库结构化数据、已下载 PDF 集合、深度研究对话或总结文件、综述文章产物。
- 用户可设置导出筛选条件，并在导出前查看导出统计。
- 大文件导出不应阻塞用户继续使用系统。
- 缺失文件应记录为跳过项，不导致整体导出失败。
- 导出完成后用户能获取文件或失败报告。

#### FR-013 定时自动构建与推送

**需求描述：**
系统应支持以 Project 为单位配置周期性自动构建任务，在无人值守情况下更新论文库并推送新有效论文。

**功能范围：**
- 用户可启用/禁用 Project 自动任务。
- 用户可配置执行间隔或计划时间。
- 自动任务使用 Project 已保存并已确认的检索词和运行时配置快照。
- 自动任务执行构建模式全流程，并使用自动确认策略跳过人工等待。
- Project 已有运行中任务时，应跳过本次调度或延后执行。
- 自动任务完成后触发邮件推送。

**验收标准：**
- 用户可按 Project 启用或禁用自动任务，并配置执行间隔或计划时间。
- 自动任务使用 Project 已保存并已确认的检索词和任务启动时配置快照。
- 自动任务能执行构建模式全流程，并按自动确认策略处理人工等待点。
- 不同 Project 的调度互不影响。
- 自动任务不会在同一 Project 上并发重复运行。
- 任务完成后能更新上次执行和下次执行信息。
- 自动任务完成后能触发邮件推送。
- 自动执行失败时能记录错误并通知用户查看。

#### FR-014 观点广场

**需求描述：**
系统应允许用户单向发布研究观点、结论或实验思路，供其他用户参考，但不提供站内讨论能力。

**功能范围：**
- 用户可发布、查看、搜索和筛选观点。
- 观点可包含类型、标题、正文、标签和联系信息。
- 联系信息仅允许用户名或邮箱。
- 支持查看次数和点赞属于 P2 能力。
- 禁止评论、回复、讨论串和实时聊天。

**验收标准：**
- 用户可发布、查看、搜索和筛选观点。
- 用户可发布和删除自己的观点。
- 观点可保存类型、标题、正文、标签和联系信息。
- 其他用户只能查看公开观点。
- 系统不提供任何评论或回复入口。
- 联系信息不得展示用户名/邮箱以外的私密联系方式。
- 查看次数和点赞未实现前，不得阻塞观点发布、查看、搜索和删除。

### 3.4 构建模式功能需求

#### FR-015 检索词生成

**需求描述：**
构建模式应根据 Project 主题生成可解释、可编辑、可复用的检索词集合，为多源论文检索提供输入。

**功能范围：**
- Agent 基于 Project 名称、描述、研究范围和用户补充要求生成检索词。
- 检索词应包含自然语言关键词、布尔表达式、同义词/缩写和排除词建议。
- 系统应展示每组检索词的生成理由、预期覆盖方向和适用数据源。
- 用户可审查、编辑、启用、禁用、删除或新增检索词。
- 右侧数据侧栏的构建模式上下文应展示当前检索词版本、待确认状态和将用于检索的数据源范围。
- 用户确认后，检索词版本应保存到 Project，用于手动构建和定时自动构建。

**验收标准：**
- 检索词生成结果可被用户查看、修改和确认。
- 检索词结果包含自然语言关键词、布尔表达式、同义词/缩写和排除词建议。
- 每组检索词应展示生成理由、预期覆盖方向和适用数据源。
- 用户可启用、禁用、删除或新增检索词。
- 右侧数据侧栏能展示当前检索词版本、待确认状态和将用于检索的数据源范围。
- 未确认检索词时，手动构建不得进入多源检索阶段。
- 检索词确认记录应可追溯到当前 Project。
- 检索词生成失败时，用户可手动输入检索词继续流程。

#### FR-016 多源论文检索

**需求描述：**
构建模式应使用已确认检索词调用多个学术数据库，汇总当前 Project 的候选论文集合。

**功能范围：**
- 支持 arXiv、OpenAlex、Semantic Scholar、ADS 等已启用数据源。
- 系统根据数据源能力转换检索表达式和请求参数。
- 支持配置检索时间范围、返回数量上限和数据源启用状态。
- 单个数据源失败时应记录原因，并允许其他数据源继续。
- 检索完成后展示各数据源命中数量、失败原因、候选列表和下一步操作。
- 右侧数据侧栏的构建模式上下文应展示查询结果摘要，包括各数据源命中数、失败数据源、候选论文数量和可跳转的检索结果分组。
- 用户可确认进入去重评分，也可调整检索词后重新检索。

**验收标准：**
- 检索请求只使用已启用数据源，并能覆盖 arXiv、OpenAlex、Semantic Scholar、ADS。
- 系统能按数据源能力转换检索表达式和请求参数。
- 用户可配置检索时间范围、返回数量上限和数据源启用状态。
- 检索结果包含标题、作者、日期、来源、摘要、外部 ID 或 URL 等基础元数据。
- 数据源失败有明确提示，不应导致已成功数据源结果丢失。
- 检索完成后能展示各数据源命中数量、失败原因、候选列表和下一步操作。
- 右侧数据侧栏能展示查询结果摘要、失败数据源、候选论文数量和可跳转结果分组。
- 用户能区分每篇候选论文来自哪些数据源。
- 用户确认后，候选论文才能进入去重、评分与筛选阶段。

#### FR-017 论文去重、评分与筛选

**需求描述：**
系统应对候选论文进行去重、评分和筛选，形成当前 Project 的有效论文集合。

**功能范围：**
- 基于 DOI、arXiv ID、外部 ID、标准化标题进行去重。
- Agent 根据标题、摘要等信息评估理论价值、技术价值和 Project 相关性。
- 系统根据阈值判断论文是否有效。
- 用户可查看评分理由并手动调整评分、有效性或去重合并结果。
- 用户可触发重新评分或返回检索阶段补充检索词。
- 右侧数据侧栏的构建模式上下文应展示候选、重复、有效、无效、待确认和失败论文数量，并支持跳转到对应筛选结果。

**验收标准：**
- 同一 Project 内不会重复关联同一论文。
- 去重逻辑至少使用 DOI、arXiv ID、外部 ID、标准化标题进行判断。
- 评分结果包含分数、是否有效和理由。
- 用户可查看评分理由并手动调整评分、有效性或去重合并结果。
- 用户可触发重新评分或返回检索阶段补充检索词。
- 右侧数据侧栏能展示候选、重复、有效、无效、待确认和失败论文数量，并支持跳转筛选。
- 用户手动调整后，Project 有效论文统计应同步更新。
- 用户确认筛选结果后，系统才能进入下载解析和后续入库流程。

#### FR-018 论文补充与手动上传

**需求描述：**
用户应能在构建模式中补充系统未检索到但对课题重要的论文或资料。论文上传、补充、移除当前 Project 关联等会改变论文库内容的操作只能在构建模式中执行。

**功能范围：**
- 支持通过 DOI、arXiv ID、URL 添加论文。
- 支持上传 PDF 文件。
- 支持批量上传属于 P1 能力。
- 系统尝试提取元数据并进入去重、解析、分析、入库流程。
- 用户可编辑自动提取的论文元数据并确认是否加入当前 Project。
- 支持从当前 Project 移除论文关联，但不删除全局 `papers` 记录。
- 支持清空当前 Project 的论文关联，操作前必须二次确认。
- 右侧数据侧栏的构建模式上下文应展示手动补充、上传解析、待确认元数据和移除结果摘要。

**验收标准：**
- 用户可通过 DOI、arXiv ID、URL 添加论文，或上传 PDF 文件。
- 批量上传未实现前，不得阻塞单篇补充和单文件上传。
- 系统能提取或要求用户补充元数据，并将补充论文送入去重、解析、分析、入库流程。
- 成功添加的论文会关联到当前 Project。
- 上传或解析失败时应展示失败原因。
- 用户补充论文不得绕过去重和权限检查。
- 用户确认后的补充论文应进入与检索论文一致的后续流程。
- 移除论文关联后其他 Project 不受影响。
- 清空当前 Project 论文关联前必须二次确认。
- 右侧数据侧栏能展示手动补充、上传解析、待确认元数据和移除结果摘要。
- 深度研究、主题综述和基础层只读查阅入口不得执行论文上传或移除操作。

#### FR-019 PDF 下载与文本解析

**需求描述：**
系统应尽量获取论文全文并解析为后续 AI 分析和 RAG 检索可用的文本。

**功能范围：**
- 根据论文元数据尝试自动下载 PDF。
- 解析 PDF 文本，并保存文件路径和解析状态。
- 下载失败或解析失败时记录原因，并使用摘要作为降级文本。
- 用户可对失败论文触发重试，或上传本地 PDF 替代自动下载结果。
- 保存可供基础层查阅使用的 PDF 本地路径、远程访问地址或签名 URL 元数据。
- 下载解析阶段完成后，应展示成功、失败、降级统计供用户确认。
- 右侧数据侧栏的构建模式上下文应展示 PDF 下载、文本解析、失败降级和待重试论文摘要。

**验收标准：**
- 成功下载的论文可查看或下载 PDF。
- 系统能根据论文元数据尝试自动下载 PDF。
- 系统能解析 PDF 文本并保存文件路径和解析状态。
- 下载失败或解析失败时应记录原因，并使用摘要作为降级文本。
- 用户可对失败论文触发重试，或上传本地 PDF 替代自动下载结果。
- 基础层论文详情可打开有权限访问的 PDF 或远程文件入口。
- 下载解析阶段完成后能展示成功、失败、降级统计供用户确认。
- 右侧数据侧栏能展示 PDF 下载、文本解析、失败降级和待重试论文摘要。
- 解析文本可被后续 AI 分析使用。
- 失败论文不会阻断整个构建流程。
- 用户确认下载解析结果后，系统才能进入 AI 分析阶段。

#### FR-020 论文 AI 分析生成

**需求描述：**
系统应对论文文本生成结构化 AI 分析，帮助用户快速判断论文价值。

**功能范围：**
- 生成一句话总结。
- 提取亮点解析。
- 提取与 Project 的相关性要点。
- 提取技术方法与创新点。
- 用户可编辑、确认或重新生成分析。
- 重新生成前应提示是否覆盖用户已保存的手动修改。
- 右侧数据侧栏的构建模式上下文应展示 AI 分析完成、失败、待确认和用户已修改论文摘要。

**验收标准：**
- AI 分析结果可在论文详情中查看。
- AI 分析结果至少包含一句话总结、亮点解析、Project 相关性要点、技术方法与创新点。
- 用户可编辑、确认或重新生成分析结果。
- 重新生成不会丢失用户明确保存的手动修改，除非用户确认覆盖。
- 右侧数据侧栏能展示 AI 分析完成、失败、待确认和用户已修改论文摘要。
- 分析失败应记录状态并允许重试。
- 用户确认后的分析结果才能作为入库和后续综述/深研上下文使用。

#### FR-021 知识库入库与图谱构建

**需求描述：**
系统应将构建模式产出的有效论文写入 Project 知识库，并维护后续 Graph-RAG 所需的向量库和知识图谱。

**功能范围：**
- 将论文元数据、Project 关联、评分、AI 分析和文件路径持久化。
- 将论文文本切分并写入向量检索库。
- 基于论文、作者、关键词、概念、方法等实体构建或增量更新知识图谱。
- 图谱创建、增量更新、重建、修复只能由构建模式触发。
- 入库前向用户展示即将入库的有效论文、跳过项和风险提示。
- 入库过程应支持增量更新和失败回滚/补偿。
- 入库完成后展示入库、向量化、图谱更新结果和失败项。
- 右侧数据侧栏的构建模式上下文应展示入库、向量化、Graph 节点/边更新和失败项摘要，并支持跳转到基础层论文库或 Graph 图谱查看结果。

**验收标准：**
- 系统能持久化论文元数据、Project 关联、评分、AI 分析和文件路径。
- 系统能将论文文本切分并写入向量检索库。
- 系统能基于论文、作者、关键词、概念、方法等实体构建或增量更新知识图谱。
- 入库前用户能看到即将入库的有效论文、跳过项和风险提示。
- 入库成功后，论文可在 Project 论文库中查看。
- 图谱更新成功后，基础层 Graph 图谱可展示最新节点和关系。
- 入库过程支持增量更新，并在失败时能回滚或补偿。
- 深度研究和综述模式只能使用已入库且有效的数据。
- 深度研究、主题综述和基础层只读查阅入口不得触发图谱重建或写入。
- 向量库或图谱更新失败时应可诊断并可恢复。
- 用户能明确看到哪些论文成功进入知识库，哪些论文被跳过或失败。
- 右侧数据侧栏能展示入库、向量化、Graph 节点/边更新和失败项摘要，并支持跳转到论文库或 Graph 图谱。

#### FR-022 邮件推送服务

**需求描述：**
系统应将当前 Project 未推送的有效论文整理为邮件，发送给用户配置的收件人。

**功能范围：**
- 构建流程完成后自动触发邮件推送，用户也可在结果页手动触发发送。
- 邮件内容包含 Project 名称、有效论文统计和论文摘要列表。
- 仅发送当前 Project 中未推送的有效论文。
- 发送前应允许用户预览本次推送范围；自动任务可按默认策略直接发送。
- 发送成功后记录推送状态。
- 手动重发属于 P1 支撑能力。

**验收标准：**
- 构建流程完成后能自动触发邮件推送，用户也可在结果页手动触发。
- 邮件内容包含 Project 名称、有效论文统计和论文摘要列表。
- 邮件只包含当前 Project 中未推送的有效论文。
- 发送前用户能预览本次推送范围；自动任务可按默认策略直接发送。
- 无未推送有效论文时不发送空邮件。
- 发送成功后能记录推送状态。
- 邮件发送失败不应回滚已完成的论文入库。
- 推送状态与发送结果一致。
- 手动构建场景下，用户能看到本次邮件推送范围和发送结果。
- 手动重发未实现前，不得阻塞正常自动推送和手动首次发送。

### 3.5 深度研究模式功能需求

#### FR-023 Graph-RAG 对话式研究

**需求描述：**
深度研究模式应基于当前 Project 已构建知识库，为用户提供多轮、流式、可引用的研究对话。

**功能范围：**
- 用户可创建和管理多个研究对话。
- 每轮对话自动执行 Graph-RAG 检索。
- Agent 回复应结合对话历史和检索上下文。
- 回复支持流式输出。
- 回复应展示引用论文、PDF/远程访问入口或图谱节点信息。
- 右侧数据侧栏的深度研究模式上下文应展示当前对话使用的引用论文、引用文段、Graph-RAG 命中来源和相关图谱节点摘要。
- 用户可从回复引用跳转到基础层论文详情或 Graph 图谱节点。

**验收标准：**
- `valid_papers = 0` 时不能进入深度研究模式。
- 用户可创建和管理多个研究对话。
- 每轮对话自动执行 Graph-RAG 检索，并结合对话历史和检索上下文生成回复。
- Agent 回复支持流式输出。
- 回复能展示引用论文、PDF/远程访问入口或图谱节点信息。
- 右侧数据侧栏能展示当前对话使用的引用论文、引用文段、Graph-RAG 命中来源和相关图谱节点摘要。
- 每轮成功对话都应保存用户输入、Agent 回复和引用信息。
- 对话引用必须能跳转到当前 Project 的论文详情或图谱节点。
- LLM 或检索失败时不得写入半成品对话轮次。

#### FR-024 深度研究输出倾向

**需求描述：**
深度研究模式应支持不同研究意图下的输出倾向，帮助用户在同一知识库背景下进行不同类型的探索。

**功能范围：**
- 创新倾向：偏向提出潜在研究方向、假设和组合思路。
- 实验倾向：偏向设计实验方案、变量、指标和验证步骤。
- 总结倾向：偏向整理已有讨论、结论、未决问题和下一步计划。
- 用户可在对话中切换输出倾向，切换不清空上下文。

**验收标准：**
- 用户能明确选择当前输出倾向。
- 系统至少支持创新、实验、总结三类输出倾向。
- 不同倾向下回复结构和关注点应明显区分。
- 切换倾向后仍能引用同一对话历史。
- 创新倾向应偏向研究方向、假设和组合思路。
- 实验倾向应偏向实验方案、变量、指标和验证步骤。
- 总结倾向应偏向已有讨论、结论、未决问题和下一步计划。

#### FR-025 对话历史、总结文件与导出

**需求描述：**
系统应保存深度研究过程，并支持将对话和阶段性结论整理为可导出的研究资料。

**功能范围：**
- 保存对话列表、轮次、标题、标签、摘要和最后活跃时间。
- 支持搜索、筛选和归档对话。
- 支持按需生成对话总结。
- 支持导出对话或总结文件。

**验收标准：**
- 对话历史按时间顺序完整可追溯。
- 系统能保存对话列表、轮次、标题、标签、摘要和最后活跃时间。
- 用户可搜索、筛选和归档对话。
- 用户可按需生成对话总结。
- 用户可导出对话或总结文件。
- 归档对话不得继续追加消息。
- 总结内容应能反映对话中的关键结论和未决问题。

#### FR-026 研究引用与图谱跳转

**需求描述：**
用户应能在深度研究模式中围绕对话引用只读探索当前 Project 的论文、PDF 访问入口和 Graph 图谱关系。Graph 图谱本身属于基础层全局可视化能力，本 FR 只定义深度研究模式中的引用上下文和跳转体验。

**功能范围：**
- 展示当前对话轮次使用过的论文引用、文段来源和图谱节点。
- 上述引用、文段来源和图谱节点应作为右侧数据侧栏的深度研究上下文展示，帮助用户在对话过程中持续查看当前证据来源。
- 支持从对话引用跳转到基础层论文详情。
- 支持从对话引用跳转到基础层 Graph 图谱，并高亮相关节点和边。
- 支持从论文详情打开有权限访问的 PDF 或远程文件入口。
- 不允许在深度研究模式修改论文库、上传论文、移除论文关联或触发图谱重建。

**验收标准：**
- 系统能展示当前对话轮次使用过的论文引用、文段来源和图谱节点。
- 深度研究上下文能在右侧数据侧栏持续展示当前证据来源。
- 引用跳转只展示当前 Project 的数据。
- 用户可从对话引用跳转到基础层论文详情。
- 用户可从对话引用跳转到基础层 Graph 图谱，并高亮相关节点和边。
- 用户可从论文详情打开有权限访问的 PDF 或远程文件入口。
- 深度研究模式不得修改论文库、上传论文、移除论文关联或触发图谱重建。
- 深度研究中的图谱跳转不改变论文库、向量库或图谱存储。
- 图谱数据缺失或过期时应提示用户返回构建模式更新。

### 3.6 主题综述模式功能需求

#### FR-027 综述架构设计

**需求描述：**
综述模式应基于 Project 主题和已构建论文库，帮助用户生成、审查并确认综述文章架构。

**功能范围：**
- Agent 扩写研究主题、范围和背景。
- Agent 生成综述标题、摘要提示和章节结构。
- Agent 对大纲覆盖度、章节顺序、主题边界和论文支撑度进行自审。
- 用户可查看审查结果，编辑章节标题、类型、顺序和要点。
- 用户可查看当前 Project 论文库和 Graph 图谱提供的综述支撑情况。
- 右侧数据侧栏的主题综述模式上下文应展示大纲章节、每章论文支撑度、低支撑章节和建议补充的论文方向。
- 用户可重新生成、局部修改或确认架构。
- 用户确认架构后，系统才能开始章节撰写。

**验收标准：**
- `valid_papers = 0` 时不能启动综述模式。
- Agent 能扩写研究主题、范围和背景。
- Agent 能生成综述标题、摘要提示和章节结构。
- Agent 能对大纲覆盖度、章节顺序、主题边界和论文支撑度进行自审。
- 用户可查看审查结果，并编辑章节标题、类型、顺序和要点。
- 用户可查看当前 Project 论文库和 Graph 图谱提供的综述支撑情况。
- 右侧数据侧栏能展示大纲章节、每章论文支撑度、低支撑章节和建议补充方向。
- 架构确认前不得自动撰写章节。
- 确认后的架构应保存版本记录。
- 架构审查结果必须和当前大纲版本绑定，不得覆盖历史版本。

#### FR-028 章节撰写、引用与修订

**需求描述：**
系统应按已确认的综述架构撰写章节内容，自动引用 Project 论文库中的相关论文，并支持章节级审查和人工修订。

**功能范围：**
- Agent 按章节逐章生成 Markdown 正文。
- 每章撰写前检索相关论文或文段作为上下文。
- 章节内容应包含可追溯引用。
- 用户可从章节引用跳转到基础层论文详情、PDF/远程访问入口或 Graph 图谱节点。
- 右侧数据侧栏的主题综述模式上下文应展示当前章节引用论文、引用段落、引用覆盖状态、未引用的重要论文和相关 Graph 节点摘要。
- Agent 对章节准确性、完整性、逻辑结构和引用规范进行自审。
- 用户可查看审查问题、接受建议、手动编辑、重新审查或重新生成章节。
- 系统记录章节审查历史和修订次数。

**验收标准：**
- 章节只能基于已确认大纲生成。
- Agent 能按章节逐章生成 Markdown 正文。
- 每章撰写前应检索相关论文或文段作为上下文。
- 章节内容应包含可追溯引用。
- 引用必须能映射到当前 Project 论文库。
- 用户可从章节引用跳转到基础层论文详情、PDF/远程访问入口或 Graph 图谱节点。
- 右侧数据侧栏能展示当前章节引用论文、引用段落、引用覆盖状态、未引用的重要论文和相关 Graph 节点摘要。
- Agent 能对章节准确性、完整性、逻辑结构和引用规范进行自审。
- 用户可查看审查问题、接受建议、手动编辑、重新审查或重新生成章节。
- 章节引用跳转不得修改论文库或图谱。
- 用户编辑后的章节内容应保存。
- 用户未确认前，不得静默覆盖用户手动修改。
- 审查结果应与章节版本对应，不能覆盖其他章节。
- 系统应记录章节审查历史和修订次数。

#### FR-029 综述汇总、终审与多格式导出

**需求描述：**
系统应将已完成章节汇总为完整综述文章，执行全文级终审，并支持导出为常用格式。

**功能范围：**
- 自动合并已确认章节。
- 自动生成摘要、关键词和参考文献列表。
- Agent 执行全文一致性、重复内容、引用完整性和格式规范终审。
- 用户可查看终审问题、编辑完整文章、重新生成摘要/参考文献或确认最终稿。
- 右侧数据侧栏的主题综述模式上下文应展示全文引用覆盖、参考文献完整性、未解决终审问题和可导出版本状态。
- 支持导出 Markdown、PDF、Word。

**验收标准：**
- 所有必需章节完成并确认后才能汇总最终文章。
- 系统能自动合并已确认章节。
- 系统能自动生成摘要、关键词和参考文献列表。
- Agent 能执行全文一致性、重复内容、引用完整性和格式规范终审。
- 用户可查看终审问题、编辑完整文章、重新生成摘要/参考文献或确认最终稿。
- 右侧数据侧栏能展示全文引用覆盖、参考文献完整性、未解决终审问题和可导出版本状态。
- 参考文献应覆盖文章中实际引用的论文。
- 终审问题必须展示给用户，用户确认后才能生成最终导出版本。
- Markdown、PDF、Word 导出文件可正常打开，内容与预览一致。

#### FR-030 综述版本管理

**需求描述：**
系统应支持综述文章版本管理，便于用户追踪大纲、章节、审查记录和完整文章的变化。

**功能范围：**
- 保存大纲版本。
- 保存章节版本和审查记录。
- 保存完整文章版本属于 P2 能力。
- 支持查看版本历史。
- 支持版本差异和回退属于 P2 能力。

**验收标准：**
- 系统能保存大纲版本。
- 系统能保存章节版本和审查记录。
- 完整文章版本、版本差异和回退未实现前，不得阻塞大纲和章节版本记录。
- 用户能识别当前版本和历史版本。
- 回退历史版本必须二次确认。
- 版本记录不得因继续编辑而丢失。
- 审查和修订记录应能追溯到具体大纲、章节或全文版本。

#### 3.8.3 Web App FR 审查知识点

- FR 应描述用户可见能力和业务规则，不应直接承担数据库字段、API 响应或前端 ViewModel 字段定义。
- 每条 FR 的验收标准必须覆盖功能范围中的主要动作、权限边界、状态变化、失败路径和不可做事项。
- P0 FR 的验收标准应能驱动 UI、状态机、数据、API、权限和 QA 的后续闭环设计。
- 入口型 FR 要区分“入口展示”和“业务写操作”；入口可以跳转或筛选，但不应绕过模式工作区执行写操作。
- 长任务 FR 必须明确运行态、等待态、失败态、取消/重试结果和并发边界。
- AI Agent FR 必须明确人工确认点、失败原子性、引用可追溯性和生成内容覆盖规则。
- 只读查询能力和写入维护能力应拆开表达，避免基础层查阅入口和构建模式维护入口发生设计冲突。
- P1/P2 能力可以出现在功能范围中，但验收标准必须明确其不阻塞 MVP 主路径。
