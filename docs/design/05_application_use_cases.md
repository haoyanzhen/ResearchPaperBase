# Application Use Cases 设计

文档版本：v1.10
更新日期：2026-10-16
依据文档：`00_layers.md`、`01_functional_requirements.md`

> 本轮定义已决 P0 API 所需的应用编排；业务规则以 01、02 及领域附录为准。P1/P2 保持原分期，局部业务待决见[独立设计与审查记录](../workorders/api_p0_design_review_2026-10-16.md)。本文不是实现或验收完成声明。

## 1. 设计目标

Application Use Cases 是所有写操作和重要读操作的统一入口。它负责把用户意图转换为可校验、可审计、可恢复的业务操作，并统一执行权限、状态、锁、配置快照、事务和任务提交。

## 3. 标准用例管线

1. 鉴权并检查账号有效性；加载授权所需的最小对象信息，校验 Project 和全部子对象归属，再执行操作级授权。管理员身份不授予 Project 访问权。
2. 校验请求结构；对 04 第 7 节要求幂等的命令检查已受理记录：同键不同请求拒绝；同键同请求在当前鉴权和结果有效性校验后重放，不重做修订校验造成假冲突。新命令再校验 Project/对象状态、`expected_revision`、等待项和必要确认。
3. 取得所需执行资格，再在保护边界内重查状态和修订。构建冻结顺序见第 7 节，不能在等待资格前固定发布基线。
4. 执行同步操作，或原子保存命令、任务身份、冻结输入/配置、执行资格和可恢复投递记录。任务句柄可由 `/tasks/{id}` 查询；不得返回成功受理后无记录地丢任务。
5. 后台经受控应用入口领取任务；队列重复投递不得重复写入。投递失败保留诊断并允许内部安全补投，不把投递成功当业务成功。
6. Worker 提交结果时重查当前权限、Project/对象状态、执行资格、输入修订和确认有效性；业务状态和对应持久事件一致提交，SSE 仅投影已记录事实。

纯预览在鉴权、结构、状态及修订校验后只计算影响范围和签发凭据，不进入业务写入/任务派发步骤，不占用业务执行槽或推进修订。技术凭据存储和审计不构成确认消费。真正执行时仍重验全部前置条件。确认载体由 04-01 明列，普通详情不预计算全部动作影响。

本节统一维护执行顺序：并发同键通过唯一约束或等价互斥只受理一次，事务提交前不返回虚构句柄；短事务竞争结束后重复请求读取已提交记录。可采用事务发件箱实现持久交接，不要求跨关系库、文件、向量及图谱的分布式事务。内部投递恢复不是 P1 用户重试/重连。具体队列产品不在本文选定。

### 3.1 知识读取上下文的执行边界

Knowledge 读取先校验来源对象与 Project/绑定版本，再通过 [06 读取契约](06_agent_knowledge_services.md#31-版本读取与存储适配契约)取得受保护 ReadContext；普通浏览才可在入口解析一次默认版本。创建对象时默认版本解析、绑定及持久依赖登记须一致提交。异步任务受理时持久记录版本/依赖，执行前取得有效读取保护，不得在队列等待后改用新默认。

子任务、检索、资产读取、图谱扩展、引用解析及缓存都传递相同上下文。提交结果前校验其证据确属绑定清单与有效输入，并重查当前授权及执行资格；上下文缺失、保护失效或依赖损坏时明确失败，不自动 latest 回落。恢复沿用原版本及输入；恢复机制仍由 02-04 承载。

发布与回收分别按 [07 第 5.2–5.3 节](07_data_persistence.md#52-发布原子性与故障边界)组织；不以长数据库事务包裹整个推理过程，也不要求读取占用 Construction 写槽。读取保护只阻止依赖被普通回收，不阻止新版本隔离构建/发布。

## 4. 配置快照

每次需要外部服务的任务在实际启动前形成配置快照：Construction 冻结本轮输入，Research 每次回复 attempt 固定当次模型/检索参数，Review 每次生成或审查固定当次参数。后续当前模型变更不修改运行中任务或知识绑定。P1 Export/Email 仅记录实际需要的配置，不要求所有任务具备 LLM、数据源与 SMTP 全部配置。

快照应记录配置来源、LLM provider、base URL 脱敏标识、模型名称、参数、数据源列表、启用状态、访问模式、速率限制、SMTP 来源、系统硬限制版本、任务启动时间、触发者、Project 和 Knowledge Version。

快照不得保存或返回 API key、SMTP 密码、用户密钥或系统密钥明文；只记录配置修订和密钥引用。执行时密钥不可用则失败并给出修复入口，不静默替换配置。

LLM 必须使用用户显式选择的可用模型；系统模型是可选来源，不是无选择时的隐式回落。数据源按 FR-007 解析，个人配置存在但不可用不冒充未配置；检索词策略只在已解析集合内选择。未实现的 P1 白名单及系统速率/并发增强不成为 P0 卡口。系统 SMTP 保存/测试是 P0，用户通知及邮件链路保持 P1。

## 5. 锁与并发

| 锁 | 范围 | 保护内容 | 失败行为 |
| --- | --- | --- | --- |
| `project_construction_write_lock` | Project | 同一 Project 只能有一个占槽 Construction Run，paused 仍占槽 | 拒绝启动或调度延后 |
| `scheduler_project_lock` | Project + 调度周期 | 防止重复自动创建 Run | 记录跳过原因 |
| `research_stream_lock` | Research Session | 同一对话一次只追加一个流式回复 | 拒绝第二次发送并提示当前回复 |
| `review_chapter_lock` | Review Run + Chapter | 生成、审查、人工保存、重新生成均互斥 | P0 拒绝冲突并返回当前任务 |
| `review_final_lock` | Review Run | 固定大纲、必需章节与内容修订 | 依赖变化拒绝旧结果替代当前稿 |
| `content_overwrite_lock` | 内容对象 | 防止覆盖确认期间内容变化 | 要求刷新后重试 |
| `export_job_lock` | Export 目标 | 避免同一产物重复生成 | 返回已有任务或创建新版本 |

执行锁应有超时、持有者、创建时间和诊断信息；技术租约超时不得隐式释放 paused Run 的业务构建槽。显式继续恢复同一 Run 实例并沿用原槽；显式取消先撤销该实例写资格，再清除占槽；显式重跑先撤销旧实例写资格，再将旧 Run 记为 cancelled 并记录被替代原因和新 Run 关联，由新 Run 实例定向接管原槽。交接未完成前不得启动新写入者，迟到写入一律拒绝。 定向交接按 [02-02 第 10 章](02-02_construction_versioning_appendix.md)闭环：新 Run 创建/准入已确定失败，或用户已显式取消新 Run，且旧 Worker 失权已确认时，关闭交接预约、允许其他申请竞争槽；保留旧 Run 取消与新 Run 失败/取消诊断，不复活旧 Run。结果不明或旧 Worker 失权尚未证实时先查证，不能凭超时开放槽。

## 6. 状态推进

状态名称和业务合法性由 [02 第 3 章](02_domain_core.md#3-run--session-生命周期)定义；下表只分配执行职责，不引入统一状态机或新生命周期枚举。

| 对象 | 状态推进边界 |
| --- | --- |
| ConstructionRun | 受理、执行、阶段等待、失败、取消、成功映射既定领域状态；成功结果区分 published 与 no_change；published 要求完整发布，no_change 不发布或切换版本。paused 为 P1，持续占槽 |
| ResearchSession | 是可继续的会话容器；单次回复成功、失败、取消只更新轮次/attempt，不终结或暂停 Session |
| ResearchResponseAttempt | 成功保存完整回复与证据；失败/取消保存诊断和未采纳片段，不把片段作为成功回复 |
| ReviewRun | 聚合简报、大纲、章节和终稿；单章完成或终稿 accepted 不自动推导整个 Run succeeded；由用户按第 9 节显式完成，完成后只读 |
| Review 内容对象 | 分别保存修订、确认、审查及 accepted/rejected 等既定状态，不等同于任务执行状态 |
| Task / P1 ExportJob、EmailPushJob | 执行状态不替代业务资源状态；传输枚举以 04-02 为准 |

已成功、取消或归档的历史实例不得原地改回 running。新实例/新运行结果保存来源关系，`copied_as_new` 不是状态。P1 恢复与通用重跑遵守 02-04，不借接口改用最新知识基线。

ConstructionRun 的合法转换及候选生命周期以 [02-02 第 10 章](02-02_construction_versioning_appendix.md)为准。单次 attempt 失败且仍可按策略重试时 Run 保持 running 和原槽；整轮失败才转 failed，旧执行者失权后释放槽。P1 原 Run 恢复须按 [02-04](02-04_run_recovery_appendix.md)校验可信断点与原输入/配置/基线，沿 failed → queued → running 创建新 attempt，重新竞争槽；条件不满足则按恢复规范明确要求新 Run。放弃恢复保持 failed，关闭恢复资格并记录清理属性。普通排队不占槽，资源暂时不足继续排队，权限或原基线等已不可执行条件使 queued → failed；未通过提交校验的草稿不制造失败运行。waiting_user 可暂停，继续只恢复原等待项，不能代替确认；相关暂停/恢复仍属 P1。

### 6.1 修订、确认与迟到结果

人工编辑记录最后修改人、时间、来源、内容状态和修订。Agent 先生成独立结果，提交时比较启动修订；人工修改优先于人工确认，人工确认优先于 Agent 草稿。失败/取消不得破坏原内容。

确认凭据限定 action、resource、revision、impact，不是权限凭据，不能绕过构建槽、归档或版本要求。技术 token 有效期只校验命令受理时点；受理后保存持久确认记录，Worker 检查内容/权限/依据的持续有效性，不以原 token 到期拒绝仍合法的长任务。相关内容或决定实质变化使确认失效，无关配置修改不使本轮确认失效。保存草稿、阅读状态和 SSE 回放均不能生成人工确认。取消先撤销写资格，之后旧 Worker 不得提交成功内容或发布；清理仅处理所属未发布产物，不删除独立待纳入修订、人工内容或已发布证据。

本文恢复/重试语境中的“原输入”指该次执行所绑定的最后有效输入修订；初始冻结快照仍保留，不能借恢复修改输入、配置或基线。API-D01 A 的显式返回检索是独立用户动作，仅在筛选等待点追加已确认检索词，原来源、时间范围、总预算和基线不变，使用剩余额度；入库确认受理后禁止返回检索。

## 7. Construction 主流程

1. 读取 Construction Workspace 和本次检索词来源，区分常规新构建与恢复、重试、重连或通用重跑。旧研究依赖不阻止构建；启用自动更新授权在配置范围内使用最新基线，不授权迁移旧研究或覆盖人工内容。
2. 预校验配置可解析性，不提前冻结基线。
3. 取得 Project 独占构建资格后，常规新构建固定此时最新已发布版本，重新解析实际配置和数据源策略并冻结输入/配置；首次构建允许无基线。恢复、重试、重连及通用重跑保持原输入、配置与基线，不隐式改用最新版本。
4. 检索论文和资料候选；部分数据源失败保留诊断并使用成功结果，全部不可用阻断。
5. 归一化身份、去重、评分和筛选。
6. 手动筛选确认绑定候选修订；误合并修正、评分/有效性调整更新候选统计，不改正式版本统计。P1 自动 Run 才启用自动确认策略。
7. 获取和解析支持格式文件，区分全文、摘要降级、资料解析及不可用项；手动确认处理结果后才能 AI 分析。
8. 生成论文严格结构分析或资料轻量摘要，提供人工编辑及分析确认。重新评分不静默覆盖人工决定。
9. 校验与候选修订绑定的入库预览确认，受理后锁定论文和资料候选内容，写入本轮隔离候选范围内的 ProjectPaper/ProjectMaterial 修订、文本资产、向量索引和图谱；不得修改已发布读取内容。
10. 按 [02-02 第 10 章](02-02_construction_versioning_appendix.md)完成裁决：知识有变化时，关系数据、向量、图谱和引用定位完整可读后发布 Knowledge Version，先准备隔离外部产物，再原子提交版本可见性、Run succeeded 与 published 结果、默认版本指针和变化记录。无变化时，原子记录 Run succeeded 与 no_change 结果、核验的既有版本、范围及时间，并将候选记为已废弃（原因：核验无变化），不生成版本或切换默认版本。两条完成路径均重新校验权限、写资格、确认有效性、内容完整性及候选基线仍等于当前最新已发布版本；首次无已发布版本不能 no_change，失败、未核验或仅零新增不能视为无变化。任何尝试基线落后均拒绝发布并保留诊断，手动场景用户须显式新建最新基线构建，自动场景后续调度可按有效授权独立新建 Run，不自动改绑或合并。
11. published 后形成 P0 版本变化清单，不改写旧研究绑定；no_change 不产生版本升级提示或空邮件。P1 邮件推送固定本轮新增有效范围并去重，失败不回滚知识发布或 Run 成功结果。

取消与 published/no_change 完成必须在同一业务裁决边界排他提交：完成先提交则保留 succeeded，取消先撤销写资格则禁止完成；不按客户端点击时间回滚。响应不确定先查持久结果，不重复执行或假定取消成功。候选待发布须满足完整性、有效确认及无待续连工作，实质变化退回准备中并撤销相应确认；发布时仍重查全部条件。

基线失配的自动尝试失败退出、不等待用户；后续调度可在仍有效的自动更新授权下独立创建最新基线的新 Run，不得将旧尝试改绑或沿用过时确认。

单条补充/单文件上传先建立请求，解析元数据或标题草稿并确认。当前版本已有成员的重复命中只记录备选来源，不创建修改已入库内容的修订；修改须先发布关联移除，再显式新导入。独立待纳入请求不因上传成功成为正式知识；构建开始后新提交默认下轮纳入。论文与资料在入库确认受理前允许候选修改，变更使受影响处理及确认失效；受理后锁定，入库失败保留草稿及诊断，P0 可新建构建，不新增原 Run 恢复入口。

同 Run 返回检索仅在筛选等待点追加已确认检索词；保留原词、初始配置、来源、时间范围、总预算和基线，使用剩余额度，撤销受影响旧执行资格并重做受影响处理，保留人工决定。入库确认受理后不可返回；更改范围/预算另建构建，通用恢复仍为 P1。

revision_only 使用同一写槽和完整发布流程，不新检索，只处理新增、移除及显式重新纳入；不接受对当前已入库论文/资料的 metadata/text/analysis 修改。用户选择单条、批量或全部移除后，一次预览列明固定成员及修订、旧版本保留、空版风险和需终止的具体冲突构建；同次确认授权自动受理移除构建及已列明终止。撤销冲突运行写资格后交接槽；新出现的冲突须刷新预览，不能静默取消未展示运行。无冲突按槽排队，不取消研究/综述；重复命令重放既有结果。确认只是受理，发布前默认版本不变，失败/取消不形成部分成功。

有意清空可发布完整一致的空版本，结果为 published 并切换默认指针，不能把检索/解析失败或零新增当清空。移除只改变后续版本关联，旧版本与引用保留，不物理删除历史文件；自动检索不得恢复人工排除，显式重新导入沿用全局身份、重新确认新内容，不继承旧确认。

手动图谱重建或修复必须走同一 Construction 写入和发布边界。关系/向量/图谱同步实现另由 06/07 细化，不允许先发布后补图谱。

## 8. Research 主流程

1. 创建 Session 时绑定已发布 Knowledge Version（含空版本，明确无证据提示，不拒绝创建、不自动换版）；采用最新知识创建关联新 Session，原 Session 的绑定与历史回复保持不变。
2. 检查 Project、Session、配置和 stream lock，原子保存用户输入、轮次和 attempt。
3. 按绑定版本检索并固定证据上下文；检索失败保留诊断，检索为空按 04-01 明确选项决定是否继续普通回复，并标明无引用上下文。
4. 调用 Agent 生成流式回复。
5. 保存消息、引用、证据定位和生成参数。
6. D02 B 将消息编辑/删除及失败片段采纳留至 P1；P0 不以读取片段实现采纳。记录 attempt 结果并释放 stream lock，更新 Session 活动信息，不因一轮成功/取消终结 Session。取消只撤销目标 attempt 资格；失败片段与输入保留，传输断线不自动取消或重启生成。

采用预览固定目标版本、继承的已保存稳定输入和来源修订；确认后创建关联新 Session 或新 Review，不 PATCH 原绑定。流式半成品不继承，历史结论仅为待复核背景，人工内容不继承确认状态。之后又有新版发布也不静默替换用户已确认目标。固定范围只改变对象级更新提示，不阻止构建；引用保持原版本及当前权限校验。

## 9. Review 主流程

1. 创建 Review Run 时绑定已发布 Knowledge Version（含空版本，明确无证据提示，不拒绝创建、不自动换版）；采用最新知识创建新版 Review，原稿保留，不在原 Run 内切换证据范围。
2. 生成大纲及自审、支撑度和低支撑建议；允许编辑，确认绑定大纲修订与知识版本。低支撑提示并记录，不新增阻断门槛。
3. 只有确认大纲后才能逐章生成，编辑不等于确认。每章固定证据上下文、大纲和章节修订。生成与审查按 FR-033 学术引用规范处理归属、直接引文定位及参考信息，不按段落/数量计算覆盖率，不设豁免申请或 strict 开关。空版上下文明确无证据，不伪造引用。
4. 每章生成、审查、人工保存和重新生成互斥。机械检查标记/条目/证据版本定位对应，语义支持不足由既有 ReviewIssue 提供建议，不依 Agent 分数阻断确认。坏标记不导致人工正文丢失，不注册伪有效 EvidenceRef；系统不得从越权/跨版本证据读取并注入正文。审查绑定当时修订，接受建议仍校验修订。
5. 汇总固定已确认大纲的必需章节范围，检查完成、确认、修订和单一知识版本；可选章节缺失不阻断，依赖变化不得让旧汇总覆盖新编辑。
6. 生成完整 Markdown 终稿及终审问题，成功默认 accepted，不增加终稿接受门槛。完整文章是唯一可写正文，摘要/关键词/参考文献投影由同一修订派生；不建立独立可导出快照生命周期。
7. 未完成 Run 的 accepted 终稿可编辑，保存即当前可读、可下载稿；expected_revision 防覆盖，失败或迟到生成不覆盖已保存稿。保存不复活 rejected 稿，重新生成按现有规则形成新结果。显式拒绝仅拒绝目标稿并禁止下载，删除其对应托管文件、保留问题和诊断；不删除其他 accepted 结果。
8. P0 单稿 Markdown 下载读取授权的指定当前修订，一次一致读取形成附件，不调用模型；修订失配返回 412，rejected/deleted/越权拒绝。响应 attachment/no-store/nosniff，预览不执行脚本。通用导出中心、批量及 PDF/Word 转换仍 P1，异步转换固定任务输入而不要求用户生成业务快照；P2 历史/差异/回退另行实现。
9. 用户显式完成时原子校验 Run/终稿/来源修订：无活动任务、当前稿 accepted、大纲及必需章节确认仍有效；终审建议可保留，终稿编辑不反向使章节确认失效。完成不是下载前置；完成后只读，继续编辑下载到本地，P0 无 reopen、复制 Run 或外部改稿回传。已下载副本不受远程撤回控制。

保留 D05 显式完成方向；R1-A 替代 D03 严格覆盖能力，R2-A 替代 D06 独立导出快照。知识版本不可变快照、人工内容保护和最小修改追溯不变。

## 10. 幂等与重试

- 用户重复提交启动命令时，若幂等键相同，应返回同一任务。
- 自动调度重复触发时，应按 Project + 调度窗口去重。
- Provider 临时失败可重试，但必须保留 attempt 和错误分类。
- 人工修改后的内容不得因任务重试被静默覆盖。

P0/P1 用例至少覆盖权限拒绝、Project 状态拒绝、配置解析失败、锁冲突、Provider 失败分类、内容覆盖保护、Knowledge Version 绑定和过期提示。

## 12. 账号、Project 与 Workspace 特殊编排

- 首位管理员和最后启用管理员约束在并发事务内检查。管理员删除用户先阻止新鉴权/任务写入，再按私人资产边界清理；账号治理不提供 Project 内容查看。重置生成的新密码仅受控响应返回，不进入日志或后续读取；其幂等重放安全边界以 04 为准。
- Project 清理预览绑定修订与影响范围，确认后重查共享引用及保留导出结果。归档/删除生效后后台写入必须拒绝或安全终止，遵守 02-02 A16；D04 A 已定：受影响非终态执行安全终止后 cancelled 并记录原因，原终态保持；清理失败独立记录，不恢复写资格。管理生效与成功结果提交按同一裁决边界排序，先完成则保留成功，先失权则拒绝迟到成功。
- Workspace 保存仅含当前用户/Project 下对象引用、基础面板和未提交草稿；恢复校验权限/状态，失效返回安全默认或空态。个人显示偏好不授予 archived Project 业务写能力；恢复不能提交任务或覆盖正式内容。
