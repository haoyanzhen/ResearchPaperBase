# 工作区模块与资产层扩展设计

文档版本：v1.3
更新日期：2026-11-04

## 1. 范围与归属

构建、研究、综述是固定的内置模块。用户可以定义新模块，并在 Project 中启用或停用。首版协议采用声明式定义，由宿主渲染表格、表单和资产选择器。本文记录扩展设计，协议操作名用于说明职责，尚未形成已发布 API 或当前 P0 的验收项。

工作区负责展示入口、切换对象和恢复上下文。模块负责自己的对象和业务动作。资产层向所有模块提供统一的查找、版本读取和文件打开接口，由来源模块解释内容和访问条件。研究会话仍归 Research，综述报告仍归 Review，论文及其发布修订仍归来源 Project。自定义模块可保存自己的记录、人工备注和资产引用。写入所有权沿用[内部模块契约](05-01_internal_module_contracts.md)。

## 2. 模块接入协议

| 操作 | 输入与可观察结果 |
| --- | --- |
| 登记定义 | 清单包含项目内唯一的 module_key、协议版本、名称、视图、记录字段和请求的资产类型与操作。宿主在登记时分配 module_id，拒绝未知的协议版本、与内置入口冲突的键，以及发布知识版本等不支持的能力。 |
| 按项目启停 | 当前用户须有目标项目对应的管理权限。启用后出现入口，停用后拒绝新操作并保留记录。提交在途操作时重新检查启用状态和权限。重启用恢复已有对象；不兼容的定义升级保留原定义和数据。 |
| 创建模块对象 | 输入目标 Project、模块标识、显式选定的已发布知识版本；服务端校验版本归属和目标模块写权限，保存绑定后返回对象标识。工作区恢复时按对象加载绑定。 |
| 使用资产 | 模块声明所需能力，例如列出研究会话、读取会话、打开生成文件或读取综述报告。保存来源引用、备注或其他对象修改时须有目标模块写权限。目标只读用户可按来源权限打开已保存的引用，不能保存新引用。资产层把读取请求路由给来源模块。清单是能力上限，用户实际可用的操作还取决于当次授权。 |

## 3. 同一套知识版本规则

本节适用于首版声明式自定义模块。内置研究与综述按 [FR-018](01_functional_requirements.md#fr-018-知识库并行更新与研究证据范围) 在同一对象内逐次跟新。两类模块共用已发布快照、权限、证据溯源和构建独占发布规则。每个使用知识的自定义模块对象在创建时绑定所属 Project 的一个已发布 KnowledgeVersion，持久化 Project 与版本标识。默认版本可作为创建时的建议，读取始终使用已保存的标识。空版本可绑定，其成员列表为空。需要采用另一版时显式选择并创建后继对象，原对象及其历史引用仍按原版解析。对象创建与版本依赖登记须同时成功；版本被使用期间，回收流程保护其依赖的资产修订。采用新版时建立独立的依赖，旧对象继续保留旧依赖。新增引用须核验所绑定版本的成员、修订与定位。资产层从其他 Project 打开的对象保留自己的来源与绑定，不参与当前版本的成员计算。详见[版本、引用与选择规则](02-02_construction_versioning_appendix.md)。

只有成功的 Construction Run 能发布新知识版本并切换默认版本。已发布快照不可原地修改。研究、综述、自定义模块和资产层对知识版本只有读权限；创建模块对象、登记外部资产引用或导出文件都不能写入版本成员、索引或默认指针。构建的写接口由服务端限制调用身份和执行资格，模块清单不能授予这项权限。

## 4. 统一资产读取与跨项目使用

例如，用户在 A 项目的证据矩阵中绑定 A/v3，再从 B 项目选择一个研究会话、该会话生成的文件和一份综述报告。矩阵保存三条来源引用；有相应权限的读者可以在矩阵里打开内容。即使 B 项目的会话中选定的回答使用 B/v7，矩阵仍然使用 A/v3。具体约定如下。

| 操作 | 资产层行为 |
| --- | --- |
| 查找与选择 | 用户显式选择来源 Project，资产层仅返回当前用户可访问的对象和允许的操作。资产引用包含来源 Project、类型、来源对象标识，以及来源端提供的修订或文件标识。会话与文件分别鉴权。 |
| 读取与展示 | 每次列举、预览、下载或异步取数时，同时检查目标模块访问权与来源对象的当前读取权；读取内容前由来源端验证归属。缓存和文件交付同样受此检查约束。其他成员打开共享矩阵时以自己的身份重新解析引用。 |
| 修订与失效 | 来源支持固定修订时记录所选修订；只提供当前视图时明确标为“当前内容”，不得充当固定证据。撤权、来源删除或修订不可读时，目标保留无敏感信息的不可用占位，不展示受限标题、摘要、缓存正文或下载地址。 |
| 引用与派生使用 | 外部资产作为来源引用单独展示，可与目标模块自己的备注共同使用。读取权不自动授权把来源正文复制进目标共享记录、导出给其他成员或发送给模型。需要作为目标项目正式知识时，沿用目标项目的接收和构建发布流程。 |

来源资产的访问遵守[Project 授权](08_security_permissions.md)和[资料使用策略](08-01_agent_data_access_policy.md)。统一资产层不产生全局共享目录；跨项目打开来源对象与目标知识版本内的证据引用分别处理，研究回答及综述稿件的证据分别按实际操作版本校验。

## 5. 实施时的验收场景

1. 在 A/v3 创建证据矩阵后，构建发布 A/v4。重开矩阵仍读取 v3；显式采用 v4 后两个对象各自可读。分别验证空版本可绑定、未发布版本和伪造的版本归属被拒绝。
2. 用户能从 A 打开有权访问的 B 会话、文件和报告。只有 A 权限的协作者不能从同一矩阵拿到 B 的内容；拥有会话读取权但无文件下载权的用户不能借会话下载文件；对 A 只读且可读 B 的用户可以查看已有引用，新增引用或修改备注时被拒绝。
3. 列表返回后撤销 B 的权限，随后预览、下载和缓存命中均须拒绝。仅提供当前稿的报告发生编辑后，界面仍标明读取当前稿；固定修订失效时不得回退到最新版。
4. 研究、综述和自定义模块分别尝试发布、切换默认指针和改变版本成员，服务端拒绝，原快照、成员及指针保持一致。保存模块备注或引用 B 的报告也不产生 A 的知识版本。
5. 在途保存与停用并发时，已生效的停用阻止迟到提交；重新启用可打开此前保存的记录。升级不兼容或来源暂不可用时，已保存的人工备注仍可恢复。

以下接口是本扩展的协议设计，尚待映射到 OpenAPI、持久化实现和可执行用例。研究会话、生成文件、综述报告由各自模块提供可授权的读取入口后，才能逐类接入。

## 6. 协议 v1 与模块清单

模块作者提交一份 JSON 清单。宿主负责生成对象列表、编辑表单和来源资产选择器。以下是一份完整示例。

```json
{
  "protocol_version": 1,
  "module_key": "evidence_matrix",
  "name": "证据矩阵",
  "view": "table",
  "fields": [
    {"key": "question", "label": "研究问题", "type": "text"},
    {"key": "notes", "label": "人工备注", "type": "text"},
    {"key": "sources", "label": "来源", "type": "asset_refs"}
  ],
  "asset_access": {
    "research_session": ["list", "read"],
    "research_file": ["list", "download"],
    "review_report": ["list", "read"]
  }
}
```

- 清单中上述六个顶层字段均必填。协议 v1 接受 table、form 两种 view，以及 text、asset_refs 两种字段类型。字段均可空，label 仅用于展示。module_key 与字段 key 使用小写 ASCII 字母开头，后接小写字母、数字或下划线，最长 64 字符；字段 key 在定义内唯一。拒绝未知写字段、重复 key、未注册的资产类型或动作、脚本和外部渲染器；文本按纯文本展示。
- module_key 是项目内稳定名称，宿主分配不可变的 module_id（UUID）。服务端保留内置模块键 construction、research、review。v1 允许 research_session 和 review_report 各声明 list、read，research_file 可声明 list、download；各动作独立授权。清单仅声明宿主允许请求的能力；服务端不接受调用者传入身份、权限、知识索引写入口或文件系统路径。
- protocol_version 描述宿主理解的格式；definition_revision 标识一份不可变的清单修订；普通 revision 用于并发控制。新增可空字段、修改显示名称或布局可兼容升级。删除或改名已存字段、改变类型会影响旧数据，v1 拒绝原地升级。扩展能力即使兼容也须项目管理者显式采用，已打开的旧表单不能用新定义静默保存。

## 7. 宿主操作与数据契约

下表路径以扩展草案的项目资源 /projects/{project_id}/modules 为前缀，M 表示 /{module_id}。路径仅描述扩展范围。响应使用[公共 API 的信封、分页、修订及幂等规则](04_api_contracts.md)。表中的项目均为目标项目；source_project_id 始终另传，不能覆盖路径中的项目。按现行权限矩阵，项目业务写入要求当前 Owner、项目可写；系统管理员身份不授予项目内容权限。

| 操作 | 方法与相对路径 | 请求 → 成功响应 |
| --- | --- | --- |
| 登记与查看 | POST 前缀；GET 前缀或 M | POST 提交 manifest，201 返回 module_id、definition_revision、revision、enabled=false。模块键冲突不覆盖。GET 返回已授权模块及当前可用动作。 |
| 启停 | PATCH M | enabled、expected_revision → 200 返回新 revision 与实际状态。停用隐藏工作区入口，管理端仍能查看定义。 |
| 升级 | POST M/definitions | manifest、expected_revision → 201 返回采用的 definition_revision 和新 revision。校验兼容性后原子切换；失败沿用旧定义。module_key 不可变。 |
| 创建对象 | POST M/objects | knowledge_version_id、definition_revision、values → 201 返回 object_id、固定版本、定义修订、对象 revision。values 仅允许定义中的字段。对象与版本依赖登记任一失败时均不生效。 |
| 恢复对象 | GET M/objects 或 M/objects/{object_id} | 列表分页；详情返回固定版本、当前定义修订、对象 revision、字段值与可用动作。新增字段以空值展示。来源字段按当前用户重新投影。 |
| 编辑对象 | PATCH M/objects/{object_id} | expected_revision、definition_revision、changes → 200 返回新对象 revision。只更新具名字段，省略即保留；空文本及空引用数组可显式写入。拒绝改绑版本或客户端提交来源标题、正文和下载地址。 |
| 采用新版 | 对象路径下 POST adoption-preview、POST adoptions | 预览接收 target_knowledge_version_id、expected_revision；执行携带该目标、修订和公共确认凭据。201 返回新对象 ID、前序对象 ID 与新绑定。沿用目标版本重新核验规则，旧确认不继承；失败保留原对象，且无孤立版本依赖。 |

采用新版时，预览返回来源对象、源/目标知识版本及拟继承字段。v1 后继对象使用当前清单，只继承用户在预览请求中显式选择的文本字段（retain_fields 数组，空数组表示不继承）；来源引用需重新选择，人工确认状态不复制。执行携带与预览一致的 retain_fields；对象修订、定义、权限或目标版本有效性变化后须重做预览。

有副作用的 POST 要求 Idempotency-Key。预览按公共 API 纯预览规则处理；PATCH 返回丢失时先查详情。过期的对象修订返回 412，缺失必需修订返回 428；表单定义已过期时要求重载定义并保留本地人工草稿。不可披露的对象统一返回 404，已授权对象的状态冲突按公共错误协议映射。未知字段返回 422。重试不得重复登记、重复创建对象或替换人工记录。

### 7.1 来源资产操作

资产引用由 source_project_id、asset_type、asset_id、selector 组成。selector 为 {"mode":"current"} 或 {"mode":"fixed","revision_id":"…"}。current 明示跟随来源；fixed 要求来源能按该不可变修订寻址。并发用的 revision 不能冒充可长期打开的 revision_id。目标只保存来源定位，展示标题、可用动作与内容由来源端按当前权限返回。

| 操作 | 输入、返回与限制 |
| --- | --- |
| GET M/assets | 必传 source_project_id 和 asset_type，可带 cursor。返回当前主体可见的定位、展示名和允许操作。游标还绑定目标模块、来源项目及筛选条件；每页重新鉴权。 |
| GET M/assets/resolve | 以查询参数传来源三元组、mode 和适用的 revision_id；返回可读投影与 resolved_revision（来源支持时）。无权、归属错配和不存在使用同一不可披露响应。读取对象详情时，失效引用只显示占位。 |
| 文件打开 | GET M/assets/file-access 使用与 resolve 相同的查询字段，返回文件名、类型及目标模块作用域内的代理下载地址，要求 download 能力。宿主调用[受权文件传输契约](04-02_transport_task_file_contracts.md)。代理地址以不透明标识关联请求主体、目标项目和模块代次、来源文件及选择的修订。实际 GET 重新核对该关联、目标模块状态和来源文件权限；URL 不进入对象字段。 |
| 保存来源引用 | 创建对象的 values 或编辑对象的 changes 中传入 asset_refs 数组。宿主校验字段、清单能力及每项来源归属与可用性后整批提交；任一新增引用不合格则整次写入回滚。已有失效引用不妨碍保存无关备注。 |

例：用户选择 B 项目的综述报告时，选择器返回 B 的定位；保存到 A 的 sources 字段时再验证一次；同事打开 A 时用同事的身份解析。对 research_file 的 list 或 download 不能从 research_session 的 read 推导。review_report 的 current 仍遵守来源端的报告状态和修订门槛。

### 7.2 按对象绑定读取知识

令 O = M/objects/{object_id}。宿主验证对象属于路径中的项目与模块，使用服务端保存的 knowledge_version_id 构造[知识读取上下文](06_agent_knowledge_services.md)。以下 GET 操作均只读。客户端另传版本替代绑定属于非法输入；游标也绑定对象和版本，过期后从同一版第一页重新开始。

| 路径 | 结果与校验 |
| --- | --- |
| O/knowledge/members | 返回 knowledge_version_id、该快照的成员投影和分页信息。已发布空版返回空页；不可访问的绑定返回不可用错误。 |
| O/knowledge/members/{member_id} | 返回该版清单所固定的资产修订与可见详情。相同论文在别版的修订不能替代；非成员按不可披露处理。 |
| O/knowledge/evidence/{evidence_id} | 校验来源项目、对象绑定、成员修订及定位后返回可读证据，区分历史定位是否可解析与当前用户是否可读。 |
| O/knowledge/members/{member_id}/file-access | 为绑定版内的文件签发受权代理读取地址；实际传输复核对象、模块代次、版本成员、文件修订和当前权限，不能经裸地址绕过。 |

查找 B 项目的会话或报告走 §7.1；上述四个操作只消费目标对象的知识版本。两条路径的资产标识不能互换。

## 8. 并发、失败与验收

宿主记录项目、模块、所用定义、对象及版本依赖。每次改变启用状态或采用定义均换发执行代次；请求开始时取得代次，提交或交付时再核对。停用后又启用也不能让前一代次的迟到写入成功。停用和定义升级保留对象及版本依赖。宿主只持有授权读取和模块自身存储端口，Construction 专用的发布命令不属于扩展协议。

| 场景 | 可观察结果与禁止副作用 |
| --- | --- |
| 重复或竞争创建 | 同主体同键同参只创建一个对象和一条版本依赖；同键异参返回 409。依赖登记失败时对象不可见。 |
| 两人编辑同一备注 | 第一笔成功后，持旧修订的第二笔返回 412；可重新加载并人工合并，服务端不自动覆盖。 |
| 停用 → 重启用 → 旧请求提交 | 旧代次失败，原记录保留；新请求可继续操作。旧下载授权不能绕过实际传输检查。 |
| 扩展读取越权或伪造来源 | 以有权项目 ID 搭配他项目资产 ID、用资产列表游标切换来源、用会话授权下载文件均失败，不暴露标题、字节或计数。 |
| 升级与保存交错 | 新增字段后旧值可读；旧表单需重载。改字段类型的升级被拒，原定义和人工记录仍可用。 |
| 资产修订不可用 | fixed 显示不可用，current 显示来源当前可读稿。用户可保存其他字段，失效引用不能变为知识版本内的证据。 |

本节为后续需求测试的输入和预期结果；实际 HTTP 注册、数据库迁移、来源适配与端到端验收分别留在实施任务中。

## 9. 首版模块定义的项目归属

2026-11-04 用户决定：首版仅支持在项目内创建自定义模块。定义及其修订归登记时的项目，启用、停用和升级只在该项目生效。需要在另一项目使用相同布局时，用户须在该项目独立创建模块。首版不提供模板复制、共享定义、导入或跨项目升级入口。

验收示例：同一用户拥有 A、B 两个项目，在两边分别登记 evidence_matrix 应获得不同的 module_id。升级 A 的字段后，B 的定义与对象保持原样。在 B 的模块管理路径中使用 A 的 module_id 返回 404，不修改任一项目。B 的模块仍可通过 §7.1 读取该用户有权访问的 A 项目会话、文件和报告；B 的知识读取继续遵守自身对象的版本绑定。
