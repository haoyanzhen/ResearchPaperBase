# Quality & Observability 设计

文档版本：v1.8
更新日期：2026-10-16
依据文档：`00_layers.md`、`01_functional_requirements.md`

## 1. 设计目标

质量与可观测设计保证 P0/P1 用例可测试、长流程可诊断、Provider 失败可分类、内容保护可验证、版本绑定可追踪。

## 2. FR 闭环要求

每个 P0/P1 FR 至少追踪到：

```text
UI / 后台入口
  -> Application Use Case
  -> Domain / Agent / Knowledge Rule
  -> Persistence or External Adapter
  -> AuthZ / State / Lock Check
  -> Test Case
  -> Diagnostic Signal
```

## 3. 测试分层

| 层 | 测试重点 |
| --- | --- |
| Domain | Project 状态、Knowledge Version 绑定、内容保护、最后管理员、论文身份去重 |
| Application | 权限、配置快照、锁、幂等、状态推进、调度跳过 |
| Agent/Knowledge | 检索归一化、评分、解析降级、Graph-RAG 引用、结构化输出校验 |
| Infrastructure | Provider 错误分类、文件签名、向量/图谱同步状态、邮件发送 |
| API | 响应信封、SSE 结束、错误分类、文件不泄漏路径 |
| UI | 禁用态、对象切换、上下文恢复、引用跳转、安全空态 |

## 4. P0 测试清单

- 用户注册登录、禁用账号拒绝、首位管理员并发。
- 用户 LLM/数据源配置保存、连接测试、密钥脱敏。
- 系统基础连接/安全配置；P1 白名单、系统速率及并发限制不作为 P0 验收前提。
- Project 创建、编辑信息、归档、软删除、私人资产清理预览。
- Workspace 进入检查和 Knowledge Version 缺失禁用态。
- Construction Run 单 Project 写锁。
- 多源检索失败分类、去重评分、PDF 解析降级、入库建图、版本发布。
- Research 流式回复锁、引用保存、版本绑定。
- Review 大纲确认、章节写锁、内容覆盖保护、终稿生成。
- 文件访问鉴权与跨 Project/版本 ID 混用拒绝。
- [04-01](04-01_p0_operation_contracts.md) 的 P0 操作验收及 [04-02](04-02_transport_task_file_contracts.md) 的幂等、取消、SSE 回放、上传/下载场景；必须验证错误请求不产生业务副作用。
- FR-034 单一终稿生成/默认接受/显式拒绝、P0 单稿 Markdown 下载；通用导出中心、批量和 PDF/Word 转换按 FR-019 的 P1 验收。

### 4.1 不可变快照一致性验收

本表为后续自动化验收要求，非已执行结果。依据 [02-02 §2.5](02-02_construction_versioning_appendix.md#25-不可变逻辑快照与资产复用边界)、[06 §3.1](06_agent_knowledge_services.md#31-版本读取与存储适配契约)及 [07 §5.1–5.3](07_data_persistence.md#51-资产原子单元与修订闭包)。适用于 P0 知识链路；通用恢复、导出等扩展链路在对应 P1 实施时执行，不提前分期。

| 编号 | 场景 | 必须断言 |
| --- | --- | --- |
| KV-I01 | V12 任务检索后发布 V13，再读取正文/分析/图谱 | 全链路及子任务仍 V12，不能读到 V13 新论文或边 |
| KV-I02 | 两版复用 A，V13 在已发布移除后重新导入 B/分块/分析 | A 同修订复用；B 新修订；V12 内容、定位、元数据与校验值不变 |
| KV-I03 | 全局高分候选在 V13、V12 候选分数较低 | V12 在自身范围检索排序，不因先全局 top-k 再过滤丢失结果；图谱每步均过滤版本 |
| KV-I04 | 发布发生在分页/缓存/异步排队之间 | 游标、缓存和 Worker 均保持原解析版本；过期游标重开不默认升级；缓存命中后撤权仍拒绝 |
| KV-I05 | 外部写入失败、延迟可见、发布提交响应丢失 | 无半版本；只认一个发布决定；默认指针/Run/发布事件一致；孤立候选不被正式读取 |
| KV-I06 | 取得读取保护与清理交错；租约到期后旧 Worker 仍活跃 | 只有一方取得资格；保护失效后旧 Worker 不可继续读/提交；共享资产不被误删 |
| KV-I07 | 旧证据损坏、权限撤销、明确删除 | 安全失败及允许的诊断，不用新证据替换；不泄露其他 Project 内容 |
| KV-I08 | 引用 ID/定位跨版本复用、模型或切片配置变化 | 拒绝错误映射；不同派生输入不能当作未变产物复用 |
| KV-I09 | 适配器替换、调用缺少 ReadContext | 同等隔离与身份契约；能力不足或缺上下文则拒绝，不能降级为最新集合查询 |

实现时使用可控并发屏障和故障注入证明上述交错，不能只依靠顺序 mock 测试。数据库测试必须显式隔离，外部 LLM/论文/邮件默认 mock；真实存储适配验收使用明确的独立测试目标，不写业务库。接口契约测试和真实存储集成测试不能替代最终端到端验收。

### 4.2 引用有效性与版本选择验收

以下为设计验收要求，未执行实现测试；P0 基础引用/选择不将 FR-031 的 P1 图谱浏览增强或 P1 导出/恢复提前。相关扩展在原分期实施时覆盖。

| 编号 | 场景 | 断言 |
| --- | --- | --- |
| KV-C01 | V13 在移除后重新导入正文/切片或排除论文 | V12 引用仍定位原修订；旧版正常可读，不判失效 |
| KV-C02 | 两版共用正文，或仅 DOI 相同 | 新研究引用必须属于目标版；相同 DOI 不绕过修订/成员核验，原引用与确认不变 |
| KV-C03 | 同用户两个 Project、相同哈希、拼接证据 ID | 仍逐项检查 Project 与成员，拒绝跨项目注入/泄漏 |
| KV-C04 | 撤稿、更正、临时故障、永久缺失、凭据过期 | 风险与可读性独立；临时故障重试同证据，凭据重新鉴权不换修订；非成功沿用安全错误 |
| KV-C05 | 引用可解析但论断被编辑 | 不自动判定支持，不继承旧人工确认；未复核明确标记；不设严格覆盖率，学术支持问题只提供建议 |
| KV-V01 | 新建、继续、历史核查、采用更新 | 分别默认最新、绑定版、原证据版、显式目标新对象；浏览不改绑定 |
| KV-V02 | 已选 V13 后发布 V14 | 显式创建仍 V13；无指定版本才事务解析最新；目标不可用失败不换版 |
| KV-V03 | 累计版本、手工补充、revision_only、来源部分失败 | 本轮窗口不冒充累计完整覆盖；无新检索不刷新截止；失败/未知不显示为完成 |
| KV-V04 | 摘要降级、资料、未知统计、零成员 | 论文来源桶互斥且合计正确，资料分开；未知不当 0，不提供伪完整度/质量评分；空版可浏览并创建 Research/Review，提示无证据且不换版 |
| KV-V05 | 最新版本暂不可用/撤权、已有固定范围 | 不自动降级或泄漏版本摘要，允许显式选合法历史版；固定不屏蔽重要风险或冒充截止认证 |

契约测试覆盖 04-01 §5.1 条件必填及错误映射；UI 验证事实标签、绑定提示与并发发布选择；真实解析/存储及端到端验收须另行执行，文档检查不替代运行验收。

### 4.3 R1–R4 已批准边界验收

以下为后续自动化与端到端验收设计，未执行；使用隔离数据库与默认 mock 外部服务，真实集成须独立明确目标。

| 编号 | 场景 | 必须断言 |
| --- | --- | --- |
| API-R01 | 连续同源陈述、原创推论、坏引用标记 | 无段落配额/豁免/strict；坏标记保留正文、展示问题且不注册有效证据；语义审查不宣称科学正确 |
| API-R02 | 空版本新建 Research/Review 并检索 | 创建成功且绑定所选空版；无证据提示、无伪引用、不暗中回退历史版；无版本/越权仍拒绝 |
| API-R03 | 终稿保存、双窗口竞争、迟到生成 | 唯一正文及派生元数据同修订；过时保存不覆盖，失败/迟到任务保留人工稿；无独立快照按钮 |
| API-R04 | 完成与编辑/任务启动竞争，拒绝稿编辑 | 原子裁决，完成后只读；rejected 不由保存复活；未解决审查建议不阻断完成 |
| API-R05 | Markdown 下载期间编辑/拒绝/撤权 | 一致读取指定当前修订，失配 412；鉴权时拒绝稿/越权不可下载；已下载副本不假称撤回；无模型调用 |
| API-R06 | 单条/批量/全移除与已知冲突构建 | 一次风险确认绑定成员修订及冲突运行；先撤销旧写资格再交接，旧 Worker 不发布；未知冲突重预览，不取消无关研究 |
| API-R07 | 排队新增成员、重复请求、移除失败 | 删除集合不扩大，重复重放；失败默认版本不变，无部分成功；旧引用依赖不阻断关联移除 |
| API-R08 | 全排除且无剩余资料/仍有资料 | 前者 published 空版、完整空视图且切换指针；后者非空；失败/零新增不冒充主动清空 |
| API-R09 | 论文及资料入库确认前后编辑 | 受理前修改使相关处理/确认失效，受理后锁定；已入库无 metadata/text/analysis 绕行；失败保留草稿，不新增 P0 原 Run 恢复 |
| API-R10 | 同 DOI 移除后显式导入/自动命中 | 新导入可成功且不继承确认，旧引用不变；全局身份不重复、无重复活动成员；自动命中不恢复人工排除 |
| API-R11 | 返回检索阶段/配置/预算变更 | 只在筛选等待点追加确认词，原词/来源/时间/总预算/基线不变且只耗剩余额度；入库确认后拒绝，不混同 P1 恢复 |

## 5. P1/P2 测试清单

- 自动调度重复触发、无自动检索词跳过、已有 active Run 延后。
- 邮件推送空邮件保护、多收件人偏好、SMTP 不可用。
- Export Job 生命周期和授权下载。
- Research 总结与导出。
- Review 版本历史、差异和回退。
- 观点广场搜索、删除、管理员隐藏。

## 6. 错误码原则

| 前缀 | 含义 |
| --- | --- |
| `AUTH_` | 认证和会话 |
| `PERMISSION_` | 权限 |
| `STATE_` | 状态不允许 |
| `CONFIG_` | 配置 |
| `LOCK_` | 并发锁 |
| `PROVIDER_` | 外部 Provider |
| `VALIDATION_` | 输入或输出校验 |
| `VERSION_` | Knowledge Version |
| `STORAGE_` | 文件、向量、图谱同步 |

HTTP/code/category 映射及安全 details 字段以 [04](04_api_contracts.md) 为唯一协议来源。details 仅向有权限的调用者展示脱敏原因和资源引用，不能把内部日志或 Provider 原始错误作为响应；管理员权限不扩大诊断可见范围。

## 7. 日志与指标

日志字段包括 `request_id`、`user_id`、`project_id`、`use_case`、`run_id/session_id/review_run_id/job_id`、`status`、`error_code`、`duration_ms`、`provider`、`attempt`。

不得记录密钥明文、完整 PDF 文本、敏感用户输入或真实文件路径。

建议指标包括 Construction Run 成功率、Provider 限流和失败次数、PDF 解析降级率、Knowledge Version 发布成功率、Research SSE 中断率、Review 章节重试率、邮件推送成功率。

## 8. 诊断快照

用户可在本人有权访问的 Run/Session/Job 详情读取脱敏快照；P0 不开放管理员读取用户 Project 快照的接口：

- 当前状态与阶段。
- 配置快照脱敏摘要。
- 锁信息。
- Provider attempt 和错误分类。
- 同步项状态。
- 最近日志摘要。
- 可恢复动作建议。

普通用户只能读取自己 Project 的诊断。P2 管理员系统诊断只可读取后端按 FR-006 形成的脱敏系统级信息，不可直接读取用户 Project、个人配置或原始任务快照。

## 9. 健康检查

- `GET /health/live`：进程存活。
- `GET /health/ready`：数据库、文件存储、队列基础可用。
- 管理员配置测试：LLM、数据源、SMTP、向量库、图谱存储。

公开健康检查不得泄漏配置细节。

## 10. 验收门槛

- P0 用例有自动化测试或明确测试入口。
- 长任务失败不会只显示“未知错误”。
- Provider 失败不会混入成功结果。
- 终态提交后提供可查询/回放的 done/error 事件；连接中断不保证收到事件，必须能用持久状态与游标恢复，不能要求以重新执行业务补事件。
- 内容覆盖、版本采用、锁冲突均可被测试复现。
- 并行构建的候选隔离、完整发布、旧研究稳定绑定、重复提交、迟到写入拒绝、人工修订保护、导出通知范围和旧证据保留，按 [领域附录](02-02_construction_versioning_appendix.md) 的验收场景细化测试；文档检查不等于这些实现测试已经通过。

- [02-02 第 10 章](02-02_construction_versioning_appendix.md)的转换与验收矩阵为现行设计入口：逐项覆盖 Run/attempt 失败区分、排队无槽与暂停保槽、可信恢复、候选修订失效、两种成功结果与取消排他、迟到 Worker 和重复请求；恢复执行仍按 [02-04](02-04_run_recovery_appendix.md)及 P1 分期。
- published 验证版本可见性、Run 成功和默认指针一致；no_change 验证既有版本及核验范围/时间可追溯，不生成新版本、不切默认、不发送升级提示或空邮件。首次无版本、Provider 失败或未完成核验不得通过无变化成功断言。
- failed 后放弃恢复保持失败统计并关闭恢复资格；暂停显式重跑旧 Run 取消原因与新 Run 关联可追溯。 定向交接同时覆盖 02-02 S27 的新 Run 创建/准入失败或显式取消分支：已确认旧 Worker 失权后关闭预约；结果不确定时不开放槽、不复活旧 Run。attempt 失败率、Run 失败率、published 数与 no_change 数分别统计，不把通知失败反写成功构建结果。
