# Security & Permissions 设计

文档版本：v1.8
更新日期：2026-10-21
依据文档：`00_layers.md`、`01_functional_requirements.md`

## 1. 设计目标

安全设计覆盖认证、授权、用户隔离、管理员边界、密钥保护、文件访问、archived 只读、审计和高风险操作确认。最终判定必须在后端 Application Use Cases 中完成。本文细化现行01/02/04/05/06/07及用户已确认的SEC规则；新增资料读取选择仅限已确认范围，不自行扩大角色、权限、确认动作或分期；公开端点和错误结构仍由04唯一维护。开发Agent的执行授权遵循AGENTS.md，不由产品权限推导。SEC-D01/03已按第12节确认；SEC-D02详细策略独立于[08-01专题](08-01_agent_data_access_policy.md)，Q1–Q4已确认，工程接入不等于已通过运行验收。

## 2. 认证

- 注册时密码必须哈希存储。
- 登录可使用用户名或邮箱。
- 禁用账号不得登录。
- 已禁用账号的既有会话在下一次鉴权或刷新时失效。
- P0 公开入口为登录、注册、CSRF 引导及最小健康检查；密码找回为 P1，未实现不得暴露不可用入口。
- 同源 Cookie、CSRF、SSE 逐次鉴权和下载代理协议以 [04](04_api_contracts.md) 及 [04-02](04-02_transport_task_file_contracts.md) 为准；禁用后不得通过事件回放、历史任务或文件地址继续获得私人内容。

## 3. 权限模型

| 资源 | 普通用户 | 管理员 |
| --- | --- | --- |
| 自己的 Project | 可读写，受 Project 状态限制 | 不默认拥有，除非另有共享规则 |
| 其他用户 Project | 不可访问 | MVP 不提供越权查看 |
| 用户个人配置 | 仅本人可读写 | 不可查看他人个人配置；系统可选模型安全投影不等于配置详情 |
| 系统配置 | 不可访问 | 可读写和测试 |
| 用户账号状态 | 仅本人基础信息 | 可启用、禁用、删除普通用户、修改邮箱、重置、授予/撤销管理员 |
| 观点（P2） | 可发布/删除本人观点，查看公开观点 | 可隐藏观点；P0 不开放 |

至少保留一个启用管理员，且并发变更时仍必须成立。管理员删除普通用户按 FR-005 处理其账号、Project 和关联私人数据，不删除其他用户数据或共享论文身份；不是取得用户 Project 内容查看权。

管理员重置密码仅首次成功响应可返回本次生成的新密码，不得读取原密码；响应不缓存、不日志，不进入通用幂等明文缓存。响应丢失与重复提交按 04 的敏感结果例外处理。

### 3.1 授权判定矩阵

所有判定从可信ActorContext和服务端归属关系取得事实；客户端提供的owner、Project、版本或available_actions不构成授权。以下按操作族索引，具体具名用例及例外引用04-01，不复制端点清单。

| 操作族 | 主体与允许条件 | 必须拒绝及不得发生的副作用 | 依据 / 测试 |
| --- | --- | --- | --- |
| Project读取、知识与引用 | 当前有效Owner；资源、版本、成员组合均属同Project；生命周期允许读取 | 非Owner/管理员越权、组合错配不泄漏对象；不改绑定、不生成内容 | 04-01 §3/5、07 §4；SEC-01/02 |
| Project业务写入 | 当前Owner、允许写入的Project/业务状态、有效修订及适用确认；提交时重验 | archived/deleted、旧修订/确认、失权attempt不写业务事实、不发布；确认不能解禁非法操作 | 04-01、05、07 §5/6；SEC-02/03 |
| 个人配置与配置测试 | 本人配置；按选定Provider和配置执行；测试不等于保存或启动业务任务 | 管理员不能读取他人个人配置；失效选择不自动换用系统模型；不泄漏密钥 | 04-01 §2配置操作、05配置解析；SEC-04 |
| 系统配置与账号治理 | 当前管理员及对应治理目标条件；修订/确认按04；至少一个启用管理员 | 非管理员拒绝；不能借治理读取私人Project；敏感重置结果不被重复回放 | 04-01账号/系统操作；SEC-01/04 |
| Task、输出快照、SSE | Project任务按当前Project权限；配置任务按配置归属/管理员系统权限；逐次读取/回放鉴权 | 知道task_id、旧游标、旧会话不授权；不因读取再次调用Provider | 04-02 §2/3；SEC-02/05 |
| 文件与当前终稿 | file-access与实际下载分别鉴权；正式资产核对版本，补充/候选核对各自scope；终稿须accepted及匹配当前revision | 不把候选当正式证据；不通过旧链接访问deleted/rejected目标；不拼接别版字节 | 04-02 §5；SEC-05 |
| Workspace上下文 | 当前用户+Project；active允许保存，archived仅读服务端上下文，本地输入按UI保留 | 上下文不能写正文或恢复业务写权；不能读他人上下文 | 04-01 §3、03；SEC-02 |
| 治理删除与私人资产清理 | 对应治理主体、已预览确认的范围、当前资格与共享依赖约束 | 不扩大到未确认冲突、不删除他人引用/全局身份；清理失败不复权、不伪报成功 | 04-01、05 §12、07；SEC-03 |

权限不足或对象不可披露时按04的防枚举规则返回；已授权的状态、修订、版本和文件错误按各操作契约返回，不把所有拒绝统一改成403或空成功。P1导出、P2协作/观点沿原分期单独验证；P0不构造未来角色权限。

### 3.2 检查位置与时机

| 边界 | 校验责任 | 失效处理 |
| --- | --- | --- |
| API受理 | 应用核验当前身份、资源祖先归属、操作状态、修订与适用确认 | 不创建被拒业务任务、不调用外部Provider；认证/幂等例外按04 |
| Worker领取及外部调用前 | 从持久命令恢复主体和范围，重验当前权限及attempt资格；不信任序列化的旧授权 | 停止该失权执行的新调用，记录安全原因；已经发出的外部请求结果按受控提交裁决 |
| 结果提交 | 应用在07的原子边界重验账号/Project、执行epoch、输入/内容修订、确认依据及版本 | 旧Worker结果不能写入或覆盖；临时产物按既定清理协议处理 |
| 读取、缓存、SSE和下载 | 应用与受控读取端口校验当前权限和完整归属；缓存/游标不携带永久授权 | 不从缓存或重放泄漏旧授权内容；流终止/快照按04-02处理，不宣称撤回已交付字节 |

前端隐藏按钮是交互提示；Agent、Provider及存储适配器不能代替应用批准业务动作。授权事实与执行资格不是同一概念，两者都有效才允许提交；锁和失权竞态复用07，不在本文建立第二套事务协议。

## 4. Project 状态权限

- `active`：允许正常读写；是否参与自动调度由 Construction Workspace 自动更新设置决定。
- `archived`：默认只读；新建、启动、继续生成、上传、删除、重跑、基于新知识创建关联会话或新版综述等写操作拒绝。
- `deleted`：不可进入 Workspace，不参与调度。

P1 导出历史内容可作为 archived 的允许动作，但仍需权限校验。P0 Workspace 上下文保存范围见 04；不得借显示偏好改写 Project/Run/Session。运行中归档、删除或清理仍须遵守 02-02 的当前权限/生命周期检查，终结按04-02 §2的D04 A：管理生效撤销资格并安全终止，既有终态不重写，清理失败独立呈现且不恢复旧资格。

## 5. 密钥、配置与数据流向

API key、SMTP密码和系统密钥不得明文持久化、返回前端或进入日志/事件。密钥由受控Secret Store或加密保管机制保存，配置只持有引用；只有既定授权执行的适配器在调用所需期间取得凭据，不把凭据拼进模型prompt。用户密钥不能用于其他用户任务，管理员不能读取用户私人密钥明文。

系统配置可按既定选择规则提供可用能力，不允许在选定模型/配置失效时静默回落。配置保存、连接测试成功、任务可启动是不同事实；修改配置不改历史运行快照。

| 数据 | 合法使用与持久化边界 | 对外/诊断边界 |
| --- | --- | --- |
| 内部运行配置 | 固化已解析的配置修订、模型、参数和来源依据；凭据保管独立，历史快照不授予当前调用权 | API RuntimeConfigSnapshot严格按04-01返回，无密钥/认证参数；不能仅存展示名称而丢失重现所需参数 |
| 模型/数据源请求 | 应用为具名用例组织当前已授权范围及固定输入/版本；Provider端口不得自行跨Project抓取上下文 | 任务需要的业务正文与凭据通道分开；文件读取分级及派生内容边界见08-01；执行仍须当前授权，不能宣称脱敏后任意数据均可发送 |
| 业务正文/证据 | 存入所属业务对象或受保护输出，按版本、归属和当前权限读取 | 不进入通用日志、审计、内部事件或公开探针；任务输出与诊断元数据分开 |
| 缓存/检索 | 复用07的Project、版本、修订与配置键；读取重验授权，检索在限定范围内执行 | 命中缓存不授予旧权限；不以全局top-k后过滤替代隔离 |
| 日志/事件/审计 | request/command/task/attempt关联、安全错误分类、动作和结果；引用可查但受权 | 不包含明文密钥、完整私人正文/输入、物理路径或原始Provider错误；不得通过诊断给管理员私人内容访问权 |
| 密码重置 | 仅首次成功响应按04例外提供新密码，旧密码不可恢复 | 不缓存/日志/通用幂等明文重放；响应丢失按既定敏感结果例外处理 |

配置快照不是Secret Store备份。凭据撤销/轮换后的历史任务如何取得可用凭据应遵守现行配置可用性规则，不用保存旧明文保证重试；简化的凭据更新规则见第12.3节。已有04-01诊断保留默认值只用于可清理诊断，不能据此删除冻结输入、人工确认或引用依赖。

## 6. 文件访问安全

- PDF、解析文本、Graph 文件和导出文件通过对象 key 管理。
- P0采用04-02规定的同源鉴权代理下载流，不提供绕过当前鉴权的存储直链；短期签名URL不是本期可自行选择的替代协议。
- 错误精确沿用04-02：不存在/越权安全404，已授权版本错配409，已授权文件丢失410；终稿缺失/失配修订为428/412。安全空态是UI呈现，不替代错误协议。
- 不得暴露本地真实文件路径、桶内部路径或其他 Project 上下文。
- 当前权限优先于历史配置或版本快照；发布、导出、下载及接管操作必须校验当前权限与对象状态。自动更新授权不授予旧研究迁移或人工覆盖权限，接管也不扩大现有 Project 权限。详见 [领域附录](02-02_construction_versioning_appendix.md)，本轮 P0 访问协议见 [04-02](04-02_transport_task_file_contracts.md)，P1 导出及完整文件生命周期仍待细化。

## 7. 高风险操作

以下仅索引上游已规定的确认或影响预览。是否使用Confirmation及其绑定字段以04对应操作为准，普通保存不新增确认。确认不能授予权限或解禁上游禁止的操作：

- Project 归档、软删除和私人资产清理。
- 用户邮箱修改、重置密码、授予/撤销管理员、启用/禁用和删除（03-01 P10a）。
- 撤销管理员权限。
- 上游明确允许的人工内容覆盖；不能据此修改已入库资产、已完成Review或绕过当前修订保护。
- 手动触发会覆盖导出产物的再生成。
- 批量清理 PDF、向量索引、图谱或运行记录。

## 8. 审计

至少记录管理员用户治理、系统配置变更、Project 状态变更、软删除和私人资产清理、密钥配置创建/更新/删除的脱敏事件、内容覆盖确认、自动调度创建/跳过/失败、管理员隐藏观点。

审计字段包括操作者、目标类型、目标 ID、动作、结果、时间和脱敏元数据，并关联适用的request/command/task/attempt。自动调度、通用导出和观点审计仅在对应P1/P2实施；不为补齐审计提前开放功能。

## 9. 安全测试入口

测试唯一明细见[09 §4.4](09_quality_observability.md#44-安全与交付细化用例)。SEC-01–06分别覆盖授权、失权、确认、数据流、文件及不可信内容，复用ARC-02/04/07/10与MOD-01/02/03/09。每项检查允许/拒绝、持久状态和未发生的副作用，不能只断言HTTP状态。产品待决项不写假定预期，记录为待决策后补测。

## 10. 本轮协议衔接与限制

04维护公开协议，05/05-01维护应用提交及类型化边界，06维护服务输入输出校验，07维护原子裁决与数据隔离。本文将其串成安全契约，不新增端点或角色。管理员诊断后台仍P2；脱敏不等于获准读取私人Project原始任务快照。上述均为设计要求，尚无新核心安全实现或渗透验收。

## 11. 不可信内容与工具边界

上传文件、论文正文、检索结果、模型输出是业务数据，不能声明ActorContext、人工确认、Project权限、执行资格或命令白名单。模型提出的动作只作为ServiceProposal，由具名应用入口校验；不能把正文中的“忽略规则”“读取其他项目”等文字解释为权限变化。

结果按06/05-01执行结构、引用归属、来源修订及写入范围校验；合法内容也不能绕过人工保护。对工具的请求只能使用服务已有端口和本次受控scope，不能直接调用任意函数、SQL、shell或路径来提交业务。此约束不禁止论文讨论代码或命令，只禁止将其当作可执行授权。

文件接收及解析严格复用04-02格式白名单、字节限额、路径穿越和解压检查；HTML不执行脚本，Office不运行宏，notebook/code只静态提取。读取文件不触发远程重新下载、解析或模型。出站网络与Provider策略按第12.2节；解析器默认无网络、仅本次输入及专用临时目录，元数据联网补全经独立数据源端口。具体隔离实现仍需验证，不能把“静态解析”当作已证明隔离。

## 12. 待人工决策的政策

本节标题保留以兼容既有引用。2026-10-20用户已确认SEC-D01的“可用性校验＋简化B”和SEC-D03简化方案。SEC-D02的Q1–Q4于2026-10-21全部确认，决定见[08-01第8节](08-01_agent_data_access_policy.md#8-已确认决定)，剩余工程及P1问题见该文第11节；TRACK-021继续跟踪接入。

### 12.1 SEC-D02 资料读取分级

默认Agent只读取公开资料，包含公开论文全文；用户切换为允许本Project私人资料时提示风险；文件入库增加公开/私人信息。public不授予跨Project共享权限。设置作用域、分类来源/修改、派生内容、混合上下文及在途行为在[08-01](08-01_agent_data_access_policy.md)唯一维护；该文件维护已确认Q1–Q4（Q4双向立即生效）及剩余接入工作，不在本主文复制细节。

### 12.2 SEC-D01 可用性校验与简化网络边界（已确认）

保存配置与验证可用分开。保存时只做字段、URL及受支持适配协议的结构校验，不隐式发起网络/模型调用；合法配置可保存为未验证。测试失败保留可编辑配置，不统一报“无法解析”。

显式测试按以下边界实施：

1. 请求先经过部署网络策略，探测本身不能绕过。Provider公网端点使用HTTPS；本机/内网目标（包括必要HTTP）由部署配置显式登记目标及端口，用户个人配置不能扩大该范围。公开资料下载可使用受控HTTP/HTTPS，逐次检查真实解析/连接目标与重定向，不把Provider测试许可扩成任意URL代理。
2. 按适配器协议获取模型列表；列表不可用或为空时允许手工填写模型ID，不将其等同于推理服务不可用。是否接受特定ID仍由模型测试和实际调用验证。
3. 对选定模型使用固定非业务测试文本进行显式最小推理测试，提示可能产生调用费用；不发送Project正文或查询已有资料。一次模型成功不能把该Provider所有模型标为可用，也不证明流式、工具或其他能力均可用。
4. 结果区分格式/协议、认证、网络、模型、额度/限流等安全错误；记录测试时间及对应配置/模型/凭据修订。配置或凭据改变后旧结果不证明新配置有效；历史成功不替代实际调用的错误处理，不擅自增加每次任务前收费探测。

解析器默认不出站，仅访问本次输入与专用临时目录；不能访问应用密钥或其他Project文件。网络元数据补全是另一个受控端口。具体连接地址校验、隔离工具和超时沿既有技术限制实施并测试，不增加P1模型白名单后台或管理员私人内容权。

04已有保存、连接测试和模型刷新入口，但手工模型、选定模型最小测试及测试状态所需的精确字段/操作映射仍需实施前校准；本节不冒充当前OpenAPI已覆盖。调用凭据只交给其对应服务，不随跨目标重定向转发。

### 12.3 SEC-D03 简化凭据处理（已确认）

用户维护个人模型/论文源凭据，管理员维护系统和SMTP凭据；应用负责隔离保管、真实失败诊断及保护已完成成果。不为任务复现维护历史API key，不把普通凭据轮换做成新业务流程。

任务仍固定已选Provider配置身份、端点、模型、参数和输入；认证材料独立解析。在同一配置归属和绑定服务不变的前提下，下一次调用可取得该配置当前有效凭据；不能仅因key字符串改变就强制任务失效。配置所有者、端点、模型、认证模式或配置身份变化不是单纯换key，不能借此静默改变既有任务绑定。无可用凭据或实际调用失败时按现有错误/失败规则处理，由用户修复；不换用他人、其他配置或系统凭据，不新增P0通用重试/恢复入口。

已发请求不能撤回；凭据更新不自动撤销业务执行资格，结果提交仍按当前权限、输入修订和执行资格校验。SMTP失败不撤销知识发布；Provider外部撤销与本应用删除保存值是不同事实。

安全保管仍遵循01 FR-006/007及07：Secret Store或加密存储，明文不进入配置快照、日志或前端。若实现使用本地加密密钥，它只负责保护凭据密文，由部署环境保管并满足10的恢复要求；不是要求加密全部论文，也不是普通用户管理功能。具体存储产品/轮换方式留给工程设计，不设旧API key保留窗口或新增密钥管理后台。
