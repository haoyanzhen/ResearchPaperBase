## 1. 权威范围与已确认决定

本专题是SEC-D02详细策略的唯一维护位置。用户已确认：默认仅允许Agent读取公开资料，包含公开论文全文；用户可以选择允许本Project私人资料，切换时提示风险；文件入库增加公开/私人信息。正文长度不是权限边界。

以下边界沿用现行01/02/04/08：Project归属与当前权限始终有效；标记公开不向其他用户分享Project文件/私有分析；管理员不因此获得私人内容读取权；KnowledgeVersion与历史证据内容不被改写；Agent不能自己扩大权限或代替人工确认。

2026-10-21用户确认Q1–Q3采用A、Q1配套边界，以及Q4双向立即生效及其限制。第3–7节为现行资料策略；第8节保存决定，第11节区分已闭合政策与未完成的工程契约，不将已定事项重复列为待决。

## 2. 为什么不能完全独立于其他设计

可以独立维护策略细节，不能独立完成端到端实现。权限会影响候选分析、向量生成、检索、会话历史、模型调用及缓存；只在文件下载入口增加开关会留下旁路。

把“资料是否允许供本次Agent执行使用”作为现有授权的附加判定，而不是另建Project权限体系。基本判定顺序：

```text
当前主体及Project权限
  → 原有业务状态 / 版本或候选范围
  → 本次执行的资料读取政策
  → 资料及其来源依赖是否满足政策
  → 受控读取 / 上下文构造 / 外部调用
```

取得文件ID、DOI、缓存命中或全局论文身份均不能跳过判定。KnowledgeVersion继续固定知识事实；资料政策是当前使用资格，不能靠“历史时曾允许”永久绕过限制。

## 3. 设置作用域与执行边界

### 3.1 用户与Project作用域

按 `(user_id, project_id)` 保存持久选择：仅公开资料 / 允许私人资料。新作用域默认仅公开资料；切换到允许私人资料时显示会读取哪些类别、当前选择的Provider及可能发送相关内容的风险。选择不能保存在Workspace显示上下文中，否则恢复UI可能恢复业务授权。

不推荐首版使用用户全局开关：在A项目打开后容易意外影响B项目。也不推荐只存在单次请求的布尔值：后台排队、跨页面构建和长会话需要可追溯的依据。P2协作不能继承另一个成员的个人授权，具体角色仍按既有分期设计。

### 3.2 执行采用与后续变更

双向立即生效：每次受控读取、上下文发送及业务结果提交依据当前资料政策判定，不再取“受理时权限上限”与当前权限的交集。受理时政策修订只用于审计，不构成冻结上限或永久授权。

- 开启私人权限后，已排队或运行中任务的下一次正常受控操作可以使用新范围；不自动重新检索、重做步骤或改写已生成结果。
- 关闭私人权限后，后续受限读取、发送和新业务结果提交拒绝；已发出的网络字节不能撤回。
- 当前Project权限、固定KnowledgeVersion、已冻结构建输入、选定对象和用户确认范围仍为独立限制。允许私人资料不把新文件自动加入本轮构建，不扩大既定输入集合。
- 已失败、取消或结束的任务不因权限放宽自动恢复；只沿既有允许的用户操作继续，不新增P0恢复入口。
- 缓存、预组装上下文和Worker持有的政策快照必须在下一边界重验；策略修订变化意味着需要重新判定，不等于所有任务一律失败。

P1自动调度以后使用其明确授权主体的当前选择和原自动执行范围，不继承其他用户授权。互联网检索来源的分类自动确认按§4.4执行；这不代替P1其他处理/分析确认策略。

## 4. 文件分类与入库流程

### 4.1 分类对象及来源

分类挂在Project内的具体文件/内容来源上，不挂在全局PaperIdentity或DOI上。公开论文可能附带私人批注；公开元数据也不证明下载的完整附件公开。物理相同哈希不能跨Project继承授权。

业务分类只有public/private两个值，另设独立的“分类未确认”事实，未知不是第三种可用权限。未确认不能当公开读取。人工上传预填private，由用户确认；P0手动流程的检索来源可提出public建议；P1无人值守互联网检索按§4.4自动确认public，并保留该份实际内容的来源依据。付费访问、登录可见、机构订阅和仅存在公开摘要，不作为全文公开依据。

文件进入系统后先完成安全接收、隔离暂存和必要静态提取，再确认分类，之后才允许模型辅助元数据生成、分析或向量化；若用户仅允许公开资料，私人文件可被接收/保存，但不能因为“正在入库”就绕过Agent读取限制。用户自己合法查看文件和必要静态接收不受此Agent附加开关限制；Agent使用仍须分类和政策判定。未确认来源必须先确认分类，开启私人权限不代替分类确认。

分类确定必须不晚于首次向模型/嵌入服务发送内容，不能拖到最终KnowledgeVersion发布。入库确认展示分类、来源依据及本轮允许使用范围；文件类别paper/material与public/private互不替代。

### 4.2 最小逻辑记录（非API字段或建表指令）

| 记录 | 需要保留的事实 | 目的 |
| --- | --- | --- |
| 用户资料使用选择 | 主体、Project、选项、政策修订、风险确认记录 | 不由前端自报授权；排队任务可追溯 |
| 来源分类 | Project、具体文件/内容修订、public/private、确认状态、来源依据、分类人/时间、分类修订 | 区别公开元数据与具体全文；支持并发更新检查 |
| 执行资料依据 | 命令/attempt、受理政策修订（审计）、每次判定的当前政策/分类修订、实际输入修订及来源依据 | 区分可动态变化的权限与冻结业务输入；外呼审计不保存正文 |
| 派生来源依赖 | 产物身份、所有实际输入来源及修订、完整性标记 | 允许判断摘要/图谱/回复是否间接含私人信息 |

不保存凭据或全文到权限审计中。具体字段、错误码、端点及与现有revision的映射由后续04/07契约收口一次落实。

### 4.3 分类更正与不可变版本

把不可变内容及入库时分类事实与“当前使用限制”分开。当前限制可收紧而不改写旧版文件/引用；读取必须重验当前限制。公开→私人需立即限制后续Agent使用，不能等新KnowledgeVersion发布才生效。

私人→公开属于放宽，仅Owner显式确认并提供依据；不能由LLM自行判定或由“没有引用私人文件”推断。按当前权限读取与已发布内容只读并不冲突，但该安全元数据更新是新操作，已由Q3批准，仍须补领域/API契约，不能借普通metadata PATCH实现。

既有无分类资产/缓存/会话的迁移须记录未确认范围，不能批量标public。无分类记录按未确认处理，保留原记录并补充分类依据；不回写历史全文或破坏引用。

### 4.4 P1无人值守互联网检索分类（已确认）

2026-10-21用户决定：互联网检索来源自动确认为公开资料，内网资料一般不参与无人值守检索。本专题将用户所称“开源”映射到已有public读取分类，不新增open_source分类，也不据此推定开源许可证、版权许可或再分发权。

- P1无人值守流程从配置的互联网检索来源取得的公开内容，自动记录public和已确认事实，不为该分类增加人工等待点。记录实际来源/获取方式、具体文件或文本修订、时间及自动确认依据；分类应在首次模型/嵌入使用前完成。
- 自动确认仅覆盖实际取得的互联网公开内容；只有公开摘要时不能把未取得或机构登录获得的全文一并标公开。沿用Q2：付费/登录/机构私有内容不能仅因服务器有公网地址或论文有公开DOI就归入公开内容。未知来源仍不得推定公开。
- 内网资料不纳入通常的无人值守检索范围，不能因内网LLM获准连接、用户开启私人资料权限或来源重定向而隐式加入。将来若明确启用内网检索，须单独定义其来源范围和授权；本条不禁止用户按现有授权手动提交内网资料。
- 自动分类不是自动共享或自动降级私人标记。人工上传预填私人及人工更正的限制保持；互联网重复命中不得覆盖本Project既有私人标记、人工排除或私人批注。若确认是独立公开来源，保留独立来源事实，按原去重/成员规则处理，不重写旧内容。
- 分类自动确认不代替基础安全接收、网络边界、用户当前权限、冻结输入、分析/入库确认或KnowledgeVersion发布条件，也不扩大P0分期。

## 5. 派生内容权限

采用可追溯依赖传播，而不是让模型自评“已经脱敏”。一个产物只要实际输入含private或未确认来源，就不能供仅公开模式的Agent使用。无来源记录或依赖不完整，也不能证明为公开；引用列表只列被引用材料，不等于全部输入来源。

| 产物 | 判定与处理 |
| --- | --- |
| 解析正文、切片、标题/摘要 | 继承实际文件/内容来源限制；提取或缩短不自动变公开 |
| 向量与索引 | 嵌入调用前先校验原文；向量及检索结果继承来源，不以“只发送向量”绕过；过滤在top-k前完成 |
| 图谱节点/边 | 按每条可追溯事实的来源校验；混合聚合且不能隔离私人成分时整体受限；不能共享节点就丢失来源 |
| 模型分析、评分、摘要 | 包含全部实际输入依赖；由公开论文加私人批注生成的分析仍受限 |
| Research回复、会话摘要、Review章节/终稿 | 含使用过的私人上下文或私人证据则受限；“本次没直接引用私人文件”不构成公开证明 |
| 缓存、工具结果、持久输出 | 保存来源依据和政策/分类修订；每次命中重验，不能把旧的公开结果直接发给新任务 |
| 用户手写问题、草稿、Project主题 | 不自动认定为公开；用户本次明确提交的文字可供本任务使用，不额外弹确认，也不授权自动抓取其他私人文件；既存主题/草稿或历史输入不能伪装本次主动提交 |

首版仅在能证明边界的产物级隔离，不强制句子级污点追踪或自动脱敏认证。部分内容可分离时可建立独立产物与输入依赖；混合产物整体受限的代价是公开模式可用材料减少。重新生成公开版本须仅使用允许输入，并走现有合法生成/确认入口，不能自动覆盖原稿或改变原KnowledgeVersion。

## 6. 会话历史、权限切换与并发

模型上下文包括历史消息、摘要、标题、草稿、工具结果，不能只过滤本次检索。公开模式下不能直接重发含私人来源的旧会话历史，也不能通过先总结再发送绕过限制。

对必须使用受限输入的具体任务明确拒绝或安全终止，保留原内容和诊断；不静默删除历史消息后继续生成。对于知识检索，仍在绑定KnowledgeVersion内按政策取允许子集，并明确“当前权限限制了可用范围”，不谎称完整知识库没有相关资料，不隐式换版。

收紧与提交并发时复用07的原子资格裁决思想：记录政策/分类修订，在读取、外呼前及提交检查；先收紧则迟到结果不得作为新的可采纳业务结果提交；已合法提交成果不因开关变化自动删除。具体Run/attempt失败/取消投影仍需接口收口；技术输出/诊断是否保留按原规则，不新增业务状态。

政策记录与分类记录具有递增修订（或等价不可复用标识），打开→关闭→再打开不能产生ABA误判。权限变更与受控操作之间必须有可测试的裁决点：

- 读取及请求派发在实际执行边界核验，不能只在创建任务或组装prompt时检查。异步派发队列在真正发送前重验；策略修改先取得裁决则后续受限派发失败。已先进入不可撤回派发阶段的请求属于在途请求，不承诺撤回；不得持有覆盖整个Provider调用的数据库事务。
- 缓存记录来源及判定依据。扩权后旧的公开检索结果不冒充新权限下的完整结果；下一次正常检索重新计算或使用匹配的缓存。收紧后旧私人上下文不能继续发送。
- 提交在当前政策/分类及执行资格的原子裁决边界重新判定。只有修订变化而实际全部输入仍允许时可重新验证后提交；不自动失败或重生成。曾被终止的attempt即使再次放宽权限仍无资格。
- 当前范围允许的读取不替代来源依赖检查；已准备上下文如有必需受限历史，明确阻断，不自动剪掉历史继续回答。

分类改变的依赖传播可以惰性重验，但公开模式不得在传播未完成时使用旧缓存。对图谱聚合或会话摘要若不能证明依赖完整，拒绝进入模型上下文。该限制只控制Agent后续使用，不能宣称撤回已发送到Provider的内容或用户已下载的副本。

## 7. 服务接缝与可独立修改范围

采用应用调用的资料策略判定接缝，返回允许/拒绝、依据修订与安全原因；服务读取可信身份、Project、执行政策、资料分类及依赖，不能接受前端提供的allow=true。以下是语义接缝，不是已新增公开端点或强制类型签名：

- 命令受理：记录当前政策修订供审计，保存冻结业务范围；执行时仍读取最新政策。
- 补充/候选处理：分类门槛位于首次模型/嵌入使用之前；已有SupplementWriteScope/CandidateWriteScope不替代资料政策。
- Knowledge读取：ReadContext携带或关联政策依据；所有检索/文件/图谱端口都执行附加过滤，不能只改prompt。
- 上下文构造：核验历史/工具/草稿及全部依赖；Provider适配器收到的是经批准的输入包。
- 结果提交：关联实际来源，核验当前政策/分类与执行资格；复用原提交机制。

网络策略SEC-D01、凭据机制SEC-D03与资料政策分别维护：允许连接某Provider不代表可发送所有资料；启用私人资料不扩大网络范围或Project角色。

| DAP-17 | 来源是内网、公开链接重定向到内网、内网模型已获准连接 | 内网不自动纳入通常无人值守范围；执行既有网络边界；模型连接许可不变成资料检索许可 |
| DAP-18 | 互联网重复命中已标private/带私人批注的资产 | 不覆盖人工分类/排除，不把派生内容洗成公开，不扩大Project共享；未知/私人登录来源不借public自动确认 |

## 11. 闭合检查与剩余工作

Q1–Q4及DAP-G04产品选择已闭合；G04由§4.4互联网来源自动确认、内网通常不纳入的规则承接。当前仍存在以下设计/工程缺项，不能把本专题称为可直接独立实现的完整接口规格：

| 编号 | 缺口 | 处理与是否需要新的人工决定 |
| --- | --- | --- |
| DAP-G01 | 04/schema尚无设置、分类确认/更正及对应错误/任务投影的完整契约 | 需按已决规则做接口收口、兼容检查；不需要重新决定Q项。不得临时用普通metadata PATCH绕过只读规则 |
| DAP-G02 | 政策/分类修订、来源依赖、缓存与dispatch/commit裁决尚无物理实现 | 类型化端口、约束、迁移、并发屏障及故障验证待实施；可以工程细化，不新增业务状态 |
| DAP-G03 | 历史资料/人工文字及混合历史的来源标记和UI提示尚未落字段 | 当前明确提交与系统自动取用必须有可信来源，不能让客户端任意标记免检；无来源不能推定公开，具体字段随G01收口 |

未知/未确认文件不能因开启私人权限跳过分类确认；历史内容不批量标public。权限开关是业务安全设置，archived仅可读的既有规则仍有效，不借本专题开放归档Project写操作。P2协作授权沿原分期另行细化。
