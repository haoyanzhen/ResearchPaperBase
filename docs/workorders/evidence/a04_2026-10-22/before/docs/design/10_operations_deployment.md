# 部署、升级与恢复的最小运行约束

更新日期：2026-10-22

## 1. 保留范围

本文只保留应用运行后难以补救的部署隔离、升级、在途任务、容量、备份恢复和发布验证。任务业务规则、数据回收资格和权限分别引用02/05、07、08，不重复维护。删除预设基础设施演进路线、泛化风险清单和P0不需要的调度/邮件配置要求。

以下是完整业务运行的实施约束，不是已验证的部署手册。工程骨架命令与限制见项目README和任务005；实际迁移、故障及部署验收随对应切片登记，不复制旧应用命令。

首版运行时、包管理、API/Worker形态及工程入口责任见[00-01](00-01_engineering_baseline.md)。工程交付和运行验证状态统一见PROJECT_STATUS，不由技术决策推定验收通过。

## 2. P0运行边界

API与Worker可同进程或分进程，使用同一受控应用入口、持久任务和执行资格协议；进程重启不恢复旧写资格，不自动将paused Run释放。关系、文件、向量和图谱适配器需满足07的隔离与可读屏障，不强制购买/部署独立产品。

环境至少区分开发、隔离测试与业务部署。显式配置关系存储、文件与索引位置、密钥保管/会话配置、当前Provider端口及技术执行限制；测试配置缺失不得回落业务环境。首次管理员按现行注册并发规则，不引入额外默认管理员账号或明文密码。

P0系统SMTP保存/连接测试不启用用户业务邮件；Scheduler、自动构建、邮件推送、通用导出为P1，P0不要求它们启动或健康。模型白名单、系统业务配额和后台诊断按01原分期，不把部署参数变成新增管理功能。

进程存活检查与就绪检查分开：就绪核对本部署实际启用的关系存储、必要文件/索引访问和任务领取能力；未启用服务不纳入。公开探针只返回安全状态，不暴露配置/对象/路径；Provider连接测试通过既定授权配置入口执行，不由健康检查发送邮件、生成内容或发布版本。

### 2.1 配置契约与启动校验

工程建立后用一个类型化配置定义作为名称、类型、单位、必需性、默认来源、敏感性、允许环境、加载优先级和重载方式的唯一来源；样例、文档及部署检查从同一来源生成或校验，不另维护相互矛盾的环境变量表。本文不提前虚构变量名。

- 存储连接/命名空间、Secret Store引用和会话安全配置等启动必需项按实际启用组件声明；缺失或无效时拒绝对应服务就绪，不自动创建默认管理员、换用业务数据库或临时无保护存储。
- 用户尚未选择模型/尚未配置Provider不等于整个应用必须停机；配置管理入口仍按04可用，依赖该配置的业务操作按既定错误拒绝。启动检查不得擅自发送业务内容或邮件。
- 04-01/04-02已有技术默认及capabilities为依据；不能以“安全默认”为名重定产品限额、权限、保留期或分期。未决定的政策显式关联08 §12/本文件§9，不猜值。
- 启动结果只记录脱敏的配置版本和来源，秘密不打印。测试连接与存储前缀须显式隔离；关键配置变更必须标明何时生效，不能改写在途任务冻结输入。

## 3. 升级和在途任务

1. 发布前核对代码、API机器契约、持久任务/事件schema版本和数据库迁移的兼容范围；变更流程见04-03/05-01。
2. 扩展结构并验证旧读写兼容后再切换进程；旧Worker不得执行不认识的载荷，未知版本保留诊断并停止领取，不猜测反序列化。
3. 停机先停止领取新任务，再排空或明确撤销执行资格；持久命令/绑定/输入不能丢失。技术重投同任务不等于用户P1重跑，外部副作用结果不明先核查。
4. 代码回滚仅在兼容已写数据与载荷时执行。破坏性迁移按07恢复方案，不承诺通用down迁移、不自动回退知识版本。

运行方案必须明确同一时刻允许共存的API/Worker版本，以及不兼容时采取排空还是停止接入。具体部署工具以后选定，不预设容器或微服务拆分顺序。

## 4. 容量与资源保护

容量计算使用声明单位和可审查输入，不把示例当最低配置或吞吐承诺：

`PDF字节 = 用户数 × 每用户Project数 × 每Project论文数 × 平均PDF字节`

旧例20 × 10 × 100 × 10 MB = 200,000 MB = **200 GB（十进制）**，不是20 GB。该例假设每Project独立保存一份，无物理去重；正文/切片、分析修订、向量、图谱、临时候选、导出及备份必须另算。

部署预算为活跃与保留版本的实测占用 + 在途候选峰值 + 升级/重建暂存 + 备份副本 + 运维余量；共享对象按真实物理复用计数，但不能用去重预测改变Project授权。记录每项参数、单位、测量依据和增长趋势，余量、保留期及资源上限在实际部署前确定，不在此猜默认值。

磁盘/配额不足必须使写入安全失败、保持旧默认版本并给出诊断；不能自动删除被引用历史资产腾空间。上传/解压/SSE技术限制沿用04-02，业务限额和保留政策不由运维隐式扩张。

## 5. 备份与恢复

备份必须关联关系库恢复点、该点依赖的不可变文件/文本/向量/图谱清单和校验值；建立可读屏障后再标记备份可用。备份期间保护引用对象，不以“数据库备份成功”替代完整证据可恢复。密钥材料单独受控备份，并记录恢复所需密钥版本，不能只恢复无法解密的引用。

恢复在隔离环境先核验账号/Project权限、版本清单闭包、文件摘要、引用定位、索引/图谱可读性和默认指针一致。旧会话/执行资格按既定授权与资格机制失效或重验，旧Worker不能连接恢复库继续提交；未完成任务仅按原命令、输入和绑定进行受控交接。

从原不可变数据重建索引仅在能验证原内容/定位与读取语义一致时恢复同版；重新解释正文、重切片或模型变化不能冒充旧修订，须经新Construction发布。缺失依赖明确不可用，不拼接最新数据。

恢复演练记录恢复点、备份范围、耗时、实际丢失窗口及未覆盖项；RPO/RTO和保留周期须按部署需要明确后才能承诺，不设置未经验证的数字。

## 6. 发布与运行验收

| 检查 | 所需证据 |
| --- | --- |
| 干净环境安装与迁移 | 真实安装/迁移命令、版本、结果及隔离配置；不使用已删除SQL草案 |
| 进程/存储可用 | 存活与实际依赖就绪，安全失败可诊断；不强制P1 Scheduler |
| 核心链路 | 09 ARC-11的构建发布及固定版本消费验证，外部服务mock与真实集成范围分开 |
| 升级/回滚 | 旧载荷/在途任务兼容与失权验证；不可逆变更有恢复证据 |
| 备份恢复与容量 | 隔离演练通过版本/引用校验，容量输入与增量有测量依据 |

保留清理任务的运行诊断和幂等重试，但回收资格、授权范围及共享依赖判断只按07执行；不在运维文档再定义自动删历史数据政策。测试及实际运行证据统一链接PROJECT_STATUS和工作单。

## 7. 可重复构建与交付证据

工程建立后固定受支持运行时版本、包管理器及依赖锁文件；干净环境按锁文件安装，不在部署时临时升级依赖。安装、静态检查、测试、构建、迁移均有统一的可执行入口和退出状态；实际命令经验证后登记，不复用已删除旧工程命令。可重复安装/构建不等于二进制逐字可复现，尚未验证的性质不得声称具备。

每次交付形成可核查记录，保存于工作单或CI产物并由PROJECT_STATUS引用：

| 证据 | 最小内容 |
| --- | --- |
| 来源与产物 | 代码提交；工作树有未提交变更时记录准确diff/摘要，不仅写HEAD；构建环境、锁文件摘要、产物摘要 |
| 协议与数据 | API契约及覆盖缺项、持久任务/事件schema、迁移起止版本；允许共存的API/Worker范围 |
| 配置 | 脱敏配置版本、来源、已启用能力和环境标识，不附密钥或私人正文 |
| 验证 | 09用例ID到实际命令/报告；通过、失败、跳过、未覆盖分别列出；mock与真实集成分开 |
| 变更与处置 | 行为变化、待决策影响、已知限制、升级步骤、回退/恢复前置和实际演练范围 |

证据必须对应本次代码/产物；更改关键代码、迁移或配置后重新执行受影响检查，不能复用旧报告宣称新产物通过。人类核查可据此判断变更、异常路径与残余风险。开发Agent的执行权限、业务决定和发布授权沿AGENTS.md及当前用户授权处理，本文件不新增逐次批准流程，也不把“构建通过”解释为获得部署授权。

## 8. 发布失败的停止与处置

实际部署前在runbook记录目标环境、迁移前版本、备份/恢复点、兼容范围、各步骤成功条件及可重试性。未验证的命令标为待验证，不当作可执行操作手册。

| 失败位置 | 停止边界与处置 | 恢复执行条件 |
| --- | --- | --- |
| 配置/兼容/验证证据检查失败 | 不切入新产物；保留当前可用部署，不自动修改配置“修好检查” | 补齐配置/证据或处理兼容问题并重检 |
| 迁移中断或提交结果不明 | 停止依赖新结构的启动/切流；查实际迁移记录与结构，不能盲目再次执行 | 确认迁移的幂等重入能力或修复方案；涉及不可逆改变按§3/5恢复 |
| 新进程就绪或业务验证失败 | 不扩大新流量；记录旧进程是否仍兼容当前数据，按预定方案排空/停接入 | 旧产物仅在仍兼容已写数据及载荷时回退；否则修复或隔离恢复，不强行down迁移 |
| 运行中依赖不可用 | 按07/04安全失败，停止无法满足完整性条件的写入；不能拼接其他知识版本 | 相同版本依赖校验恢复，执行资格重新核验；结果不明先查持久事实 |
| 备份恢复校验失败 | 不将缺失证据/错误权限的恢复环境接入业务，不连接旧Worker继续写 | §5闭包/权限/完整性通过后受控恢复，不以数据库可连接判成功 |

是否排空、停止接入或采用并存版本由该次兼容方案明确；本文不设未经决定的停机窗口、自动故障转移或数据丢失容忍值。重试不得新增业务命令或隐式重跑用户任务。

## 9. 待决策的运行目标

OPS-D01的部署方向已于2026-10-19由用户选择A：首版采用单部署、允许计划停机、人工恢复。管理员始终可授权计划停机，不以零停机、并存升级或自动故障转移作为首版要求；不新增应用内停机控制台。API/Worker/解析器可分进程，具体工具与拓扑以后选择。

计划停机仍按§3/8处理新任务接入、排空/执行资格及持久数据，管理员许可不绕过一致性和恢复校验。停机不等于取消全部业务对象或删除用户数据。

用户未确认前轮建议的20账号规模、24小时RPO、8小时RTO、7日加4周备份保留或其他容量数值，不作为默认值。剩余恢复目标、保留期及预算在实际部署前按需要明确；本地工程可继续，不承诺未经演练的恢复时限。网络/数据外发/凭据政策只在08 §12维护。由TRACK-022关联TRACK-007c/009b/011b，工程证据不重复登记。
