# Project Delivery

文档版本：v1.0
更新日期：2026-10-23

## 入口与职责

从本文件向上三级定位仓库根目录，不依赖调用时工作目录。先读 [AGENTS](../../../AGENTS.md)、[项目状态](../../../docs/PROJECT_STATUS.md)、[设计索引](../../../docs/design/README.md)、[实施入口](../../../docs/IMPLEMENTATION_ENTRY.md)及当前任务相关规范，检查实际 Git 工作区。保留已有修改。

实施入口第2节是阶段与人工交接规则的唯一维护位置；按其中 S1–S7 顺序执行。使用[任务模板](../../../tasks/example.md)记录实例与检查点，不另建重复状态库。此 skill 是执行指令，不是后台调度器，不保证跨会话自动唤醒或硬性阻止跳步。

## 执行与恢复

1. 从用户实际指令确定单任务或批次授权，记录来源、范围、顺序与依赖。调用 skill 本身、任务文件存在、状态表待办或前任务通过均不是下一业务任务的授权。范围不明时仅整理已有信息，提出具体问题，不启动不明范围的实现。
2. 恢复时先读取任务单检查点、授权来源、人工决定和对应内容快照，再比对当前文件（含未提交/未跟踪文件）。缺少授权或证据不能用状态标签补足；保留历史，记录差异，回到最早受影响阶段。不要重置或覆盖其他人的改动。
3. 逐阶段执行并在交接、返工、等待、结束前保存检查点。基础测试与需求追踪在首次人工审核前完成；后续覆盖复核不能代替它们。设计/文档任务执行引用、版本与一致性检查，不为凑流程运行无关应用测试。
4. S3 必须委派独立 subagent：提供任务授权、规范、实际产物路径/快照、可运行验证入口及允许副作用；要求自行读文件与反例，不以主 agent 总结作结论。审查者只读、不得启动业务任务或修改共享工作区；输出严重度、位置、需求依据、复现证据和验证限制。主 agent 修复已授权缺陷，再请审查者复核受影响部分。工具不可用时记录未执行，不能以自审替代独立通过。
5. S4 人工节点遵循实施入口：准备具体审核包，引用原始用户决定并绑定范围及基线。没有真实决定就保存等待状态，向用户列出问题、证据、选项、建议和仅被阻塞的部分；不反复轮询或把等待超时当作批准。已授权且不依赖决定的准备工作可继续，但不得跳过阶段门槛。
6. S5/S6 产生变更后执行 S7 复验及受影响的独立复审；需要人工重新接受时回 S4。简化以保持行为、边界与测试强度为条件，没有收益即记录无需修改，不制造重构任务。
7. 当前任务满足 S7 收口条件后，再核对下一任务已有授权及前置。队列耗尽、缺授权、外部依赖不可用或必须人工决策时保存可恢复交接。例行工程修复在授权范围内自主完成；业务规则冲突不得自行裁决。

交付时给出当前阶段、实际变更、验证证据、独立审查结论、人工待决事项及下一步。分列设计、代码、自动验证、人工接受状态；不把本轮文档交付称为业务验收。
