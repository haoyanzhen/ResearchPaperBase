# 下一阶段工作安排：从已发布版本到研究、综述与项目自定义模块

文档版本：v1.2
更新日期：2026-11-04

## 1. 阶段目标

以[已验收的手动论文构建](../../tasks/049-ingestion-publication.md)发布的知识版本为起点，让用户先在研究会话中按轮使用最新版本并核查历史证据，再在综述中完成一份可追溯的报告，最后用项目内创建的“证据矩阵”引用已有成果。研究和综述优先形成独立可用的产品路径，两者均不依赖自定义模块宿主。需求归属见[原任务拆解 §10](preimplementation_design_tasks_2026-10-21.md)，扩展范围见[模块协议 v1.3](../design/05-02_workspace_module_extensions.md)。

## 2. 实施顺序与分工

| 顺序 | 负责人及交付范围 | 依赖与验收条件 |
| --- | --- | --- |
| 1 | Knowledge 提供操作版本读取，Research 提供会话创建、恢复和研究轮次的版本记录；前端直接建会话、显示本轮证据范围。先行切片对应 FR-018/028。 | 复用 task049 发布与读取入口。轮次受理与版本依赖原子登记。发布 v2 后，重开旧回答仍读 v1，同一会话下一轮自动用 v2；空版可建并提示证据为空，继续须显式选择；无可访问版本、版本归属错误或建会话失败时不留下对象或孤立依赖。 |
| 2 | Research 完成首轮问答、历史重开和证据跳转，覆盖 FR-028–031 的限定范围。 | 依赖 1。用受控模型走通提问→回答→定位版本内原文；证据不可读时给出可解释状态，失败响应不成为成功正文。浏览器验证在途回复用 v1 完成，发布后在原输入区追问使用 v2，历史引用仍读 v1。此处为研究里程碑。 |
| 3 | Review 完成按次记录版本的大纲、章节生成与编辑，再接审查、终稿与授权下载，按 FR-032–036 分两次交付。 | 共用 1 的读取契约，可与 2 并行准备。先验收空版低支撑提示、确认和人工稿保护，再验收同一修订的报告及文件；迟到生成不能覆盖人工修改，终稿下载时重验状态与权限。此处为综述里程碑。 |
| 4 | 扩展宿主与 Workspace 实现项目内清单登记、启停和对象编辑，用“证据矩阵”绑定一个已发布版本。 | 依赖 1，按模块协议 §§6–9 核验。A、B 可各自创建同名模块，升级 A 不改变 B；停用再启用后旧请求不能提交，原记录可恢复；不能调用构建发布接口。 |
| 5 | Research、Review 分别提供会话、生成文件、报告的授权读取端口，资产层与前端按来源逐类接入矩阵。 | 依赖 4 和对应的真实来源。B 的矩阵绑定 B/v1，可引用 A 中获授权的成果；撤权后列表、预览、缓存及实际下载均不得泄露内容。失效引用不妨碍保存无关备注。此处为扩展里程碑。 |

实施次序采用 1 → 2 → 3 → 4 → 5；表中的依赖决定哪些准备与验证可以提前。第 5 项的研究文件需要来源模块已有文件身份、归属和读取契约；若尚缺生产者，单列该文件交付，先完成会话与报告，文件验收保持开放。真实模型质量单列，受控模型只验证流程。

### FR-018 版本更新的验收分工

- 第 1、2 项：在 V1 回复流式输出时发布 V2。研究工作台显示“检测到知识库版本更新”；不抢输入焦点、不要求确认。原回复及其恢复仍用 V1，下一次提问在相同 Session ID 下使用 V2。历史引用按原修订读取。
- 第 3 项：V1 章节任务受理后发布 V2，综述编辑器显示同一句提示，草稿与光标保留。在同一 Run 内继续下一章或开始审查直接使用 V2。旧章与新章的证据可分别定位；发布不触发重写、重新确认或整稿重跑。
- 两模块验证连续发布、发布与受理并发、断线重开、空版、无权与 no_change。失败、空核验不误报；已完成或归档的对象不因此恢复写资格。第 4 项的自定义矩阵按其自身固定版本协议验收。

验收依据见[功能需求 FR-018](../design/01_functional_requirements.md)和[版本更新领域规则](../design/02-02_construction_versioning_appendix.md)。

## 3. 启动与交接

第一张实施任务单贯通“建会话 → 提问 → 发布新版 → 同一会话继续提问”。复用 task049 的发布及历史读取入口，盘点轮次、任务、版本依赖与工作区恢复落点。用隔离库和浏览器核验同一会话 ID 下先后两轮各自的版本、提示、历史引用与失败回滚。

每个切片记录需求、可观察结果、测试与当前执行证据。工程负责人组织自验、独立审查及回归；研究、综述和扩展里程碑分别交用户体验与验收。阶段状态以[项目状态](../PROJECT_STATUS.md)为准，计划本身不更新完成度。

Windows/Linux PDF 隔离解析实测已排至 L0 后的下一大阶段（TRACK-023）。启动该大阶段时单列平台、镜像和清理验证；本计划的版本读取切片可独立推进。非论文构建、历史删除、生产保留与恢复策略继续按既有跟踪项管理。
