# Project Delivery

文档版本：v1.2
更新日期：2026-10-28

## 入口与职责

从本文件向上三级定位仓库根目录，不依赖调用时工作目录。先读任务顶部最新检查点，并按需定位规范段落；读取 [AGENTS](../../../AGENTS.md)、[项目状态](../../../docs/PROJECT_STATUS.md)、[设计索引](../../../docs/design/README.md)、[实施入口](../../../docs/IMPLEMENTATION_ENTRY.md)及当前任务相关规范，检查实际 Git 工作区。保留已有修改。

实施入口第2节是工程阶段、业务决策和里程碑验收规则的唯一维护位置；按其中流程v1.8的 S1–S7 顺序执行，取消逐任务人工审阅门禁。使用[任务模板](../../../tasks/example.md)记录实例与检查点，不另建重复状态库。此 skill 是执行指令，不是后台调度器，不保证跨会话自动唤醒或硬性阻止跳步。

## 执行与恢复

1. 从用户实际指令确定单任务或批次授权，记录来源、范围、顺序与依赖。调用 skill 本身、任务文件存在、状态表待办或前任务通过均不是下一业务任务的授权。范围不明时仅整理已有信息，提出具体问题，不启动不明范围的实现。
2. 恢复时先读取任务单顶部检查点、授权来源、人工决定和对应内容快照，再比对当前文件（含未提交/未跟踪文件）。缺少授权或证据不能用状态标签补足；保留历史，记录差异，回到最早受影响阶段。不要重置或覆盖其他人的改动。
3. 逐阶段执行并在交接、返工、等待、结束前保存检查点。基础测试与需求追踪在S2完成；后续覆盖复核不能代替它们。设计/文档任务执行引用、版本与一致性检查，不为凑流程运行无关应用测试。
4. S3 必须委派独立 subagent：按实施入口提供有界任务包：任务授权、相关规范位置、上次有效基线及当前差异、实际产物路径/快照、可运行验证入口及允许副作用；避免默认复制全部会话。首次无有效基线须建立本任务完整审查；复审聚焦改动及受影响依赖，未改动但受影响的内容仍须读；要求自行读文件与反例，不以主 agent 总结作结论。审查者只读、不得启动业务任务或修改共享工作区；输出严重度、位置、需求依据、复现证据和验证限制。主 agent 修复已授权缺陷，再请审查者复核受影响部分。工具不可用时记录未执行，不能以自审替代独立通过。
5. S4覆盖复核与S5简化后，执行S6最终复验及受影响的独立复审。保持行为、边界与测试强度，没有收益即记录无需修改，不制造重构任务。S7条件满足后自主工程收口，核对下一任务授权与前置并继续，不等待逐任务人工接受。
6. 业务决策D和里程碑验收M遵循实施入口。S1记录里程碑范围、触发点、场景和后续依赖；尚无约定时提出分组，在首个完整业务成果形成时提交验收，不无限推迟。真正需要决定时，提供具体产物/问题、证据、选项、建议及仅被阻塞的工作；无实际答复保存等待状态，继续独立的已授权工作。常规实现与修复不反复索取批准。
7. 恢复旧任务必须按实施入口的旧→新阶段映射追加检查点，保留历史接受、待审和执行证据；不能把旧S4当作覆盖已完成，也不能将取消例行门禁解释为业务决定已获批准。全量拆解只建立任务地图，延期或未授权业务不自动执行。
8. 队列耗尽、缺授权、必需验证/独立审查不可用，或依赖业务决定/里程碑验收时，保存可恢复交接，明确未完成范围。不能以自审、缺项说明或通过测试数量替代必需验证与独立审查。里程碑接受后的变化按实施入口判断补充验收，不把旧接受迁移到新基线。

状态入口只汇总当前事实；任务第4/5节单点维护需求矩阵与验证，其他记录引用。完整日志/清单留在文件，工具优先返回摘要及失败定位；不可降低必需测试或独立审查强度。人工里程碑接受后按实施入口核对范围并创建本地Git commit，保留混合工作区、不自动push；在检查点记录接受基线与commit，未获接受不自动提交。

交付时给出当前阶段、实际变更、验证证据、独立审查结论、业务待决事项、里程碑状态及下一步。分列设计、代码、自动验证、工程收口、里程碑人工接受状态；不把文档交付或自动工程收口称为业务验收。
